# Обвязка агентов: из чего состоит и как развернуть

Порядок работы — кто ставит, кто исполняет, кто проверяет — описан в
[`AI_AGENT_PROTOCOL.md`](AI_AGENT_PROTOCOL.md) и здесь не повторяется: копия разойдётся
с оригиналом. Этот документ отвечает на два других вопроса — **из каких файлов схема
физически состоит** и **как поднять её на другой машине или в другом проекте**.

## Состав

| Файл | Что делает | В git |
|---|---|---|
| [`../.windsurfrules`](../.windsurfrules) | единственный нормативный источник: архитектура, безопасность, тестирование, язык | да |
| [`../CLAUDE.md`](../CLAUDE.md) | указатель для Claude Code: что прочитать перед работой | да |
| [`../.claude/settings.json`](../.claude/settings.json) | разрешения Claude Code и `PreToolUse`-хук сохранности данных | да |
| `../.claude/commands/kg-work.md` | единственная проектная команда Claude Code | да |
| [`../.devin/config.json`](../.devin/config.json) | проектные разрешения Devin | да |
| `../.devin/config.yml` | `defaultSkill`, список скиллов, `hooks.on_start` — то, чем Devin читает доску на старте | да, с 2026-09-08 |
| [`../.devin/skills/`](../.devin/skills/) | скиллы в одном экземпляре; в `.claude/skills/` — тонкие указатели на них | да |
| [`../.devin/prompts/`](../.devin/prompts/) | мастер-промпты для моделей без доступа к репозиторию | да |
| `../.devin/config.local.json` | личный оверрайд разрешений | **нет, и правильно** |
| [`AI_HANDOFF.md`](AI_HANDOFF.md), [`AI_LOG.md`](AI_LOG.md), [`tasks/`](tasks/) | состояние: доска, журнал, постановки | да |

Пользовательского уровня у схемы нет вовсе: в домашнем каталоге агента нет ни общих
разрешений, ни глобальных команд, ни глобальных скиллов. Всё лежит в проекте — и это
не случайность. Агент, который на двух машинах ведёт себя по-разному, не рецензируем:
воспроизвести чужой прогон нельзя, а значит нельзя и опровергнуть.

## Развернуть этот проект на другой машине

Аккаунт переносить нечего — войти тем же. Всё, что составляет схему, приезжает
клоном. Остаётся окружение:

1. `git clone`, рабочая ветка `ai-agents`.
2. **Python на `PATH`.** Хук [`../scripts/devops/guard-personal-data.py`](../scripts/devops/guard-personal-data.py)
   висит на каждом вызове Bash; без интерпретатора не работает ни одна команда, а не
   только опасные.
3. Docker Desktop с WSL 2, Go, Node, `gh` — версии в [`../.windsurfrules`](../.windsurfrules).
4. `.devin/config.local.json` — только если этой машине нужен набор разрешений, отличный
   от проектного. Файл необязателен: без него действует [`../.devin/config.json`](../.devin/config.json).

Проверка, что развернулось: `.\scripts	esting\check-all.ps1` (или `./scripts/testing/check-all.sh`)
— 16 фаз, включая `Documentation links`.
Отдельно стоит убедиться, что сработал именно хук, а не его отсутствие: команда из
списка `ask` в [`../.claude/settings.json`](../.claude/settings.json) обязана
остановиться, а не выполниться.

## Перенести схему в другой проект

Переносится **скелет, а не содержимое**. `.windsurfrules` этого репозитория написан под
Go, SvelteKit и pgvector; в другом проекте он будет врать с первого дня, а норма, которой
не верят, хуже отсутствующей.

Что имеет смысл повторить:

- **один** нормативный файл и указатель на него в корне;
- доска, журнал и каталог постановок — состояние передаётся через репозиторий, второго
  канала связи нет намеренно: у git есть история, ревью и откат, чего нет ни у почты, ни
  у чата;
- одна команда запуска, режим которой выбирает агент, а не человек;
- префикс в имени команды. Короткие имена сталкиваются со встроенными (`review` — с
  `/code-review`, `peer` — с `/peers`), и тогда молча выполняется не то, что задумано;
- скиллы — **задним числом**. Умозрительный скилл превращается в пересказ учебника: в
  июне 2026 так появились и через два дня были удалены 5234 строки, где на двенадцать
  файлов не нашлось ни одной ссылки на реальный артефакт проекта.

Что переносить нельзя: разрешения и запреты. Их состав зависит от того, что в проекте
можно разрушить. Здесь запрещены `docker volume rm`, `docker system prune` и `rm` —
потому что в томах живут личные заметки; в проекте без такого актива этот список
бессмысленно строг.

## Ловушки, на которых уже спотыкались

**Файл-механизм вне git.** До 2026-09-08 `.devin/config.yml` попадал под маску
`.devin/*` и в репозиторий не входил, хотя три документа утверждали, что Devin читает
доску именно через его `hooks.on_start`. На свежем клоне утверждение было ложным.
Проверка дешёвая и стоит того, чтобы делать её при каждом добавлении:

```bash
git check-ignore -v .devin/config.yml
```

Правило общее: **если документ называет файл механизмом, файл обязан быть в git.**
Иначе документ описывает не проект, а одну машину.

**Скиллы конкурируют за внимание.** Описание каждого загружается в любую сессию. На
дюжине они начинают срабатывать невпопад, и экономия контекста оборачивается против
себя. Число держим малым осознанно.

**Хук — общий, а не точечный.** `PreToolUse` с матчером `Bash` вызывается на каждой
команде. Медленный или падающий хук останавливает всю работу агента, поэтому у него
стоит `timeout` и он обязан отвечать быстро.
