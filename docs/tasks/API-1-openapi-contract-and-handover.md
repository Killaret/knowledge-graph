Постановка для Devin. Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

Ставит Claude Code, реализует Devin, проверяет Claude Code.

**Очерёдность:** не блокирует PUB-2 и PUB-3, но пункт 2 после PUB-3 придётся выполнять
заново — см. «Взаимодействие с PUB-3».

## Две мои ошибки подряд, обе записаны

**Первая.** Я сообщил владельцу, что `/swagger/index.html` отдаёт пустую спецификацию.
Основание: `backend/docs/swagger.json` содержит ноль путей и аннотаций `@Router` в коде
нет. Чем UI питается — не посмотрел.

**Вторая.** Посмотрев код, я находку снял: UI указан на рукописный `openAPI.yaml`
(`router.go:97`), файл раздаётся статикой (`router.go:104`), освобождён от обеих
проверок авторизации (`middleware/jwt.go:58`, `middleware/apikey.go:36`) и копируется в
образ (`backend/Dockerfile:23`). Вывод: всё работает. Снова по чтению, снова без запуска.

**Что показал запуск.** Тест-стек, бэкенд на `127.0.0.1:18083`:

```
GET /openapi.yaml       -> 200, 73103 байта, 55 путей, openapi: 3.1.0
GET /swagger/index.html -> 200
GET /swagger/doc.json   -> 200, 210 байт  (та самая пустая спека swaggo)
```

А в браузере на `/swagger/index.html`:

> **Unable to render this definition.** The provided definition does not specify a valid
> version field. Supported version fields are `swagger: "2.0"` and those that match
> `openapi: 3.0.n`.

**Симптом был настоящий, причину я назвал неверно оба раза.** UI грузит правильный файл
и не умеет его прочитать: спецификация написана на OpenAPI 3.1.0, а Swagger UI, вшитый
в `swaggo/files`, понимает только 2.0 и 3.0.x. Разработчик, которому дадут эту ссылку,
увидит красную плашку и ничего больше.

Мораль ровно та, что записана в `.windsurfrules`: чтение кода находит кандидата и не
подтверждает его. Второй раз за день.
## Зачем задача

Разработчику Java-сервиса нужен договор, которому можно верить: посмотреть, что вернёт
создание заметки, и импортировать спецификацию в Postman для проб. Сегодня договор есть
и он в неплохом состоянии — но ничто не мешает ему разойтись с кодом молча, а первым
об этом узнает человек, который на него уже что-то написал.

## Что проверено исполнением

Собрал одноразовый тест в `backend/cmd/server/`, поднял роутер тем же `setupRouter`,
что и боевой, и выгрузил `r.Routes()`. Затем сверил с `openAPI.yaml` по парам
метод + путь, приведя `{id}` к `:id`.

```
операций в openAPI.yaml : 70
маршрутов в роутере     : 75  (из них 3 служебных: /openapi.yaml GET+HEAD, /swagger/*any)
задокументировано лишнего: 0
не задокументировано    : 2
    GET /api/v1/graph/analytics
    PUT /api/v1/links/:id
```

**Спецификация правдива.** Ни одного пути, которого нет в коде. Пробел — два маршрута.

**Ловушка, на которой я сам споткнулся и которую надо учесть в пункте 2.** Первый прогон
дал 69 маршрутов и «шесть путей в спеке, которых нет в коде» — все шесть про черновики.
Причина: я передал `nil` вместо обработчика черновиков, а эти маршруты регистрируются
условно. С `&drafthandler.Handler{}` их стало 75, и ложная находка исчезла. **Тест,
который строит роутер беднее боевого, покажет дрейф там, где его нет.**

Одноразовый тест удалён, `git status` чист.

## Что сделать

### 0. Версия спецификации — блокер, решение за владельцем

Без этого пункта остальные бессмысленны: договор нельзя показать, пока он не
отображается.

В `openAPI.yaml` восемь мест с union-типами — конструкция, которой в 3.0 нет:

```
2522, 2525, 2592, 2616, 2627, 2644:  type: [string, 'null']
2630, 2647:                          type: [integer, 'null']
```

Других признаков 3.1 нет: ни `const`, ни `webhooks`, ни `$schema`, ни схемных
`examples`. То есть спецификация помечена как 3.1, а пользуется из неё одним приёмом.

**Вариант А — опустить спецификацию до 3.0.3.** Восемь строк механически:
`type: [string, 'null']` → `type: string` плюс `nullable: true`. Работает вшитый UI,
работают генераторы клиентов, максимальная совместимость с инструментами. Цена — формат
на версию старше и `nullable` вместо union-типа.

**Вариант Б — оставить 3.1 и заменить отображалку.** Отдавать современный Swagger UI 5.x
статикой или поставить Redoc либо Scalar, которые 3.1 понимают. Цена — новый фронтовый
артефакт в образе и его обновление; выигрыш — спецификация остаётся на актуальном
стандарте.

**Рекомендация: вариант А.** Задача — дать второму разработчику договор, который
открывается везде без оговорок, а не отстоять версию формата. Восемь строк против нового
артефакта в образе — несопоставимая цена. Проверить дополнительно, как выбранная версия
импортируется в Postman, и написать результат в документ из пункта 4, а не по памяти.

### 1. Задокументировать два недостающих маршрута

`GET /api/v1/graph/analytics` и `PUT /api/v1/links/{id}` — в том же стиле, что соседние
операции: теги, параметры, тела запроса и ответа, коды. Путь `/api/v1/links/{id}` в
файле уже есть (`backend/openAPI.yaml:1156`), добавляется только операция `put`.

### 2. Контрактная проверка против дрейфа

Go-тест в `backend/cmd/server/`, который строит роутер и сверяет `r.Routes()` с
`backend/openAPI.yaml`. Падает в обе стороны: маршрут без описания и описание без
маршрута — одинаково дефект.

Требования:

- **Роутер строится в полной комплектации.** Все обработчики, влияющие на состав
  маршрутов, передаются ненулевыми — см. ловушку выше. Если появится ещё один условно
  регистрируемый обработчик, тест обязан его учитывать.
- **Служебные маршруты исключаются явным списком** (`/swagger/*any`, `/openapi.yaml`), с
  комментарием, почему каждый в нём. Список коротким не будет случайно — он должен быть
  коротким намеренно.
- **Нижняя граница на число сверенных маршрутов**, как в
  `TestNoteIDRoutesRequireAccessGuard`: тест, который однажды не найдёт ни одного
  маршрута и останется зелёным, ничего не сторожит.
- Сравнение по паре метод + путь, `{param}` приводится к `:param`.
- Сообщение об ошибке называет конкретный маршрут и сторону расхождения. «Спецификация
  разошлась с кодом» без имени маршрута бесполезно.

**Доказать мутацией, обе стороны:**

1. добавить в роутер маршрут, которого нет в спецификации, — тест краснеет и называет
   его;
2. удалить из `openAPI.yaml` операцию существующего маршрута — тест краснеет и называет
   её.

Обе мутации откатить, приложить вывод.

### 3. Судьба пакета `backend/docs`

Сгенерированные `docs.go`, `swagger.json`, `swagger.yaml` от 26 июля содержат ноль
путей, подключены слепым импортом (`backend/cmd/server/main.go:16`) и копируются в
образ (`backend/Dockerfile:24`). UI ими не пользуется.

Убрать: пакет, слепой импорт и строку `COPY` из `Dockerfile`. Пустая спецификация,
лежащая рядом с настоящей, — приглашение однажды перепутать.

**Осторожно:** слепой импорт регистрирует спеку в swaggo, и по `/swagger/doc.json` она
отдаётся. Проверить живьём, что после удаления UI по-прежнему открывается и показывает
70 операций, — это часть критериев приёмки, а не формальность.

### 4. Путь второго разработчика: найти и поднять

Задача владельца в его словах: чтобы разработчик Java-сервиса **нашёл, где она, и смог
её развернуть**. Значит это не список ссылок, а дорога от чистой машины до открытого
Swagger UI и коллекции в Postman.

Общего документа об API в `docs/` нет — есть только
[`../API_ERRORS_EN.md`](../API_ERRORS_EN.md) про ошибки. Завести `docs/API_EN.md` по
принятому именованию (`ARCHITECTURE_EN`, `DEPLOYMENT_EN`, `CONFIGURATION_EN`), добавить
строку в указатель [`../README.md`](../README.md) и в раздел Documentation корневого
`README.md`.

Содержание — по шагам, каждый проверен запуском, а не памятью:

1. **Поднять стек.** Какой файл compose и какой командой. В репозитории их три:
   `docker-compose.yml`, `docker-compose.test.yml`, `docker-compose.personal.yml`.
   Назвать тот, который годится постороннему, и сказать, чего он не поднимает.
2. **Куда смотреть.** Порт брать из compose, а не из головы: у тест-стека бэкенд на
   `127.0.0.1:18083`, значит UI — `http://127.0.0.1:18083/swagger/index.html`. Для
   другого стека порт другой; в документе должно быть сказано, где его посмотреть.
3. **Где сам файл.** `GET /openapi.yaml` на живом сервере, он же `backend/openAPI.yaml`
   в репозитории. Оба пути назвать: первый нужен, когда сервер уже поднят, второй —
   когда ещё нет.
4. **Postman.** Коллекция создаётся импортом OpenAPI напрямую. Отдельный файл коллекции
   в репозиторий **не класть**: это второй артефакт с тем же содержимым, он разойдётся
   с первым — та же болезнь, что мы лечили в `COMMANDS.md` и в `README`.
5. **Авторизация для проб.** Как получить токен (какой endpoint, какое тело), в каком
   заголовке его слать, и что часть маршрутов после PUB-1 открыта анониму — чтобы
   человек не решил, что сломано, получив 200 без токена.
6. **Что вернёт создание заметки.** Владелец назвал этот пример прямо: разработчику
   нужно видеть форму ответа `POST /api/v1/notes`. Проверить, что в спецификации она
   описана полностью — схема ответа, а не только код.

Текст — на английском, как остальная продуктовая документация.

## Взаимодействие с PUB-3

PUB-3 переименовывает `/api/v1/graph/all` в `/graph/public`. В спецификации этот путь
описан (`backend/openAPI.yaml:1659`). После PUB-3 проверка из пункта 2 обязана
покраснеть, если спецификацию не поправили, — это хороший признак, а не помеха.
Если PUB-3 делается раньше, переименование в `openAPI.yaml` входит в неё.

## Ограничения

- **Аннотации `@Router` не заводить.** Рукописная спецификация — источник правды;
  генерация из кода означала бы переписать 70 операций и получить второй источник.
  Решение зафиксировать в шапке `openAPI.yaml` одной строкой, чтобы следующий не начал
  генерацию заново.
- Существующие описания не переписывать, кроме двух добавляемых операций.
- Personal-стек не трогать.

## Критерии приёмки

1. **`/swagger/index.html` показывает операции, а не плашку об ошибке.** Проверяется
   в браузере на поднятом стеке, скриншот обязателен — именно этот шаг я пропустил
   дважды.
2. `openAPI.yaml` описывает все маршруты роутера, кроме служебных; расхождений ноль.
3. Контрактный тест есть, зелёный, и **обе** мутации из пункта 2 ловятся с указанием
   конкретного маршрута; вывод приложен.
4. Тест строит роутер в полной комплектации: добавление условно регистрируемого
   обработчика не создаёт ложного расхождения.
5. Пакет `backend/docs`, слепой импорт и строка `COPY` убраны.
6. **Живая проверка:** стек поднят, `/swagger/index.html` открывается, показывает
   операции, и `GET /openapi.yaml` отдаёт файл с кодом 200. Свидетельство — в
   [`../MANUAL_TEST_FEEDBACK.md`](../MANUAL_TEST_FEEDBACK.md), поле «Screenshot / Logs».
7. Раздел о передаче написан, порт и URL проверены запуском, а не памятью.
8. `check-all` зелёный.
