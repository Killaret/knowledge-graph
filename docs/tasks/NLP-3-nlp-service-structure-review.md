## Что уже установлено (первичный обход Devin, 2026-09-19)

### Состав

- `nlp-service/app/main.py` — FastAPI, `lifespan` прогружает модель при старте; `/health` падает 503, если модель не поднялась.
- `nlp-service/app/nlp_utils.py` — ленивый синглтон `SentenceTransformer` под `threading.Lock` (`HF_HUB_OFFLINE=1` по умолчанию, кэш `HF_HOME/hub`), YAKE-экстрактор ключевых слов (ru+en стоп-слова NLTK), косинусная близость на чистом Python.
- `nlp-service/app/models.py` — pydantic-DTO; `openapi.yaml`, `tests/` (pytest), `Dockerfile` (двухстадийный, модель скачивается в образ), `entrypoint.sh`.
- Запуск: `uvicorn ... --workers 1` (`Dockerfile:79`), порт 5000.

### Внешний контракт (4 эндпоинта)

| Метод | Что делает | Кто зовёт |
|---|---|---|
| `POST /embed` | `model.encode(text)` одного текста | backend `nlp/client.go` — ComputeEmbedding на заметку |
| `POST /extract_keywords` | YAKE `top_n` (вес = `1-score`, кламп [0,1]) | backend — ExtractKeywords |
| `POST /similarity` | кодирует **оба** текста, косинус → [0,1] | backend — при пересчёте весов связей |
| `GET /health` | флаг загруженной модели | docker healthcheck |

Клиент backend: `internal/infrastructure/nlp/client.go` — HTTP timeout 10 с, ретраи.

### Подтверждённые особенности и риски

1. **Сериализация на event loop.** Эндпоинты — `async def`, а `model.encode()` — блокирующий CPU-вызов внутри них. При `--workers 1` все запросы физически стоят в одну очередь. Это и есть наблюдавшийся потолок ~7 задач/с при разборе очереди (медиана embedding 1 с): конкурентность воркера 10 в NLP не упиралась — NLP сериализовал.
2. **Нет батч-эндпоинтов.** Воркер делает 1 HTTP-запрос на заметку: 118 заметок = 118 × /embed + 118 × /extract_keywords. `SentenceTransformer.encode(list)` умеет внутренний батчинг — один вызов на N текстов эффективнее и по сети, и по CPU.
3. **`/similarity` переисполняет эмбеддинги.** Кодирует оба текста заново, хотя вектора уже лежат в pgvector и близость считается в БД. Кандидат на выпил или перевод на приём готовых векторов.
4. **Тихое усечение.** `encode()` режет вход до `max_seq_length` модели (у MiniLM 128 wordpieces) — у длинных заметок хвост контента в эмбеддинг не попадает. Для MODEL-1 это важно: замеры на длинных текстах покажут усечённый сигнал.
5. **YAKE — GPL.** Известно, трек — NLP-2 (замена на keybert + лемматизация). Здесь только отметить пересечение.
6. **Ресурсы.** Один инстанс держит модель в RAM (~1.1 ГБ наблюдено). `workers=N` масштабирует CPU линейно, но умножает память — на ноутбуке владельца предел близко.

### Пути оптимизации (для обсуждения, не решения)

- `POST /embed_batch` (+ `keywords_batch`): список текстов → список результатов; воркер группирует по ~16–32.
- `def`-эндпоинты или `run_in_threadpool` — снимает блокировку event loop (CPU всё равно сериален под GIL; реальный выигрыш — только батч или процессы).
- `workers: 2` — самый простой рычаг, цена ~+1 ГБ RAM.
- Стратегия длинных текстов: осознанный выбор `max_seq_length` / чанкинг+усреднение пулингом — зависит от итогов MODEL-1.
- Метрики: время encode, размер батча, длина входа — пригодятся при замере.
