# RELEASE-1. Версия 1.0: состав, статус, путь до выпуска

Статус: **в работе — Claude Code.** Состав утверждён владельцем 2026-09-26 (решение 67). Дата — после
постановок P11-4 и COMET-1 (раздел «Дата»).

**Решение владельца (2026-09-26, RELEASE-1):** 1.0 — для владельца, локально, один пользователь. В
состав входят:
- доведение сданного;
- загрузка графа, как задумано (UI-LOAD-1);
- шаг «связать» — UX-1 и три дефекта;
- смена модели (MODEL-2);
- кластеризация (P11-4) с нормализацией ключевых слов (P11-3) как зависимостью;
- напоминания (COMET-1);
- сверка документации с кодом (DOC-AUDIT-2);
- полный ручной прогон.

Всё остальное — после 1.0. С этого дня новое идёт только в «после 1.0».

## Зачем 1.0

Решение 16 (2026-09-08): объём ограничивается выпуском 1.0. Причина — слова владельца из интервью
FACE-1: «постоянно тащу новые фичи, не успеваю дотестировать».

Цель — «полочка со связями», которой владелец пользуется каждый день:

1. **Сложить:** импорт закладок, букмарклет, заметка.
2. **Увидеть связи:** автоматические и ручные.
3. **Найти:** поиск, граф в 2D и 3D, кластеры, рекомендации.
4. **Не потерять:** бэкапы.

## Статус проекта на 2026-09-26

- **Стадия** — alpha (`ROADMAP.md`), версия фронтенда `0.0.2`. Теги `v1.0.0-stable` (2026-04-10) и
  `v1.1.1front` (2026-04-13) — вехи весны, к этому выпуску отношения не имеют. Как назвать выпуск,
  чтобы не путать, решается при выпуске.
- **Узкое место — ревью Claude Code и решения владельца, а не реализация.** За неделю Devin сдавал по
  5–14 работ в день. Сейчас у него 5 работ на ревью (лимит 5 из 5), ещё три готовые задачи ждут
  слота.
- **Блокеры сентябрьского аудита по `CHANGELOG.md` в основном закрыты:**
  - `SKIP_AUTH` работает только в тестовом профиле;
  - чужие заметки по id больше недоступны;
  - приватные ответы больше не кешируются как публичные.

  `ROADMAP.md` этого не отражает, сверит DOC-AUDIT-2. Для локальной 1.0 многопользовательский режим не
  нужен.
- **Найдено 2026-09-26:**
  - постепенная загрузка графа была сделана и потеряна при чистке (UI-LOAD-1);
  - документация описывает то, чего в коде нет (DOC-AUDIT-2).

## Полное ручное тестирование

**Что есть сейчас:**
- два чек-листа: `docs/operations/MANUAL_TEST_CHECKLIST_COCKPIT.md` (панели, фильтры, виды, 2D,
  first-person, тема, страница заметки) и `docs/operations/MANUAL_TEST_CHECKLIST_MINIMAL.md`;
- журнал находок `docs/agents/MANUAL_TEST_FEEDBACK.md`.

`docs/operations/REGRESSION_TEST_PLAN.md` — в основном автоматические и инфраструктурные проверки,
пользовательских сценариев цикла в нём нет.

**RELEASE-TEST-1** — один чек-лист по циклу 1.0, собранный из двух существующих и состава 1.0. Разделы:
сложить, связать, найти, не потерять, 2D и 3D, кластеры, напоминания. В каждом пункте — шаг, ожидание,
отметка.

**Два прохода:**
1. **Claude Code в браузере на тест-стенде.** Отсеять очевидное до того, как владелец потратит время.
2. **Владелец на кандидате в выпуск.** Данные — копия реальных заметок из свежего бэкапа в отдельном
   стенде. Заодно проверяются бэкап, восстановление и переход данных на 1.0. Personal-стек не
   трогается.

## Критерии готовности 1.0

1. Всё из состава принято ревью; `scripts/testing/check-all.ps1` без `-Quick` зелёный.
2. Ручной прогон владельца по RELEASE-TEST-1 — без открытых блокеров; находки записаны в
   `MANUAL_TEST_FEEDBACK.md`.
3. DOC-AUDIT-2 закрыта: по каждому «нет в коде» есть решение владельца, `ROADMAP.md` описывает 1.0
   как есть.
4. Бэкап и восстановление проверены на копии реальных данных; миграции переводят данные на 1.0 без
   потерь.
5. Выпуск оформлен: раздел 1.0 в `CHANGELOG.md`, версия, тег, текст FACE-1.
