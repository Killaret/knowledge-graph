# NOTE-QUALITY-1: цикл проверки, нормализации и обогащения заметки

## Статус

**2026-09-13 — обсуждение.** Постановка от владельца: нужен pipeline, который после создания/импорта заметки проверяет, нормализует и обогащает её до тех пор, пока она не соответствует критериям качественных данных. Критерии ещё не определены. Предварительные решения владельца зафиксированы ниже.

## Цель

Заметки, особенно импортированные из закладок/ссылок (`dust`), должны проходить контролируемый цикл обработки **до** того, как их увидит пользователь и до того, как запустятся текущие фоновые задачи (`ExtractKeywords`, `ComputeEmbedding`, `RecalculateLinkWeights`, `RefreshRecommendations`).

Pipeline должен:
- проверять структурную и семантическую корректность заметки;
- нормализовать title, content, metadata, `source_url`, type;
- обогащать (до тех пор, пока не исчерпаны возможности);
- сообщать пользователю о дубликатах/битых ссылках/низком качестве;
- не удалять и не принудительно объединять без согласия пользователя;
- писать всё, что сделал, в лог.

## Решения владельца (2026-09-13)

- **Без cron.** Обогащение — синхронная/очередная задача при создании/импорте и по ручной кнопке пользователя "доработать заметку".
- **Пользователь может поставить метку** на заметку, и она уходит на ту же лупу обработки.
- **Переклассификация допустима** (`dust` → `star`/`planet` и т.д.), но под контролем пользователя.
- **Связи/дубликаты**: не удалять, не объединять автоматически; предлагать пользователю, если хочет — откат.
- **Ссылки**: не ходить по сети. Проверять только синтаксическую валидность; битые помечаем, но не делаем ничего.
- **Всё пишем в лог**: какие критерии не прошли, какие изменения были предложены/применены.

## Главный открытый вопрос: критерии качества

Без определения "хороших данных" pipeline не знает, когда остановиться. Нужна система динамических весов и коэффициентов, по которым вычисляется **quality score** заметки.

### Предварительные критерии

1. **Структурные**:
   - `title` не пустой, в лимите, без мусора.
   - `content` не пустой или есть `source_url`.
   - `type` валиден, соответствует содержимому.
   - `source_url` синтаксически корректен (если есть).

2. **Семантические**:
   - Ключевые слова извлечены.
   - Эмбеддинг посчитан.
   - Нет дубликатов по `source_url` или embedding-близости.
   - Есть смысловой "вес" — не менее N слов или есть ссылка/цитата.

3. **Связностные**:
   - Есть рекомендации/связи, либо явно помечена как singleton.
   - Нет orphaned links.

4. **Пользовательские**:
   - Не помечена "требует доработки".
   - Не стоит в статусе `dust`/`debris` бесконечно.

### Идея шкалы качества

| Уровень | Диапазон | Что означает |
|---------|----------|--------------|
| `low` / низкое | 0.0 – 0.4 | Структурно сломано: пустой title, невалидный type, битая ссылка, дубликат. Требуется ручная обработка или повторный цикл. |
| `medium` / среднее | 0.4 – 0.7 | Есть данные, но маловато: нет keywords/embedding, мало контента, type не уверен (`dust`). Идёт на повторный проход. |
| `high` / высокое | 0.7 – 1.0 | Структура, семантика и связи на месте. Можно запускать `ExtractKeywords`/`ComputeEmbedding`/`RefreshRecommendations` и показывать пользователю. |

Коэффициенты можно делать динамическими: за каждый пройденный критерий начисляется вес, за критический дефект (`title` пустой, `type` невалиден) — штраф, который невозможно компенсировать другими баллами.

## Вариант stopping criteria

- **По достижению уровня `high`.**
- **По исчерпанию возможностей**: за итерацию ничего не изменилось (не добавились keywords, не сдвинулся type, не появились связи).
- **По лимиту попыток**: максимум 3 итерации с нарастающими задержками (30 сек, 5 мин, 1 час). После третьей — `needs_manual_review`.

## Предлагаемый pipeline (первый вариант)

```
Создание / импорт / ручная кнопка / метка "доработать"
        │
        ▼
┌──────────────────────────────┐
│ 1. Структурная проверка      │
│    (title, content, type,    │
│     source_url)              │
└──────────────────────────────┘
        │
        ▼
┌──────────────────────────────┐
│ 2. Нормализация              │
│    (trim, dedup, type infer, │
│     url parse)               │
└──────────────────────────────┘
        │
        ▼
┌──────────────────────────────┐
│ 3. Quality score             │
│    (динамические веса)       │
└──────────────────────────────┘
        │
        ▼
  quality >= high? ──YES──► запускаем ExtractKeywords / ComputeEmbedding / RecalculateLinkWeights / RefreshRecommendations
        │ NO
        ▼
┌──────────────────────────────┐
│ 4. Обогащение                │
│    (title infer, dedup hint, │
│     type suggestion)         │
└──────────────────────────────┘
        │
        ▼
  итерации исчерпаны? ──YES──► needs_manual_review
        │ NO
        └───────► ещё один проход (с задержкой)
```

## Что не входит (явно)

- Сетевые запросы к `source_url`.
- Автоматическое удаление/объединение заметок.
- Cron-обход всех заметок (до решения владельца).
