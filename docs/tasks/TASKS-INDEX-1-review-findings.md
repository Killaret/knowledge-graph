`BATCH-TEST-STRATEGY` → `BATCH-TEST-1-…`, `YAKE-REPLACE-…` → `NLP-2-…` и т.д. Проверил

документации; ревью витрины и есть ревью AUD-1. Идентификатор не выдуман. Ссылки на старые имена
починены — `check-docs-links` зелёный.

Я сам пользуюсь этим указателем и сторожем с 16.09 — он дважды поймал файл, потерявший якорь
после ретенции (`DEPLOY-review-findings.md`, `BACKUP-1-…`, `SECURITY-1-…`). Это лучшее
свидетельство, чем мутации.

## Мелочь по конструкции: указатель зависит от собственного коммита

Колонка «Last commit» — `git log -1 --format=%cs -- <файл>`. Любой коммит файла постановки
меняет дату → указатель расходится → сторож красный → нужен ещё один коммит «обновить дату».
В истории Devin таких коммитов-довесков пять (`generate(docs): update task index date…`); я
обхожу через `--amend`. Сторож, который краснеет от самого факта коммита, приучает к ритуалу,
а не к проверке.

Варианты: сторож не считает дрейфом расхождение **только в колонке даты** (сравнивать строки без
неё), либо колонку убрать — дата коммита есть в `git log`, указателю она не нужна. Первое проще
и сохраняет колонку как справочную.

## Принято без замечаний

- Генератор берёт идентификатор из доски и журнала, а не из имени файла — файл без якоря
  остаётся неизвестным, а не получает идентификатор из воздуха.
- Сообщение сторожа печатает ожидаемую и найденную строку — видно, что именно разошлось.
- Постановки не правились по содержанию — только имена и ссылки.
