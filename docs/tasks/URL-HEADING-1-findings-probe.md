## Overall findings

1. **`<title>` usually needs cleaning.** Site suffixes (`- Wikipedia`, `- jwt.io`, `| OneLogin Developers`) are common. A regex that removes the last dash/pipe and a known site name improves the candidate.
2. **`h1` inside `<main>`/`<article>` is the strongest title candidate.** On jwt.io the `<title>` is `JSON Web Tokens - jwt.io`, but the article h1 is `JSON Web Token (JWT) Debugger`; the h1 is semantically better.
3. **A global `<header>` should not be skipped blindly.** Wikipedia puts the article h1 in `mw-body-header` (a `header`-like container inside the article). The current skip of `header` should only apply to the page-level header directly under `<body>`.
4. **h2/h3 outline is reliable for structured content.** Technical docs (Keycloak, OneLogin, MDN, The API Book) and course pages produce clean nested outlines.
5. **Noise is not only in `<footer>`/`<aside>`.** Promotional sections (`Курс с помощью в трудоустройстве`, `Новости`, `Спасибо за подписку!`) can appear as h2 inside the main content area with classes like `course-promo`, `subscribe`, `news`. Class/ID-based filtering is necessary.
6. **Grid/container signals are useful but not enough alone.** `<main>` and `<article>` are present on many pages, but they are not universal. Fallback to ancestor class names (`content`, `page-content`, `mw-parser-output`, `documentation`) catches more pages.
7. **Course and marketplace pages have the most noise.** Yandex Practicum, Skillbox, Litres, Coursera and similar sites mix article content with calls to action, related courses, reviews and subscription forms.
8. **Duplicate detection by title string similarity is noisy.** `Auth Code Flow + PKCE` and `Auth Code Flow pt. 2` are related but not the same. A higher threshold and content comparison are needed before suggesting duplicates.
9. **Some pages are behind auth or return non-HTML.** Postman workspace URLs returned HTTP 401; cloud/bars and mail links require sessions. The extractor must handle failures gracefully and should not fail the whole batch.
10. **Russian pages do not differ structurally from English ones.** Cyrillic headings parse correctly with charset detection (`golang.org/x/net/html/charset`). The same heuristics apply.
