# UI-DESIGN-1. Переработка дизайна приложения

Статус: **задача на потом — разобрать вместе с владельцем.** Идея владельца 2026-09-26: раз в
аккаунте есть плагин design, использовать его для переработки дизайна приложения. Постановки ещё
нет: объём и приоритет решаются в разговоре.

## Чем работать

Навыки плагина design работают по скриншотам и описаниям, коннекторы (Figma, Slack и другие) им
не нужны:

- `design-critique` — структурная критика экрана: удобство, иерархия, согласованность;
- `accessibility-review` — проверка по WCAG 2.1 AA: контраст, клавиатура, размер целей, экранный
  диктор;
- `ux-copy` — тексты интерфейса: кнопки, ошибки, пустые состояния, подтверждения;
- `design-system` — несогласованные имена и захардкоженные значения в компонентах;
- `design-handoff` — спецификация для разработки: отступы, токены, состояния, поведение.

## Предлагаемый порядок — предмет разговора

1. Скриншоты главных экранов на тест-стенде: граф 2D и 3D с верхней панелью, панель заметки,
   список, превью импорта, модалки.
2. Разбор каждого экрана навыками выше.
3. Один список изменений с приоритетами.
4. Владелец выбирает, что делать.
5. Выбранное уходит Devin постановками.
