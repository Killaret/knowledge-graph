# KG-BOARD-1. Сводка доски и сторож давности: `kg-board` вместо чтения доски целиком

Постановка: Claude Code, 2026-11-15; дополнена 2026-11-15 (решение 116: держатель и очередь агента в бэклоге, поиск по архиву). Исполнитель: Devin. Ревью: Claude Code. Основание — решения 107
и 112, веха 4 [RULES-IMPORT-1](RULES-IMPORT-1-external-skill-set.md) (пп. 3–5). Идеи взяты из
`board-status.py` переданного набора. Сам скрипт не переносится: он разбирает другой формат доски.

## Зачем

1. **Доска читается целиком на каждом старте.** Сейчас `docs/AI_HANDOFF.md` весит 28 560 байт. Из них
   действовать нужно по десятку строк, а 43 строки бэклога на старте не нужны никому (решение 107).
2. **Давность строк не видит никто.** Devin не открывал доску с 18.10 по 14.11, 27 дней. SMART-CREATE-1
   стоит `отклонено` с 08.11. Ни один сторож об этом не сообщил: сторожа считают число строк и размер
   доски, но не их возраст.
3. **Старт Devin читает старую доску.** `hooks.on_start` в `.devin/config.yml` читает
   `docs/AI_HANDOFF.md` с диска до синхронизации. 2026-11-14 каталог Devin отставал от `origin` на
   8 коммитов, 2026-11-15 — на 2.
4. **`в работе` в бэклоге проходит сторож.** Правило 2 `check-board-limits.mjs` считает `в работе` и
   `отклонено` только в разделах агентов (массив `AGENT_SECTIONS`). 2026-11-14 в бэклоге так стояли
   14 строк, 2026-11-15 — BACKUP-4.

## Что сделать

### 1. Общий разбор доски

Разбор таблиц доски по разделам переносится из `check-board-limits.mjs` в
`scripts/testing/lib/board-parse.mjs`. Его используют оба скрипта, копии разбора быть не должно.
Поведение `check-board-limits.mjs` после переноса не меняется, кроме пп. 4 и 5.

### 2. Скрипт сводки `scripts/testing/board-status.mjs`

**Источник.** По умолчанию скрипт делает `git fetch origin` и читает доску через
`git show origin/ai-agents:docs/AI_HANDOFF.md`, а не рабочую копию. Флаги, как у
`check-board-limits.mjs`: `--board=<файл>` и `--today=YYYY-MM-DD` для тестов, `--no-fetch` для
работы без сети. Если `fetch` не удался, скрипт читает последний известный `origin/ai-agents`, а в
первой строке вывода предупреждает: «fetch не удался, доска на <хеш>».

**Вывод.** Обычный текст, без таблиц. По порядку:

1. Хеш `origin/ai-agents`, по которому построена сводка.
2. Маркеры «Прочитано» с давностью в днях.
3. Разделы «На Devin», «На Claude Code», «На человеке». Строка — идентификатор задачи (жирный текст до
   двоеточия в колонке «Что»), статус (первое слово из словаря), давность в днях, пометки из п. 3
   ниже и путь к постановке. Текст статуса после первого слова в вывод не идёт.
4. Бэклог — очередь каждого агента и владельца: строки бэклога, где он держатель, сверху вниз, в
   том же виде. Держатель — имя сразу после тире в статусе, после префикса «1.0 ·» или
   «после 1.0 ·», если он есть: `Devin`, `Claude Code`, `владелец` (решение 116). Пример:
   «**бэклог** — Claude Code: ревью №7 · готово у Devin 01.10» — строка в очереди Claude Code.
   Строки без держателя — только их число. Три верхние строки бэклога без учёта держателя очередь
   агента не показывают: 2026-11-15 очередь ревью Claude Code — 11 строк бэклога.
5. Реплики — только заголовки: кто → кому, дата, задача.

На доске 2026-11-15 вывод не длиннее 3 КБ. Код выхода — 0. Ненулевой — только если доску не удалось
прочитать.

**Поиск по архиву.** `--archive <слово> [<слово>…]` печатает строки `docs/archive/board/*.md`, где
есть все слова без учёта регистра: месяц, «Что», статус до 200 символов. Файлы — от нового месяца к
старому. Вопрос «что решили по …», «когда закрыли …» решается этим поиском, а не чтением архива
целиком — архив растёт каждый месяц. Сводку доски флаг не печатает.

### 3. Давность и сроки

**Движение строки** — более поздняя из двух дат: колонка «Обновлено» и последний коммит файла
постановки. Файл берётся из первой ссылки на `tasks/…` в колонке «Где». Дата коммита:
`git log -1 --format=%cs <ревизия> -- docs/tasks/<файл>`, где ревизия — та, с которой читается доска.
Если ссылки нет, файла нет в ревизии или клон неполный, берётся только «Обновлено», и это не ошибка.

**Сроки без движения** (решение 112): `в работе` — 2 дня, `отклонено` — 2, `на ревью` — 1,
`решает владелец` — 3. У `бэклог` срока нет. Строка старше срока помечается «просрочено N дн.».
Граница: строке ровно на сроке пометки нет, через день после него — есть.

**Срок в тексте статуса.** Срок пишется как «срок DD.MM» или «к DD.MM», иногда с годом: «срок 31.10»,
«к 28.10.2026». Найденный срок помечается «сегодня», «завтра» или «прошёл». Год, если не указан,
берётся из текущей даты. «до» не считается сроком: в документах проекта оно чаще значит условие
(«до 1.0», «до готовности 2D»), а не дату.

**Маркер «Прочитано»** старше 3 дней — пометка «давно не читал». N = 3 — умолчание постановки, а не
решение владельца, см. «Открытые вопросы».

### 4. Сторож лимитов: давность — предупреждением

`check-board-limits.mjs` печатает просрочки строк и маркеров из п. 3 в `warnings`. Код выхода от них
не меняется: давность сообщает человеку и агентам, что что-то зависло, но приёмку через `check-all` не
останавливает. Сторож читает рабочую копию, как сейчас, а даты коммитов берёт от `HEAD`.

### 5. Сторож лимитов: правило 2 во всех разделах

`в работе` и `отклонено` в «Бэклоге» и «На человеке» — ошибка: «статус не для этого раздела, строку —
в раздел исполнителя». Лимит 3 на исполнителя по-прежнему считается по разделам агентов. Новая
фикстура `fixtures/board-limits/` с такой строкой в бэклоге — сторож краснеет и называет строку.

Доска на этот случай уже вычищена: BACKUP-4 2026-11-15 переведена в `бэклог` с номером ревью.
Сторож с правилом из п. 5 на текущей доске зелёный.

### 6. Хук старта Devin

В `.devin/config.yml`, `hooks.on_start` и `rules`, чтение `docs/AI_HANDOFF.md` заменить запуском
`node scripts/testing/board-status.mjs .`. Если формат `config.yml` не умеет запускать команды при
старте, написать это в отчёте с источником: строкой документации Devin или опытом. Тогда хук
перестаёт читать доску, а сводку запускает `kg-work`, шаг 1.

### 7. `kg-work`, шаг 1, у обоих агентов

В `.claude/commands/kg-work.md` и `.devin/skills/kg-work/SKILL.md` шаг 1 читает вывод
`board-status.mjs`, а не доску. Доска целиком открывается только для правки строки, точечно, по
правилу шага 5. Шаг 0 (свой каталог, синхронизация) не меняется. Шаг 5 у обоих: в итоге сессии — хеш последнего запушенного коммита и строки владельца, просроченные
по сводке, с вариантами из постановки (протокол, «Как запускается работа», решение 116). Свою команду Claude Code не правит
(«Чего не делать» в `kg-work`), поэтому обе копии правит Devin.

### 8. Скилл `kg-board`

`.devin/skills/kg-board/SKILL.md`, `triggers: [user, model]`. Указатель — в
`.claude/skills/kg-board/SKILL.md`, как у `kg-new-chat`. Скилл запускает скрипт и пересказывает вывод
человеку: кто что должен, что просрочено. Описание — триггер (решение 110): `/kg-board`, «что на
доске», «кто что делает», «что висит». Скилл ссылается на скрипт и решения 107, 112, нормы не
дублирует. Строка о скилле — в базовом скилле `.devin/skills/knowledge-graph/SKILL.md`. Строки в
`CLAUDE.md` и протоколе пишет Claude Code после приёмки.

### 9. Тесты

`scripts/testing/board-status.test.mjs` на фикстурах в духе `check-board-limits.test.mjs`. Он же
строкой в `scripts/testing/core-checks.tsv`, рядом с `board-limits-tests`. Каждая мутация ниже должна
давать красный тест:

| Мутация | Что ловит |
|---|---|
| срок `на ревью` 1 → 2 | сроки по статусам |
| граница `>` → `>=` | строка ровно на сроке |
| дата коммита постановки не учитывается | движение по постановке |
| маркер «Прочитано» не проверяется | п. 5 RULES-IMPORT-1 |
| правило 2 снова только в разделах агентов | п. 5 этой постановки |
| источник — рабочая копия, а не `origin/ai-agents` | п. 3 «Зачем» |
| держатель берётся из раздела, а не из текста статуса | очередь агента в бэклоге |
| поиск по архиву — любое слово вместо всех | `--archive` |

Последнюю мутацию проверить можно на временном репозитории в тесте или вручную. Если вручную —
записать прогон в отчёте.

## Критерии приёмки

1. Каталог отстаёт от `origin/ai-agents` на коммит, изменивший доску. `board-status.mjs .` показывает
   новую версию.
2. На доске 2026-11-15 вывод не длиннее 3 КБ.
3. Пометки «просрочено» совпадают с ручным подсчётом по срокам решения 112 на фикстуре: строка на
   сроке, на день старше, с постановкой свежее «Обновлено», без ссылки на постановку.
4. «срок 31.10» на `--today=2026-11-15` — «прошёл», «к 16.11» — «завтра», «до 1.0» — без пометки.
4а. На доске 2026-11-15 в очереди Claude Code из бэклога — 11 строк ревью №7–17 и строки с
   держателем `Claude Code` после «1.0 ·» / «после 1.0 ·»; строка без держателя ни в одну очередь не
   попадает.
4б. `--archive BACKUP-3` находит строку BACKUP-3 в архиве; `--archive BACKUP-3 несуществующее` — ноль
   строк.
5. `check-board-limits.mjs`: просрочки — предупреждения, код выхода 0. `в работе` в бэклоге — ошибка.
6. Мутации из п. 9 красные, после отката зелёные.
7. Хук старта и `kg-work`, шаг 1, у обоих агентов запускают сводку.
8. `scripts/testing/check-all.ps1` без `-Quick` зелёный, сводка приложена.

## Открытые вопросы владельцу

Владелец решил сроки (решение 112). Два умолчания Claude Code поставил сам, их можно поменять до начала
работы:

- **N для «Прочитано» — 3 дня**, как ретенция реплик и срок `решает владелец`. 27 дней отсутствия
  Devin такой порог поймал бы на четвёртый день.
- **Давность — предупреждение, а не ошибка.** Ошибка останавливала бы `check-all` из-за того, что
  владелец три дня не ответил, а это не дефект кода.
