# NOTES-LIMIT-1. Больше 300 заметок — список и граф молча показывают 300

Статус: **бэклог — 1.0 · Devin.** Найдено Claude Code 2026-09-29 при замере GRAPH-LIGHT-1.

**Решение владельца (2026-09-29, NOTES-LIMIT-1):** исправить в 1.0. Слова владельца: «по поводу ноут
лимитов, да».

## Что происходит

Фронтенд берёт заметки одним запросом `GET /api/v1/notes?limit=10000`
(`frontend/src/shared/api/notes.ts`, `getNotes`). Бэкенд урезает `limit` до
`backend.pagination.max_limit` = 300 и отдаёт первые 300, сообщая `total`. Фронтенд `total` не читает.

Дальше граф фильтруется по этому списку: `FilterState.filterGraphData`
(`frontend/src/entities/graph/model/filter-state.ts`) оставляет только узлы, чьи заметки есть в списке,
и только связи между ними. Граф-сервис при этом отдаёт все заметки.

## Воспроизведение

Тест-стенд, `seed-test-data.ps1 -NoteCount 1000 -LinkCount 1000 -Seed 11 -PublicPercent 0`, вход
тестовым пользователем, главная страница (2026-09-29):

- `GET /api/v1/notes?limit=10000` → 300 заметок, `total: 1000`, `limit: 300`;
- `GET /graph-service/api/v1/graph/full` → 1 000 узлов и 1 000 связей;
- на экране: «300 nodes · 87 links», в списке 300 карточек.

Предупреждения нет. У кого больше 300 заметок — например, после импорта закладок, — тот видит часть
своего графа и не знает об этом.

## Что сделать

1. Список получает все заметки: постранично до `total` — или отображается постранично, если так решит
   владелец.
2. Граф без выбранного фильтра не теряет узлы, которых нет в списке.
3. Тесты: `total` больше `max_limit` — в списке и на графе все заметки; мутация «одна страница» —
   красная.
