## Блокер. Окно выбора закрывается тем же кликом, который его открыл

Живьём: правый клик по узлу → «Связать с…». MutationObserver фиксирует, что окно `link-target-picker` появилось и
исчезло:

| Страница | Мышью | Enter на пункте меню |
|---|---|---|
| `/` | появилось 6391 мс, исчезло 6392 мс | 7246 → 7247 мс |
| `/graph` | 6037 → 6037 мс | 6874 → 6875 мс |

Через 500 мс окна нет; создать связь из меню нельзя.

Причина: `LinkTargetPicker.svelte` слушает `click` на `window` (`handleClickOutside`). Клик по пункту меню сначала
открывает окно, затем всплывает до `window`. Цель клика — пункт меню, а не окно, и окно закрывается. Проверено
исполнением: если в живой странице остановить всплытие этого клика на `document`, окно остаётся открытым (прогон с
`UX1_WORKAROUND=1`).

Почему тесты не поймали. `LinkTargetPicker.spec.ts` рендерит окно отдельно, а `GraphNodeContextMenu.spec.ts`
проверяет только вызов `onLinkTo`. Связку «пункт меню → окно открыто» не проверяет ни один тест. Нужен тест, который
кликает «Связать с…» и ждёт, что окно видно. Без исправления этот тест должен быть красным.

## Принято без замечаний

- Пункт «Связать с…» скрыт в режиме только для чтения и без `onLinkCreate`.
- Исключения в списке: источник и технический узел Knowledge Core, как при протягивании связи.
- После выбора заметки открывается та же форма связи, что и при протягивании: тип и вес сохраняются по прежнему пути.
- `/graph`: полноэкранные загрузка, ошибка и пустое состояние остались только для случая без данных. Ошибка
  перезагрузки поверх графа — закрываемая плашка.
