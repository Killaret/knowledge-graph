Черновик — Devin, по обсуждению с владельцем 2026-09-21; **постановка v1 — Claude Code,

**Решение владельца (2026-09-23, CHUNK-1):** чанкинг с заголовком заметки в каждом чанке — в v1
включён. Переход на чанкованные (и нормализованные, NLP-4) векторы делается **один раз, вместе со
сменой модели** в MODEL-2 — одним пересчётом, с проверкой дельта-разметкой владельца (~25 пар,
решение 51).

## Постановка v1 (Claude Code, 2026-09-23)

Черновик ниже — алгоритм и параметры — принимается как есть. Открытые вопросы черновика закрыты
замером (`CHUNK-1-measurement-findings.md`) и решением владельца:

| Вопрос | Ответ v1 | Основание |
|---|---|---|
| Агрегация doc-вектора | **среднее** по чанкам | взвешенное (первый чанк ×2) почти не отличается: 0.744 → 0.768 на MiniLM, 0.963 → 0.967 на e5 — и сдвигает вектор к началу, то есть частично воспроизводит усечение, которое чиним |
| Заголовок в каждом чанке | **да**, параметр `title_injection` (по умолчанию `true`) | решение владельца; меняет ближайших соседей у 46 % заметок — поэтому проверка дельта-разметкой при включении |
| `target_tokens` / `max_tokens` / `overlap` | 256 / окно модели / 0 | как в черновике |
| Заметка-заглушка (контент — одна строка `## [title](url)`) | **ноль чанков → вектор только по заголовку**, в ответе `no_content: true` | 9 из 108 заметок корпуса; пустое не эмбеддится, но заметка не выпадает из связей — у заглушек импорта заголовок и есть содержание. Сам признак — сигнал для NOTE-QUALITY-1 |

### Что входит в v1

1. **Модуль** `nlp-service/app/core/chunking.py` — чистая функция `chunk(text, params) -> list[Chunk]`
   по алгоритму черновика, без FastAPI, модели и ввода-вывода. `token_count` считает токенизатор,
   переданный параметром (модуль от модели не зависит).
2. **Агрегация** — там же: `aggregate(vectors) -> vector`, среднее с L2-нормировкой; размерность
   не меняется.
3. **Подключение за выключателем.** Параметр `EMBED_CHUNKING` (env → конфиг, по умолчанию
   **`off`**):
   - `off` — `/embed` и путь ключевых слов работают **ровно как сейчас**;
   - `on` — `/embed`: чанки → один пакетный `encode` → среднее; в ответ добавляются `chunks: N` и
     `no_content: bool` (обратно совместимо). Путь ключевых слов: наивный `_doc_vector`
     (`nlp_utils.py:202`, 100 слов без структуры) заменяется этим чанкером.
   Включает выключатель MODEL-2 — вместе с новой моделью и нормализацией, одним пересчётом.

### Что не входит

Хранение чанков и их векторов (`nlp_artifacts`, `note_chunk_embeddings`) — это NLP-4 и MODEL-2:
размерность таблицы векторов зависит от выбора модели. Перекрытие чанков, порт на Java — бэклог.

### Критерии приёмки

1. **Инвариант окна:** ни один чанк не длиннее `max_tokens` — тест на фикстурах с длинными
   прогонами без пунктуации, код-блоком и таблицей длиннее окна.
2. **Ложные границы:** `т.е.`, `др.`, `e.g.`, `3.14`, инициалы `А.С.`, URL не рвут предложение —
   по тесту на каждый класс.
3. **Ничего не теряется и не дублируется:** склейка чанков без инъекции заголовка даёт весь
   непробельный текст исходника по порядку; `text[char_span]` совпадает с текстом чанка — тест
   по свойствам на случайных текстах.
4. **`heading_path`** верен на вложенных заголовках.
5. **Выключатель:** при `off` векторы `/embed` на корпусе фикстур совпадают с нынешними
   (косинус 1.0); при `on` размерность та же, заглушка даёт `no_content: true` и вектор заголовка.
6. **Мутации, каждая обязана краснеть:** снять инвариант окна; считать `т.е.` концом предложения;
   не обновлять `heading_path`; выключить инъекцию заголовка; агрегация «только первый чанк».
7. Скорость при `on` на текущей модели: p50/p95 на заметку по корпусу фикстур — в находках.
8. Документация: раздел о чанкинге и выключателе в `docs/architecture/ARCHITECTURE_SUMMARY.md`,
   параметр — в `docs/operations/CONFIGURATION_{EN,RU}.md`.
9. Adversarial Phase — раздел находок в этом файле; `check-all` без `-Quick` — сводка на доске или
   в журнале.

## Черновик (Devin, 2026-09-21)

## Проблема (факт, измерено 2026-09-21)

`/embed` в nlp-service вызывает `model.encode(req.text)` без чанкования
(`app/main.py`). У текущей модели `paraphrase-multilingual-MiniLM-L12-v2`
`max_seq_length = 128` — эмбеддинг заметки видит только первые ~128 токенов.
Медиана корпуса владельца — 384 слова: **большая часть текста в вектор
не попадает вообще**, все similarity/связи построены на усечённых входах.

Существующий `_doc_vector` (`nlp_utils.py`) режет по 100 слов — наивно:
слова вместо токенов, без структуры, без происхождения, не персистентно,
используется только в `extract_keywords`.

Чанкер — общая зависимость **NLP-4** (шаг 2 конвейера), **MODEL-2**
(окно e5-base 512 тоже < медианы корпуса) и **NLP-2** (заменяет `_doc_vector`).

## Решение (зафиксировано владельцем 2026-09-21)

### Алгоритм резки

Иерархия границ, от крупных к мелким:

0. **Жёсткий инвариант: `len(chunk) ≤ max_tokens` — всегда.** Чанк больше
   окна модели никогда не эмитится: модель урежет его молча, а молчаливое
   усечение хуже нашей явной резки. Это потолок, не рекомендация.
1. **Структурные блоки** — заголовки (markdown `#`-уровни), абзацы,
   прямая речь/цитаты. Код-блоки и таблицы — **атомарны предпочтительно**:
   не рвём, пока блок ≤ max. Блок > max — режется внутри по своей
   структуре (код — по строкам, таблица — по строкам) как последнее
   средство: инвариант (0) важнее атомарности.
2. **Предложения** — граница по знакам препинания `.!?…` (+ закрывающие
   кавычки/скобки относятся к завершённому предложению). Ложные границы
   отсекаются списками сокращений (`т.е.`, `др.`, `г.`, `i.e.`, `e.g.`),
   шаблонами чисел (`3.14`), инициалов (`А.С.`) и URL — списки и шаблоны
   внешние, по языкам.
3. **Клаузы** — только для предложения, которое само > max: режем по
   `;` `:` `,` (половинки получат близкие векторы — сходимость при сборке).
4. **Паковка** — предложения складываются в чанк жадно до `target_tokens`,
   не пересекая структурные границы; ниже предложения не дробим.
   Больше чанков-атомов лучше, чем меньше — но не по одному предложению.

### Параметры (внешние, не хардкод)

| Параметр | Значение v1 |
|---|---|
| `target_tokens` | 256 |
| `max_tokens` | окно модели (`model.max_seq_length`) |
| `sentence_end_chars` | `.!?…` |
| `closing_chars` | `»""')\]` |
| `abbreviations` | список по языку |
| `code_fence_markers` | ` ``` `, индент-блоки, markdown-таблицы |
| `overlap` | 0 (стыки чистые; вариант в бэклог) |

Алгоритм и параметры описываются **языконезависимо** — тот же чанкер
будет портирован в Java-сервис (middleware, большие объёмы). ML-сплиттеры
запрещены: только явные правила + словари.

### Выход чанка

```json
{"idx": 0, "text": "...", "heading_path": ["H1", "H2"],
 "char_span": [0, 480], "token_count": 120, "kind": "prose|code|table",
 "forced_split": false}
```

`token_count` считается токенизатором модели (привязка к `model_version`
осознанная — смена модели и так пересчитывает всё).

### Где живёт

`nlp-service/app/core/chunking.py` — чистый модуль, domain-уровень
(по Clean Architecture: без FastAPI/модели/I/O; функция
`chunk(text, params) -> list[Chunk]`). Оркестрация (когда резать, куда
писать) — в application-слое пайплайна NLP-4, не здесь.

### Процедурные решения

- **Атомарная единица — заметка.** Правка → пересчёт всех чанков;
  идентичность отдельного чанка не отслеживаем. (Поправка к спеке NLP-4:
  «выборочный пересчёт изменившегося раздела» уходит в бэклог.)
- **Overlap** — v1 без; пункт в бэклог.
- Чанкер работает на любом тексте — нормализованном (NLP-4) или сыром
  (текущий /embed, MODEL-2 до NLP-4).

## Открытые вопросы (эмпирически, на корпусе)

1. **Агрегация doc-вектора:** mean vs взвешенный (первый/заголовочный
   чанк тяжелее). Замерить оба — тот же харнес, что для нормализации.
2. **Title-инъекция:** подставлять ли `title` заметки (+ e5-префикс
   `passage:`) в начало каждого чанка. Плюс — контекст темы для
   серединных чанков; риск — раздувание внутризаметочного сходства.
   Замерить с/без. Владелец склоняется к «да», решение — по цифрам.
3. **Срок годности замеров.** Все эмпирические результаты (этой задачи
   и NLP-4-normalization-measurement) валидны для текущего качества
   входных данных. После трека NOTE-QUALITY-1 / доработки заметок
   Java-контуром входной корпус изменится и **все замеры надо
   перепрогнать** — выводы могут не устоять.

## Связи

- **NLP-4** — чанкер = шаг 2 конвейера; происхождение/хранение по его спеке.
- **MODEL-2** — `passage:`/`query:` префиксы, окно 512, таблица
  `note_chunk_embeddings`.
- **NLP-2** — `_doc_vector` заменяется этим чанкером.
- **NOTE-QUALITY-1** — та же логика весов/качества нужна Java-сервису;
  параметры чанкера — часть будущего контракта.
- **URL-HEADING-1** — `heading_path` — задел под неё.

## Находки реализации (Devin, 2026-09-24)

**Условная полнота.** Код за выключателем готов и проверен; сам чанкер в
боевом смысле «не полный», пока не закрыты зависимости: активация —
MODEL-2 (вместе с моделью и нормализацией NLP-4, одним пересчётом), а
замеры на корпусе перепрогоняются после NOTE-QUALITY-1 (входные данные
изменятся). См. «На человеке» на доске.

### Корпусной прогон (108 заметок, `work-nlp4/notes_dataset.json`, реальная модель из кэша)

- **off-паритет:** вход модели байт-в-байт совпадает с legacy
  `title + " " + content` у 108/108; на закодированном образце (10)
  min cosine = 1.000000. Различие появилось только потому, что worker
  теперь шлёт `content`/`title` раздельно — сборка строки перенесена
  в сервис и воспроизводит legacy точно.
- **on-путь:** dim = 384 у всех; чанков/заметку p50 = 8, max = 25;
  `no_content: true` у 8 заметок (в постановке оценивалось «9 из 108» —
  строгий и нестрогий паттерн `## [t](u)` находят 8; расхождение
  зафиксировано, не считаю дефектом: оценка была приблизительной).
- **Скорость on (CPU, MiniLM):** p50 = 337.8 мс, p95 = 823.5 мс,
  mean = 357 мс на заметку.
- Скрипт: `nlp-service/scripts/measure_chunk1_flag.py` (заголовки не
  печатаются — решение 47).

### Мутации (критерий 6 — каждая красная)

| Мутация | Красные тесты |
|---|---|
| Окно: oversized-юнит эмитится целиком | window_invariant, long_unbreakable, title_overhead (3) |
| `т.е.` считается концом предложения | все 7 false-boundary параметризаций |
| `heading_path` не обновляется | nested_heading_path, structured_text (2) |
| Инъекция заголовка выключена | title_injection, embed_on, doc_vector_on (3) |
| Агрегация «только первый чанк» | mean_with_l2_normalization (1) |
| Доп.: резерв бюджета под заголовок снят | title_overhead_is_reserved (1) |
| Доп.: `_combined_text` убран из off-пути | embed_off_combines_title_and_text (1) |

**Замечание о прочности:** две ослабленные мутации инварианта окна
(убрать ранний force-split / убрать проверку `actual_tokens` во flush)
остались зелёными — инвариант защищён в двух местах; ломающая мутация
(эмит oversized целиком) красная. Это не дыра в покрытии, а двойная
защита; зафиксировано честно.

### Adversarial-фаза: найденные дефекты

- Реализационный регресс при разработке: `extract_keywords(None)` падал
  после введения `_combined_text` — пойман существующим тестом, исправлено
  guard'ом на входе.
- Новых дефектов продукта adversarial-прогон не нашёл: ложные границы,
  stub-заметки, границы окна, пустые/однотокенные/неразрывные тексты
  покрыты и зелёные.

### Известные ограничения (осознанно, v1)

- `char_span` склеенных чанков может пропускать пробельные разделители —
  инвариант: непробельные символы сохраняются по порядку (property-тест).
- При `token_counter` заголовка ≥ `max_tokens` резерв бюджета не
  применяется (инъекция может превысить окно) — патологический случай,
  для заметок заголовок короткий.
- Индент-код и таблицы определяются построчно; вложенные фенсы/екзотика
  Markdown — упрощённо, достаточно для корпуса.
- `EMBED_CHUNKING` включается только в MODEL-2; `on`-вектора не
  совместимы с текущими `note_embeddings` — пересчёт обязателен.
