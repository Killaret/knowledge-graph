## Блокер

### Фильтрация по модели в graph-service не покрыта ничем, а единственный касающийся её тест сломан

Боевой запрос (`services/graph-service/internal/db/postgres_client.go:247`) теперь такой:

```sql
SELECT note_id, embedding::text, updated_at FROM note_embeddings
WHERE note_id = ANY($1) AND model_name = $2
```

А схема в `postgres_client_integration_test.go:80-85` колонки `model_name` не содержит вовсе:

```sql
CREATE TABLE IF NOT EXISTS note_embeddings (
    id UUID PRIMARY KEY,
    note_id UUID NOT NULL REFERENCES notes(id),
    embedding vector(3),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

Воспроизведение:

```
cd services/graph-service && go test -tags=integration -count=1 -run TestPostgresClient ./internal/db/

--- FAIL: TestPostgresClient_Integration/GetEmbeddings
    Received unexpected error:
    ERROR: column "model_name" does not exist (SQLSTATE 42703)
```

**Вторая половина хуже первой: об этом никто бы не узнал.** Файл помечен `//go:build integration`, а интеграционные тесты во всём репозитории запускаются только внутри `backend/`:

| CI, `backend-integration-tests` | `go test -tags=integration ...` | `backend` |
| `run-full-test-cycle.ps1:195` | `go test -tags=integration ...` | `backend` |

То есть `postgres_client_integration_test.go` не исполняется **нигде**.

Проверил мутацией: убрал `AND model_name = $2` из боевого запроса, оставив вызов с двумя параметрами — то есть внёс дефект, который упал бы ещё и в рантайме на несовпадении числа аргументов. ### Находка: `-post` игнорирует `-dry-run`

`cmd/embed-recompute/main.go:45`:

```go
if *post {
    runPostSteps(ctx, database, cfg)
    return
}
```

Возврат происходит до проверки `-dry-run` на строке 69, а `runPostSteps` про этот флаг не знает вовсе. Значит `embed-recompute -post -dry-run` **выполняет** `REINDEX` и `DELETE FROM note_recommendations`, тогда как оператор просил предпросмотр.

Данные не теряются: рекомендации производные и ставятся на пересчёт тут же. Но флаг обманывает, а команда деструктивная — это ровно тот случай, когда предпросмотр и просят. Лечится либо честным dry-run внутри `runPostSteps`, либо явным отказом на несовместимую пару флагов.
