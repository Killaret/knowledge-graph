# NOTE-HEALTH-1. Техническое и пользовательское здоровье заметки

Статус: **бэклог — этап 0 в 1.0 (Devin, маленький); этапы 1 и 2 — после этапа 2 NOTE-QUALITY-1.**
Постановка — Claude Code, 2026-09-27, по разговору с владельцем.

**Решение владельца (2026-09-27, NOTE-HEALTH-1):** здоровье заметки — две разные сущности, и они не
сливаются. Граница — кто может починить: техническое чинит система, пользовательское — только человек.
Техническое показывается, только когда что-то не так; пользовательское видно всегда. У библиотеки и
кластера — оба уровня отдельно. В 1.0 декоративный «HEALTH» скрывается, а нынешняя строка «Качество»
становится строкой «Обработка».

## Зачем

Мысль владельца от 14.09 (NOTE-QUALITY-1): здоровье — видимая функция, а не внутренняя метрика; нужен
понятный индикатор «хорошая / средняя / плохая» и здоровье библиотеки или кластера. Сейчас:

- строка «Качество» в панели заметки смешивает оба здоровья: «обрезана при импорте» и «битая кодировка»
  — вина обработки, «пустая» — вина содержания;
- «хорошая / средняя / плохая» нет — это веса этапа 2 NOTE-QUALITY-1;
- здоровья библиотеки нет; «HEALTH» в нижней панели — декорация: отношение числа связей к числу заметок
  (`frontend/src/widgets/cosmic-cockpit/CockpitBottomPanel.svelte:15`, «Phase 1: decorative health»).
  Соседний «CLUSTER Deep Space» — заглушка до P11-4.

## Модель

| | Техническое здоровье | Пользовательское здоровье |
|---|---|---|
| вопрос | система сделала всё, что могла? | заметкой можно пользоваться? |
| кто чинит | система: повтор шага, перезабор, дообогащение с пределом попыток (решение 77) | только человек; система подсказывает |
| состояния | в порядке, в обработке, требует дообработки, сырая | хорошая, средняя, плохая — разметка владельца |
| показ | только при проблеме: «Обработка: обрезана при импорте — Перезабрать» | всегда: оценка и что улучшить |
| когда меняется | успокаивается после обработки | когда человек правит заметку |
| кому ещё | вердикты `create`, `enrich`, сырая — маршрутизация для Java-сервиса (решение 42) | — |

Сигналы NOTE-QUALITY-1 по сущностям:

| Сигнал | Здоровье | Кто чинит |
|---|---|---|
| обрезана нашим лимитом | техническое | система — перезабор |
| битая кодировка | техническое | система — перезабор с верным декодированием |
| нет вектора или ключевых слов, ошибка обработки | техническое | система — повтор шага |
| только ссылка | сначала техническое, потом пользовательское | система загружает страницу; зачем она сохранена, знает человек |
| пустая | пользовательское | человек |
| обрывки без структуры, шаблонное название, нет мысли | пользовательское | человек, система подсказывает |

## Этап 0 — в 1.0 (Devin, маленький)

1. Декоративный «HEALTH» в нижней панели скрыт, пока не готова настоящая метрика.
2. Строка «Качество» в панели заметки называется «Обработка» и показывается, только когда что-то не
   так; при «в порядке» строки нет.

Критерии: тест компонента — при «в порядке» строки нет, при проблеме — «Обработка» с причиной;
нижняя панель без «HEALTH»; снимок — в `docs/agents/MANUAL_TEST_FEEDBACK.md`.

## Этап 1 — после этапа 2 NOTE-QUALITY-1

1. Пользовательская оценка «хорошая / средняя / плохая» по весам этапа 2 и подсказка, что улучшить.
2. Техническое и пользовательское хранятся и отдаются API раздельно.

## Этап 2 — библиотека и кластер

1. Библиотека: техническое — «N заметок не обработаны до конца» (диагностика); пользовательское —
   сколько хороших, средних и плохих, фильтр «плохие».
2. Кластер: то же в легенде кластеров (P11-4).
3. Нижняя панель показывает настоящую метрику вместо скрытой декоративной.

Критерии этапов 1 и 2 — при их постановке, по итогам этапа 2 NOTE-QUALITY-1.

## Этап 0 — исполнение (Devin, 2026-10-01)

1. **Декоративный «HEALTH» скрыт.** `CockpitHUD` принял `health?: number | null` (по умолчанию
   `null` — блок `hud-health` не рендерится); `CockpitBottomPanel` больше не передаёт декоративное
   «links/1.5·nodes» значение. Код отрисовки и тесты цветовых поясов остаются — этап 2 вернёт
   настоящую метрику через тот же проп.
2. **«Качество» → «Обработка», только при проблеме.** Строка в `CockpitNoteDetails` рендерится при
   `qualityStatusKey(q) !== "cockpit.noteDetails.quality.ok"`; при «в порядке» строки нет — вместе с
   кнопками действий (они недостижимы без строки, что соответствует модели «техническое чинит
   система»). Значение `quality.label`: «Processing» / «Обработка».

**Тесты:** `quality.spec` — строка отсутствует при чистом вердикте, метка «Processing/Обработка»
при проблеме; тесты Re-assess/restore переведены на проблемные записи (раньше работали на чистой —
теперь такой строки нет). `CockpitHUD.spec` — `hud-health` отсутствует без пропа. Мутации
«health всегда» и «строка всегда» — красные. Живой снимок нижней панели: спек
`tests/note-health-1.spec.ts`, результат в `docs/agents/screenshots/note-health-1/`.

Этапы 1–2 не тронуты — после этапа 2 NOTE-QUALITY-1.
