# MODEL-1B. Дозамер моделей: точность на папках, порог, полный конвейер

Постановка: Claude Code, 2026-09-23. Исполнитель: Devin. **Первая в очереди блока моделей.**
Продолжение [`MODEL-1`](MODEL-1-embedding-model-measurement.md): её замер закрыл скорость, память и
выдачу поиска, но оставил три дыры, без которых выбор модели делать рано.

**Решение владельца (2026-09-23, MODEL-1B):** перед выбором модели — этот дозамер. Выбор — между
`multilingual-e5-small` и `multilingual-e5-base` по заранее оговорённому правилу (ниже); решение
остаётся за владельцем и принимается по выдачам (решение 41), точность — дополнительная линза.
Любая смена модели включает перекалибровку порога автосвязей под шкалу новой модели.

## Три дыры MODEL-1

1. **Таблица близости пар есть только для текущей модели.** В `MODEL-1-review-findings.md` под
   каждым кандидатом вместо пар стоит строка параметров (ошибка сборки отчёта), в
   `MODEL-1-findings-raw.md` таблица 2 есть только для `current@128`. А это то, из чего
   строятся автосвязи.
2. **Точность по папкам мерили только для текущей модели.** Харнес W-1
   (`nlp-service/scripts/eval_link_formula.py`) умеет подменять векторы, но кандидатов через
   него не прогоняли. Для `current@128`: p@1 = 0.506, p@3 = 0.451 (exact).
3. **У e5 другая шкала близости.** У текущей модели первый сосед на корпусе владельца в среднем
   0.62 — порог `GAMMA_LINK_MIN_SCORE = 0.6` проходит примерно половина заметок. У e5-base
   ближайшие соседи 0.88–0.92 (`CHUNK-1-measurement-findings.md`) — с порогом 0.6 каждая заметка
   связалась бы с двумя ближайшими, какими бы они ни были. Порог надо выводить заново для
   каждой модели.

Плюс подозрение: e5-base в MODEL-1 медленнее e5-small в 9 раз (2 320 против 256 мс), а по объёму
вычислений ожидается раза в четыре. Перемерить с одинаковыми настройками потоков.

## Варианты

Восемь, на одном корпусе, одним скриптом:

| | Модель | Текст | Вектор |
|---|---|---|---|
| A | текущая, окно 128 | сырой | усечение — **как сейчас в проде** |
| B | e5-small, окно 512 | сырой | усечение |
| C | e5-base, окно 512 | сырой | усечение |
| D | текущая, окно 128 | нормализованный | чанки, среднее, заголовок в каждом чанке |
| E | e5-small | нормализованный | чанки, среднее, заголовок в каждом чанке |
| E′ | e5-small | нормализованный | чанки, среднее, **без** заголовка |
| F | e5-base | нормализованный | чанки, среднее, заголовок в каждом чанке |
| F′ | e5-base | нормализованный | чанки, среднее, **без** заголовка |

D–F — то, что пойдёт в прод после MODEL-2: нормализация (NLP-4, один проход с предохранителями) и
чанкер (CHUNK-1, среднее по чанкам, заголовок в каждом чанке — решение владельца). Здесь их
прототипы из `measure_normalization.py` и `measure_chunking.py` — промышленных модулей ещё нет,
расхождение с ними оговорить в находках. Префиксы e5: `passage:` для заметок, `query:` для
запросов поиска.

## Что мерить

1. **Точность по папкам** — харнес W-1 без изменений метода: p@1, p@3, p@5 на трёх
   гранулярностях (exact, l1, parent), 79 заметок с непустой папкой.
2. **Кривая порога** — для каждого варианта, степень 2 (как в проде): для порогов 0.30…0.95 с
   шагом 0.05 — доля заметок, получивших хотя бы одну связь, и точность этих связей (цель в той
   же папке, exact). Отдельной строкой — **t\*: наименьший порог, при котором точность ≥ 0.50**
   (ориентир W-1). Это и есть стартовое значение `GAMMA_LINK_MIN_SCORE` для модели.
3. **Распределение близости** первого и второго соседа — медиана и среднее для каждого варианта.
4. **Шум.** Бутстрэп по заметкам (1 000 повторов): 95-процентный интервал разности
   p@3 exact **F − E**. Это то, на чём стоит правило выбора.
5. **Скорость и память** — для A, E, F: время на заметку целиком (нормализация + чанки + векторы),
   p50/p95; время на один чанк; RSS. Для e5-small и e5-base — одинаковые `torch.get_num_threads()` и
   `OMP_NUM_THREADS`, значения записать. Объяснить разрыв 9× или показать, что он был артефактом.
6. **Для глаз владельца** — таблица близости пар (top-15 на тех же 20 заметках) для всех восьми
   вариантов и выдача поиска top-10 по десяти запросам MODEL-1 для A, E и F.
7. **Лист дельта-разметки** (решение 51): 25 заметок, у которых первый сосед в лидирующем варианте
   (E или F — у кого выше p@3) отличается от A. В строке: заметка, прежний сосед, новый сосед,
   колонка для отметки владельца «было лучше / стало лучше / оба мимо».

## Правило выбора — оговорено заранее

- Если 95-процентный интервал разности p@3 exact **F − E** целиком выше нуля — e5-base лучше за
  пределами шума: **e5-base**, с миграцией колонки 384 → 768 и медленной фоновой обработкой
  (владелец ставит качество выше скорости).
- Иначе — **e5-small**: та же размерность 384, колонка не меняется.
- Правило подсказывает, решает владелец: смотрит выдачи и лист разметки. Итоговая строка находок —
  что выбирает правило и на каких цифрах.

  абсолютный путь, чтобы владелец их открыл. Это принцип решения 47 — не добавлять личные данные
  в публичный репозиторий, пока старые убираются.
