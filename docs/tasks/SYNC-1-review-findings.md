**Вердикт: отклонено.** Транспорт SSE работает живьём, применение по месту в `delta.ts` верное. Но холст
применяет дельту по месту только пока симуляция ещё не остановилась. У пользователя, который просто смотрит на граф,

### Блокер 1. В покое дельта не применяется по месту (критерий B.1)

`GraphCanvas.svelte`: эффект данных уступает дельте только при `simState.isRunning` (стр. 849), эффект дельты при
`!simState.isRunning` помечает дельту принятой и выходит (стр. 973). Но `isRunning` становится `false`, как только
затухание закончилось (`simulation.ts:158`). Это обычное состояние открытого графа через несколько секунд после
загрузки.

Живьём (`sync1-probe.cjs 12000`: 12 с на установление, потом изменение через API из «другой вкладки»; два прогона):

| Изменение | Что на холсте |
|---|---|
| новая заметка | появилась через 0,8–1,1 с; все прежние узлы — новые объекты симуляции, сдвиг 45–107 px |
| переименование | дельта с `updated_nodes: "Alpha renamed"` пришла через ~0,5 с; холст за 15 с название не сменил. Отдельный прогон: 6 с — старое название, после перезагрузки — новое |
| связь между стоящими узлами | все узлы — новые объекты, сдвиг 57–241 px |
| удаление заметки | узел ушёл через 0,6–0,9 с; остальные — новые объекты, сдвиг 16–183 px |

Новые объекты и большой сдвиг означают полную перестройку: `clearSimulation` и `startSimulation`, узлы заново на
окружности, сброс камеры. Это то самое «мигание» из дыры 6.

Контроль (`sync1-probe.cjs 0` — изменение сразу после загрузки, пока симуляция идёт): новая заметка встала по месту,
прежние узлы — те же объекты. Значит, `applyIncremental` верен, а ломает его гейт в холсте.

### Блокер 2. Тесты не ловят перестройку на уровне холста (критерий B.2)

Мутация: в `GraphCanvas.svelte:849` условие уступки заменено на `false`, то есть холст перестраивается на каждое
изменение. Результат: `src/widgets/graph-canvas` и `src/entities/graph-canvas` — 384 из 384 зелёные.
`GraphCanvas.events.spec.ts`, тест «applies delta updates to the simulation», проверяет только число узлов (5). Оно
одинаково и при применении по месту, и при перестройке. Нужен тест холста: симуляция остановилась, пришла дельта,
прежние узлы — те же объекты и на тех же координатах; переименование видно в `getSimulationNodes()`. Мутация гейта
должна делать его красным.

### Блокер 3. Автосвязь воркера на граф не попадает (критерий C.1)

`c-probe.cjs`: при открытом графе через API созданы две почти одинаковые заметки. Воркер создал две связи `gamma`
(12:43:04,1 и 12:43:04,8), сигнал SSE пришёл, клиент сам запросил дельту четыре раза за 4 с. Но ни в одной дельте
связей нет, и в `/graph/full` этого пользователя `links=[]`.

Причина — вне диффа B/C. Автосвязи пишутся с `creator_id = NULL` (на тест-стеке: `gamma` — 5 из 5 без владельца,
`user` — 6 из 6 с владельцем), а граф-сервис отбирает связи по `creator_id = $1` (`linkVisibilitySQL`,
`services/graph-service/internal/db/postgres_client.go:247`, с `03671d0`, июль). Критерий C.1 без этого не выполнить
ни через SSE, ни опросом. Отчёт автора честно оговаривает, что C.1 живьём не прогонялся. Где чинить — у воркера или
в фильтре граф-сервиса — решает исполнитель; живой прогон C.1 после починки обязателен.

### Принято без замечаний

- `applyIncremental`: удаление узла вместе с инцидентными связями, связь по ключу без дубля, добавление через

- Брокер SSE: поток несёт только `{event, event_id}`, изоляция по `user_id` держится тестом и мутацией, битые события

- Живьём новая заметка из другой вкладки приходит через 0,5–1,1 с без действий пользователя — доставка из ADR 014
  работает.
- nginx: отдельный location без буферизации в обоих конфигах.

### Попутно

- **`ux3-blackhole.spec.ts` при `SKIP_AUTH`** — см. `UX-3-review-findings.md`, «Попутно». Причина там названа: ключ
  кэша `skip-auth` против `user_id` события в `pubsub.go:205`. Здесь не перепроверял. При настоящем входе удаление
  доходит до холста за 0,6–0,9 с, таблица выше. Спек входит в `chromium-skip-auth`, а тот гоняет CI, — чинить
