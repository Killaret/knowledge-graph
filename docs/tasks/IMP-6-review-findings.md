## Правка 1 — тело запроса ≥ 10 КБ восстанавливается: принято

`logging.go` читал тело и возвращал его только при `< 10000` байт; теперь возвращает всегда,
разбирает для лога — только малое. Мутация (вернул `&& len(bodyBytes) < 10000` в условие):

```
--- FAIL: TestLoggingMiddlewareRestoresLargeRequestBody
```

Тест с телом 11 000 байт ловит откат. Хорошая правка, хороший тест.

## Правка 2 — валидатор `url` убран из `importItem`: объяснение неверно, тест холостой

Постановка: «валидатор Gin `url` требует схему+хост и отверг `javascript:` на этапе binding».
Проверил валидатор напрямую (`validator/v10`, `Var(u, "url")`):

```
javascript:(function(){})();     true
chrome://settings                true
about:blank                      true
file:///C:/x                     true
www.example.com                  false
```

`javascript:` валидатор **принимает**. Отвергает он адрес **без схемы**. Следовательно:
(а) названный механизм не мог дать 400 на `javascript:`; 400 на живом стенде давала правка 1
(тело > 10 КБ → EOF), и это подтверждено в самой постановке замером 9999/10001 байт;
(б) регрессионный тест `note_handler_import_test.go:147` шлёт `javascript:` — с возвращённым
валидатором он **проходит**:

```
mutation: binding:"required,url,max=16384" восстановлен
ok  	knowledge-graph/internal/interfaces/api/notehandler	3.536s
```

Тест, который зелёный и с правкой, и без неё, ничего не охраняет.

Сама правка — перенос проверки URL с binding на поэлементную ошибку — разумна и остаётся.
Нужно: тест с адресом **без схемы** (`www.example.com`) — с валидатором он даёт 400 на всю
пачку, без валидатора — 200 и per-item ошибка; и абзац в постановке исправить, чтобы читатель
не унёс ложный механизм дальше.

## Правка 3 — параллельный фетч в `Preview` (×10) и таймаут клиента 120 с: принято

Семафор на 10 и `WaitGroup` в `service.go:332`. Живой прогон Devin на реальном файле владельца
(135 ссылок) — 200/200/200; повторить не могу, файл в репозиторий не входит и не должен.
Ограничение параллелизма разумное; отдельного теста на тайминг не требую.
