# P11-4. Кластеризация графа

Статус: **бэклог — 1.0 · Devin; запуск после MODEL-2** (решение 67): пороги калибруются на
окончательной модели эмбеддингов. Постановка — Claude Code, 2026-09-27, по журналу
[`P11-1-clustering-design-notes.md`](P11-1-clustering-design-notes.md), решениям 28 и 79.

**Решение владельца (2026-09-27, P11-4):** кластеры показываются цветными областями под узлами; в 1.0 —
два уровня, кластеры и подкластеры, с семантическим масштабом: издалека видны кластеры с именами,
ближе — подкластеры, вблизи — заметки; имена меняются по уровню. Кнопки «пересчитать» на экране нет:
пересчёт идёт сам, принудительный — командой, описанной в документации. Глубину вложенности потом
определяет сам кластер, а не фиксированное число; в 1.0 — два уровня. Уточняет решение 28 («иерархия
и масштаб — позже»). Владелец выбирал по живому макету: три уровня масштаба, области против оттенка
узлов.

## Решения владельца (решение 28, журнал P11-1)

- Метод гибридный: семантика — основа, связи дополнительно сближают заметки.
- `cluster_id` стабилен: детерминированный обход плюс наследование id через сопоставление с прежним
  разбиением. Иерархия и масштаб — уточнено решением 79: два уровня в 1.0.
- Модель веса ребра описывается в этой задаче.

## Что есть сейчас (проверено 2026-09-27)

- Кластеров нет нигде: ни в сервисе графа, ни в API, ни во фронтенде.
- Координат заметок в базе нет; раскладка — в браузере и в сервисе графа. Кластеризация строится по
  векторам и связям, не по координатам.
- Сервис графа уже читает эмбеддинги (`services/graph-service/internal/db/postgres_client.go`,
  `GetEmbeddings`) — гибрид считается целиком внутри него.
- `links.weight` — не независимый сигнал: пересчёт ставит весом любой связи, ручной и автоматической,
  сходство текстов из NLP (`backend/internal/application/linkweight/service.go`, `Similarity` →
  `UpdateWeight`).
- Ключевые слова — леммы с исходной формой (NLP-2, P11-3) — годятся для имён кластеров.
- Модель мультиязычная (P11-2); замер P11-2: один смысл на разных языках — 0,96–0,99, несвязанные
  тексты — 0,51–0,60.

## Модель веса ребра

```
w(i,j) = α · sem(i,j) + β · rel(i,j)
```

- `sem` — косинус эмбеддингов, только для k ближайших соседей выше порога τ. По замеру P11-2 порог
  ставится заметно выше 0,6; точное значение — на окончательной модели после MODEL-2.
- `rel = base(link_type) · origin(source_type)`: ручная связь — полный вклад, автосвязь — уменьшенный;
  автосвязь одна ребро не создаёт. `links.weight` не используется — это тот же `sem` другим путём.
- Типы связей — по LINK-TYPES-1 (`related`, `dependency`; `parent` и `child` — до ORIGIN-1). После
  ORIGIN-1 происхождение «рождена из» — дополнительный вклад в `rel`.
- `α`, `β`, `τ`, `k`, `base`, `origin` — в конфиге.

## Разбиение

- Louvain по графу `w` в сервисе графа. Детерминизм: узлы и рёбра в порядке id, фиксированное зерно.
- Наследование id: каждый новый кластер сопоставляется с прежним по наибольшему пересечению множеств
  заметок; совпавший получает прежний id, остальные — новые.
- **Два уровня** (решение 79): кластеры и подкластеры. Louvain и так строит разбиение слоями —
  подкластеры берутся с предыдущего слоя того же расчёта. Подкластер целиком лежит в своём кластере.
- Наследование id — на каждом уровне отдельно, тем же сопоставлением по пересечению.
- Пересчёт — сам, по событиям графа (механизм SYNC-1 A2) с задержкой, чтобы пачка правок дала один
  пересчёт. Кнопки на экране нет; принудительный пересчёт — команда (по образцу
  `backend/cmd/quality-recompute`), описанная в `COMMANDS.md`.
- Кэш — в Redis, по хешу данных, как снимки SYNC-1.

## Имя кластера

- Автоматически — 2–3 ключевых слова с наибольшим TF-IDF: у кластера — относительно всего графа, у
  подкластера — относительно своего кластера. Считается по леммам, показывается исходной формой.
- Пользователь может переименовать; своё имя переживает пересчёт через наследование id.

## API

- `/graph/full` и дельта: у узла — `cluster_id` и `subcluster_id`; отдельный список кластеров и
  подкластеров: id, родитель, имя, размер, цвет.
- Переименование кластера — отдельный метод; `openAPI.yaml` — вместе с кодом.

## Показ на графе (решение 79)

Цветные области под узлами; в 3D — туманность, «галактика». Семантический масштаб, границы — в конфиге:

| Масштаб | Что видно |
|---|---|
| далеко | области кластеров, имена кластеров; заметки — мелкие точки без подписей |
| средне | области подкластеров, их имена; подписи у главных заметок (UI-GRAPH-1) |
| близко | области едва видны, подписи у всех заметок |

Легенда — имена кластеров и фильтр «только этот кластер». Цвет подкластера — оттенок цвета кластера.
Цвета областей не спорят с цветами типов узлов и связей (LINK-TYPES-1).

## Не в 1.0

Больше двух уровней: глубину вложенности потом определяет сам кластер — делится, пока есть на что
(решение 79). Трек A (`docs/architecture/clustering.md`, отложена), стражи кластеров, Orbital 3D,
Knowledge Voyager.

## Критерии приёмки

1. Детерминизм: два пересчёта на одних данных — то же разбиение и те же id — тест.
2. Наследование: добавили заметку — id остальных кластеров не изменились; кластер разделился — больший
   кусок сохранил id — тесты.
3. `links.weight` в `w` не участвует — мутация «вес связи в `w`» красная; автосвязь одна ребро не
   создаёт — тест.
4. Русская и английская заметка об одном попадают в один кластер — тест на фикстуре с векторами
   окончательной модели.
5. Имя: по леммам, показ исходной формой; переименование переживает пересчёт — тест.
6. Два уровня: каждый подкластер целиком в своём кластере; id подкластеров наследуются так же, как id
   кластеров — тесты.
7. Масштаб: на трёх уровнях видно то, что в таблице «Показ на графе» — тест отрисовки; снимки «далеко»,
   «средне», «близко» в 2D и 3D на сиде плюс импорт — в `docs/agents/MANUAL_TEST_FEEDBACK.md`.
8. Команда принудительного пересчёта работает и описана в `COMMANDS.md`.
9. Время пересчёта на 1 000 заметках — замер; предел — в конфиге по итогам замера.
10. Документы: `ARCHITECTURE_SUMMARY.md`, API.
