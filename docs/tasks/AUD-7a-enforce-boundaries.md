# AUD-7a. Сделать границы слоёв и порог покрытия проверяемыми

Постановка для Devin. Источник: [`../EXTERNAL_AUDIT_2026-09.md`](../EXTERNAL_AUDIT_2026-09.md), находки A-1-AUD и T-2. Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

Ставит Claude Code, реализует Devin, проверяет Claude Code.

**Очерёдность:** можно брать сразу. С AUD-5 и с треком P11 не пересекается.

**Это первая половина AUD-7.** Вторая — [`AUD-7b`](AUD-7b-lint-tests-and-coverage-denominator.md), она требует решений владельца и вскрывает неизвестный объём. Здесь только то, что заведомо пройдёт на текущем коде.

## Проблема

Проект держит три правила, которые записаны в норме, реально соблюдаются — и не проверяются ничем.

1. **Чистая архитектура на бэкенде.** `.windsurfrules` требует: домен без `*gorm.DB`, `gin.Context`, Redis и Mongo; внутренние слои не знают о внешних. Соблюдается.
2. **Границы FSD на фронтенде.** `.windsurfrules:136-146` перечисляет, кто кого может импортировать, и помечает это как MANDATORY. Соблюдается.
3. **Порог покрытия бэкенда.** `.windsurfrules:186` обещает «цель 70%, минимум 60%». Фактически около 67%, то есть по существу правда.

Ни одно из трёх не имеет машинной проверки: в `backend/.golangci.yml` нет `depguard`, в `frontend/eslint.config.js` нет правил импортов, в CI `go test` идёт без `-coverprofile` и без гейта.

Разница между «правило соблюдается» и «правило невозможно нарушить незаметно» здесь принципиальна. За эту неделю мы дважды видели, чем кончается первое: плотность тумана откатилась при регенерации конфига и никто не заметил, пока не покраснели чужие тесты; исправление по находке 6 в A-3 не покрыто регрессией, и откат проходит зелёным.

## Почему это дёшево

Измерено 2026-09-06, перед постановкой:

| Проверка | Результат |
|---|---|
| `internal/domain`, `internal/application` — импорты фреймворков и обратные зависимости | **0 нарушений** |
| `shared/` импортирует `entities`/`features`/`widgets`/`components` | **0 файлов** |
| `entities/` импортирует что-то кроме `shared` | **0 файлов** |
| `components/atoms/` импортирует `molecules`/`organisms`/выше | **0 файлов** |
| `features/` импортирует `widgets` | **0 файлов** |

То есть правила включатся и **пройдут сразу**. Задача не про починку кода, а про установку сторожа на уже чистое место. Ожидаемый дифф — три конфигурационных файла плюс шаг CI.

Карта самих границ — в скилле [`kg-layers`](../../.devin/skills/kg-layers/SKILL.md); дублировать её здесь не нужно, но правила `depguard` и ESLint обязаны ей соответствовать.

## Что сделать

### 1. `depguard` на границы Go

`backend/.golangci.yml`, добавить `depguard` в список линтеров и описать списки.

Минимально необходимое:

- `internal/domain/**` — запретить `gorm.io/**`, `github.com/gin-gonic/**`, `github.com/redis/**`, `go.mongodb.org/**`, `github.com/hibiken/asynq`.
- `internal/domain/**` и `internal/application/**` — запретить импорт `knowledge-graph/internal/infrastructure/**` и `knowledge-graph/internal/interfaces/**`.
- `internal/application/**` — запретить те же фреймворки, что и домену.

Сообщение об отказе должно называть правило, а не только пакет: разработчик, увидевший отказ, обязан понять, какую границу он пересёк.

**Не трогать** `run: tests: false` — это предмет AUD-7b.

### 2. Правила импортов FSD в ESLint

`frontend/eslint.config.js`. Достаточно `no-restricted-imports` с `patterns` по слоям — отдельный плагин границ подключать не требуется, зависимостей и так много.

Покрыть переходы из `.windsurfrules:136-146`:

- `src/shared/**` — запретить `$entities`, `$features`, `$widgets`, `$components` и относительные пути в те же каталоги.
- `src/entities/**` — разрешить только `$shared`.
- `src/components/atoms/**` — запретить `molecules`, `organisms`, `$features`, `$widgets`.
- `src/components/molecules/**` — запретить `organisms`, `$features`, `$widgets`.
- `src/features/**` — запретить `$widgets`.

`src/routes/**` не ограничивать: по норме ему можно всё.

Относительные пути учесть обязательно — иначе правило обходится одним `../../widgets/...`.

### 3. Гейт покрытия бэкенда в CI

`.github/workflows/_core-checks.yml`, джоба `backend-checks`.

Заменить прогон на вариант с профилем и добавить шаг проверки порога: посчитать `total` из `go tool cover -func` и упасть, если он ниже установленного значения.

**Порог не выдумывать.** Сначала измерить фактическое покрытие на текущем коде, затем поставить порог **на два процентных пункта ниже** измеренного и записать это число в `.windsurfrules` вместо нынешней формулировки «enforced min 60%». Запас в два пункта нужен, чтобы гейт не падал от нормального дрейфа; поднимать его — отдельная работа, не эта.

Профиль писать во временный файл и удалять после — `coverage.out` уже в `.gitignore`, но мусор в рабочем дереве после CI не нужен.

## Ограничения

- **Правила не меняются, меняется только их проверяемость.** Если `depguard` или ESLint покажут нарушение — это находка, о которой надо сообщить, а не повод ослабить правило или переписать код в обход.
- Не трогать `run: tests: false` и знаменатель покрытия фронтенда — это AUD-7b.
- Не подключать `eslint-plugin-boundaries` или иные новые зависимости без необходимости: `no-restricted-imports` входит в ESLint.
- Не менять пороги покрытия фронтенда в `vitest.config.ts`.
- Не трогать `.claude/`, `docs/tasks/AUD-*`, `docs/EXTERNAL_AUDIT_2026-09.md`.
- Personal-стек не поднимать.

## Критерии приёмки

1. `golangci-lint run` на текущем коде проходит с включённым `depguard` — без единого нарушения.
2. `npm run lint` на текущем коде проходит с новыми правилами импортов — без единого нарушения.
3. Гейт покрытия проходит на текущем коде; порог записан в `.windsurfrules` и совпадает с тем, что стоит в CI.
4. **Каждая из трёх проверок доказанно ловит нарушение.** Это главный критерий, см. ниже.
5. `go test ./...`, `go vet ./...`, `npm run test:unit`, `npm run check` — без новых замечаний.

### Про критерий 4

Сторож, который никогда не срабатывал, ничем не отличается от отсутствующего. Поэтому каждую проверку нужно проверить мутацией — временно нарушить и убедиться, что стало красным:

- в файл из `internal/domain` добавить импорт `gorm.io/gorm` → `golangci-lint` обязан отказать с внятным сообщением;
- в файл из `src/shared` добавить импорт из `$widgets` → `npm run lint` обязан отказать;
- временно поднять порог покрытия выше фактического → шаг CI обязан упасть.

После каждой пробы вернуть состояние через `git checkout`.

## Что приложить к результату

Вывод трёх мутаций — по одному фрагменту на каждую, с текстом отказа. Плюс измеренное покрытие бэкенда и выбранный порог.

Без этого приёмки не будет: за эту неделю дважды выяснялось, что зелёный прогон ничего не доказывает, пока не увидишь его красным.
