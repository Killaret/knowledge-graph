# AUTO-1. Убрать человека из середины: автопуш и запуск Devin по событию

Постановка для Devin. Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

Ставит Claude Code, реализует Devin, проверяет Claude Code.

**Очерёдность:** не блокирует PUB-1..3, можно брать параллельно.

## Зачем

Сегодня передача работы между агентами держится на человеке: он запускает сессию, он делает `push`. Из-за этого моё ревью доезжает до Devin только когда владелец вернулся к компьютеру, и наоборот.

Решение владельца: **автопуш плюс запуск Devin по событию `push`.** Полную петлю по расписанию пока не делаем.

## Что не делаем и почему

**Почту, вебсокет и отдельный API как канал связи — не заводим.** Транспорт уже есть: git и [`../AI_HANDOFF.md`](../AI_HANDOFF.md). У него есть история, ревью и откат, чего нет ни у почты, ни у сокета. Второй канал означал бы второй источник правды — ровно та болезнь, которую мы за неделю лечили трижды: сгенерированный конфиг против источника, промпты против правил, доска против документации.

**Границу тоже стоит назвать прямо.** Автоматизация несёт исполнение и ревью, но не решения. Сегодняшняя сессия закрыла восемь задач без владельца и упёрлась в четыре вопроса, на которые ни один агент не имел права ответить. Петля обязана останавливаться на разделе «На человеке», а не пытаться его обойти.

## Что сделать

### 1. Автопуш в конце сессии

В обе копии `/kg-work` — мою в `.claude/commands/` и твою в `.devin/skills/` — добавить: после коммита своей работы выполнить `git push origin ai-agents`.

Условия, которые должны быть записаны рядом с правилом:

- пушить **только** `ai-agents`, никогда не `main`;
- пушить только собственные коммиты; если в дереве есть чужие незакоммиченные правки — не трогать их и сказать об этом;
- при отказе push из-за расхождения — `git pull --rebase`, и если конфликт не тривиальный, остановиться и написать на доску, а не разрешать его наугад.

Своё ограничение я себе не пишу — обе копии правишь ты.

### 2. Запуск Devin по событию push

Новый workflow, например `.github/workflows/agent-trigger.yml`: на `push` в `ai-agents` создать сессию Devin с неизменным промптом `прочитай docs/AI_HANDOFF.md и делай своё`.

Три защиты, без которых заводить нельзя:

**От самозапуска.** Твой собственный push обязан не триггерить новую сессию — иначе получится вечный цикл. Отсекай по автору коммита или по актору события; выбери надёжный признак и объясни выбор.

**От холостого хода.** Триггерить только если в push изменился `docs/AI_HANDOFF.md`. Прочие коммиты доски не двигают, и будить по ним некого.

**От бесконечности.** Ограничение на число автозапусков в сутки. Число выбери сам и запиши в workflow с обоснованием; при исчерпании — не запускать и оставить след в логе.

Ключ `DEVIN_API_KEY` кладётся в секреты репозитория — это действие владельца, отдельной строкой на доску.

### 3. Что остаётся за человеком

Записать в [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md): запуск Claude Code, слияние в `main`, и всё, что попало в раздел «На человеке». Автоматизация этих трёх вещей не касается.

## Ограничения

- Не пушить в `main` ни при каких условиях.
- Не разрешать конфликты слияния автоматически.
- Не запускать Devin, если единственные открытые строки доски — в разделе «На человеке».
- Personal-стек не трогать.

## Критерии приёмки

1. Правило автопуша присутствует в обеих копиях `/kg-work` дословно одинаково.
2. Push в `ai-agents` с изменением доски создаёт сессию Devin.
3. **Push, сделанный самим Devin, новую сессию не создаёт.** Это главный критерий: проверить реальным push, а не чтением условия.
4. Push без изменений `docs/AI_HANDOFF.md` сессию не создаёт.
5. Ограничение на число запусков срабатывает — проверить, временно поставив предел в единицу.
6. Отсутствие секрета `DEVIN_API_KEY` не роняет прочие джобы: workflow пропускается с внятным сообщением.

## Что приложить к результату

Ссылки на прогоны workflow по критериям 2, 3 и 4 — три разных исхода на трёх реальных push. Условие, которое «выглядит правильно», здесь не считается: цикл из двух агентов, запускающих друг друга, — самая дорогая ошибка в этой задаче.
