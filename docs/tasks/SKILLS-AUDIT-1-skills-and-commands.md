## Что сделать — Claude Code

### 1. Ревью каждого скилла

По пяти правилам раздела «Как писать скиллы» протокола. Каждое правило — вердикт с доказательством,
как в SPEC-AUDIT-1:

- **якоря:** каждый файл, команда, порт и значение конфигурации существуют на `origin/ai-agents`, и
  каждая команда скилла выполнена хотя бы раз;
- **источники** перечислены в шапке и до сих пор существуют;
- **жанр:** скилл не повторяет норму из `.windsurfrules` и не стал разовой задачей;
- **описание — триггер:** в нём есть слова, которыми человек называет задачу;
- **размер:** до ~500 строк.

Отдельно — **нужен ли скилл вообще**. Протокол требует держать число скиллов малым. Скилл, ловушка
которого устранена в коде, удаляется или сливается с другим. Удаление — только с согласия владельца.

Правки, которые не требуют решения владельца (якорь, источник, описание), Claude Code вносит сам.
Удаление скилла, слияние и перенос текста в норму — в разборе, на решение владельца.

### 2. Команда на каждый скилл — у обоих агентов

- **Devin:** `user` в `triggers` у всех проектных скиллов. Исключение — `knowledge-graph`: это
  правило по умолчанию, а не команда. Если поиск зависит от списка в `.devin/config.yml`, туда же
  добавить все скиллы. Ответ искать по документации Devin CLI и проверять исполнением.
- **Claude Code:** у каждого скилла есть указатель в `.claude/skills/`, описание совпадает с
  каноническим байт в байт. `kg-work` остаётся командой в `.claude/commands/`.
- **Документы:** раздел «Слэш-команды проекта» в `CLAUDE.md` перечисляет все команды. Фразу
  «Единственная проектная команда» в `kg-work.md` убрать или переписать. Список скиллов в
  `.devin/skills/knowledge-graph/SKILL.md` («Project Skills») и в `CLAUDE.md` совпадает с каталогом.

### 3. Сторож расхождений

Описания уже разошлись, разойдутся и снова. Нужна проверка в CI, которая краснеет, если:

- в `.devin/skills/` есть скилл без указателя в `.claude/skills/` или наоборот;
- описание указателя не совпадает с каноническим;
- у проектного скилла (кроме `knowledge-graph`) нет `user` в `triggers`.

Это код, поэтому сторож делает Devin по отдельной строке. Claude Code пишет её в разборе, если
владелец согласен.

### 4. Проверка вызова

На стороне Claude Code каждый `/kg-*` вызывается в сессии из `D:\knowledge-graph-review`, и скилл
загружает канонический текст. Свидетельство — список команд сессии и первая строка ответа на каждую.

1. Ревью правок Claude Code по тем же пяти правилам. Якоря проверять исполнением, а не по описанию.
2. Вызвать каждый `/kg-*` в сессии из `D:\knowledge-graph-ai-agents` после синхронизации с
   `origin/ai-agents` и перезапуска: Devin читает список скиллов при старте. Свидетельство — вывод.
3. Вердикт — в `docs/tasks/SKILLS-AUDIT-1-review-findings.md`.

## Готово, когда

- по каждому скиллу есть вердикт по пяти правилам с доказательством, а решения владельца записаны;
- человек вызывает по имени каждый проектный скилл у обоих агентов: у Claude Code это проверено
  Claude Code, у Devin — Devin;
- описания в двух копиях совпадают, документы перечисляют все команды;
- Devin принял.

## Вне задачи

- `kg-board`, сводка доски и хук старта Devin, который читает доску с диска, — это KG-BOARD-1. Если
  `kg-board` появится раньше, ревью охватывает и его.
- Глобальные скиллы аккаунта (`anthropic-skills:*`, в том числе `ap-*` проекта Avanpost) — не
  репозиторий.
- Пока `ai-agents` не слита в `main`, сессии в `D:\knowledge-graph` не видят новых скиллов. Слияние
  делает владелец (PR #123).
