**Вердикт: принято.** Класс закрыт в корне, а не заплаткой на одном ключе, и у решения есть
сторож от расхождения — это лучшее, что можно было сделать с этим дефектом.

## Что было и что стало

`getJSONFloatOrDefault` и соседи отдавали значение из JSON всегда, когда файл загружен, а
отсутствующий ключ разбирался в ноль. Файл вшит в образ (`backend/Dockerfile:24`), значит
Go-умолчания были мертвы во всех контейнерах: цепочка «env → JSON → умолчание» на деле была
«env → JSON → ноль».

Теперь обе точки загрузки (одиночный файл и слияние частей) разбирают JSON **поверх структуры,
засеянной умолчаниями** (`defaultJSONConfig()`): отсутствующий ключ сохраняет умолчание,
явный `0`/`false`/`""` применяется, частичная карта дополняет засеянные записи, а не заменяет
их целиком.

## Проверено исполнением

| Что | Результат |
|---|---|
| `go test ./internal/config/` | зелёный; `go build ./...` — зелёный |
| `TestDefaultJSONConfig_MatchesCallSiteDefaults` — сторож расхождения: `resolveConfig(nil)` и `resolveConfig(defaultJSONConfig())` сравниваются целиком (`DeepEqual` по всей `Config`) | зелёный |
| **Мутация**: убрана одна засеянная строка (`cfg.Backend.Search.FallbackToILike = true`) | **FAIL** — «seeded JSONConfig must reproduce every built-in default — a missing field means defaultJSONConfig drifted from the call sites». Сторож видит именно то, ради чего написан |
| `TestDefaultJSONConfig_ExplicitValuesWin` | явные `false`/`0` в файле побеждают засеянное `true`; отсутствующая запись карты (`links_create`) сохраняет умолчание 50, заданная (`notes_create`) — 5 |
| Порог автосвязей | `<= 0 → 0.6` остался как второй рубеж; `TestGammaLinkMinScore_MissingJSONKey` зелёный, мутация `if false` — красная (см. разбор LINKS-1) |

Сторож расхождения — главное здесь: умолчание, добавленное в точке вызова и забытое в
`defaultJSONConfig()`, уронит тест, а не тихо станет нулём в проде. Без него исправление
продержалось бы до следующей новой настройки.

## Мелочи

1. `maps.Clone`/`slices.Clone` на картах и срезах засеяны правильно (иначе `json.Unmarshal`
   мутировал бы пакетные умолчания через загруженный конфиг) — но самого этого свойства тест
   не проверяет: мутация «убрать `Clone`» останется зелёной, пока в одном процессе не загрузят
   два разных конфига. Дёшево добавить, если руки дойдут.
2. Абзац про `getJSONFloatOrDefault` в `docs/operations/CONFIGURATION_{EN,RU}.md` (внесён
   DOC-AUDIT-1) теперь описывает прежнее поведение — «новые ключи обязательно добавлять в
   `config/*.json`, иначе ноль». Его надо переписать под новое: ключ можно опустить, умолчание
   применится. Пока не переписан — читатель уносит устаревшее правило.

## Принято без замечаний

- `resolveConfig` выделен из `Load` ради тестируемости — обе ветки сравниваются напрямую.
- Исправлены обе точки загрузки, а не только та, что попалась в LINKS-1.
- Поведение стендов не изменилось: `config/backend.json` и `knowledge-graph.config.json` и так
  содержат все ключи; исправление страхует конфиги, которых в репозитории нет.
