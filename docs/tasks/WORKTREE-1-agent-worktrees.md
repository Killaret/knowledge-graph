# WORKTREE-1. Каноническая карта worktree и правила синхронизации

Постановка: Devin, 2026-09-24. Исполнитель: Claude Code.

## Контекст

Правила нескольких worktree сейчас разнесены по `AI_AGENT_PROTOCOL.md`,
`AI_AGENT_SETUP.md`, `kg-work`, постановкам AUTHOR-2 и TEST-LOCK-1. Нет одного
документа, который отвечает: какой worktree чей, на какой ветке он должен быть,
что проверять на старте, что делать при отставании remote и кто синхронизирует
`main`/`ai-agents`.

Фактическое состояние на 2026-09-24:

- `D:\knowledge-graph` — `main`;
- `D:\knowledge-graph-ai-agents` — `ai-agents`;
- `D:\knowledge-graph-review` — detached checkout.

## Сделать

Создать канонический `docs/agents/WORKTREES.md`:

1. Таблица фактических worktree: путь, владелец, назначение, ожидаемая ветка.
2. Правила владения `main` и `ai-agents`.
3. Startup freshness checks: clean tree, fetch, status/branch, worktree list,
   read marker HEAD.
4. Что делать при `behind`/`diverged` remote: остановиться и сообщить, не делать
   молчаливый pull/rebase/merge.
5. Merge policy: `main ↔ ai-agents` только человеком или по явному поручению;
   конфликт документов доски решается в пользу `ai-agents`.
6. Safety: перед действием, способным убить чужой прогон, проверять процесс и
   ownership ресурсов.
7. Открытый вопрос: какая рабочая форма review-клона Claude правильная —
   detached `origin/ai-agents` или именованная ветка. Предложить вариант и
   обосновать его фактами текущего workflow.

Обновить `AI_AGENT_SETUP.md` и `AI_AGENT_PROTOCOL.md` только указателями на
канонический документ, без дублирования нормы.

## Не входит

- реализация `check-agent-worktree.mjs`;
- автоматический pull/rebase/merge;
- изменение прав удаления Personal/dev/test данных;
- изменение ограничений другого агента.

## Критерии приёмки

1. `WORKTREES.md` соответствует фактическому `git worktree list` на машине.
2. Каждая норма имеет один канонический источник; старые документы ссылаются,
   а не копируют.
3. Из документа однозначно следует:
   - кто работает в `main`;
   - кто работает в `ai-agents`;
   - что делать при `behind`;
   - кто делает merge;
   - что делать при конфликте board/docs.
4. Все команды из документа реально выполнены на текущей машине.
5. Спорные решения явно названы вопросами владельца, а не записаны как уже
   принятые.
