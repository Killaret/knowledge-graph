# IMP-8. Массовый импорт: описание «что это» для упавших и стабовых ссылок

**Статус: бэклог.** Зафиксировано по просьбе владельца 2026-09-18, реализация не начата.

## Контекст

IMP-7 добавил опцию «только заголовок» для error-строк превью. При ручном разборе `bookmarks_18.09.2026.html` выяснилось, что одного заголовка мало: владельцу нужны заметки вида «что это за ресурс + ссылка». Devin вручную создал 16 таких заметок (10 пустых + 6 стабовых элементов очереди): Coursera-курсы по слагу URL, «крипто-обменник», «онлайн-школа», «дизайн-файл Figma» и т.п.

Формулировка владельца: «при импорте надо дать команду — оставить заголовок, написать что это, каким-то образом извлечь что это, всё записать».

## Требования

1. **Поле описания у error-строк.** При включённом «только заголовок» (IMP-7) показывать текстовое поле «что это» — введённое описание уходит в `text` элемента импорта вместо пустоты. Бэкенд менять не нужно: `importItem.text` уже принимает произвольный текст, `ProcessImportTask` пишет его в контент.
2. **Подсветка стабов.** Элементы, прошедшие фетч, но с тривиальным текстом (< ~200 символов после заголовка — стабы SPA/логинов/пейволов), помечать отдельным бейджем и давать ту же опцию описания. Сейчас они визуально неотличимы от нормальных.
3. **Автоподсказка описания (опционально, вторым шагом).** Источники в порядке приоритета:
   - слаг и путь URL (`/learn/software-processes/` → «Software Processes»);
   - заголовок закладки из файла (он уже есть в `title`);
   - meta `description`/`og:description`, если частичный ответ всё же пришёл;
   - позже — NLP/LLM-генерация по домену и заголовку.
4. **Дедуп сохранить.** Ручные/описанные заметки не должны конфликтовать с очередными элементами — `loadExistingSourceMap` уже дедупит по нормализованному `source_url`, поведение оставить.

## Замечания к реализации

- Точка входа: `frontend/src/routes/import/bookmarks/+page.svelte` (строка превью), хелперы `shared/utils/import-preview-items.ts`.
- «Стаб» — эвристика на фронте по длине `text` из ответа превью; не путать с error-строками.
- Связано: IMP-7 (title-only opt-in), IMP-6 (batch-пайплайн), NOTE-QUALITY-1 (критерий качества заметки — стабы пересекаются с ним).

## Проверено вручную (2026-09-18)

16 заметок созданы через `/api/v1/import/bookmarklet` с title+описание+URL; очередные элементы с теми же `source_url` отвалились дедупом при запуске воркера. Пустых/стабовых ссылок из файла не осталось.

## Уроки ручной нормализации базы (116 → 113 заметок, 2026-09-18)

Полный разбор базы владельца выявил классы дефектов, которые должна покрывать реализация:

1. **Логин-стены.** Часть ссылок фетчит страницу входа (hexlet уроки, habr career, bingx) — контент = форма логина. Признаки: title «Вход…», короткий шаблонный текст, ключевые слова «email/пароль». Действие при импорте: детектить и сразу предлагать title-only + описание.
2. **Семантические дубли.** Нормализация сохраняет query-параметры — `utm_*/referral/cf_chl_tk` делают один ресурс разными URL (Stepik-курс ×2, Glassdoor ×2). Дедупу нужен санитайзер трекинг-параметров.
3. **Одинаковый фетч на разные URL.** Три разных урока Хекслет за логином вернули одну страницу каталога — три заметки с идентичным контентом. Дедуп по контенту (сигнатура/хэш), не только по URL.
4. **Бойлерплейт-контент.** Animego/senkuro страницы несут метаданные тайтла (рейтинг, жанры, статус, число серий) среди навигационного мусора — качество извлечения можно улучшить шаблонами по домену.
5. **Папки закладок.** В экспорте Chrome есть структура папок (`<DT><H3>`) — группа «английский/словари» точно предсказывает тему ссылок. При импорте стоит сохранять путь папки в `metadata.import.folder_path` и использовать как подсказку описания/типа. **Важно:** папки — это ground truth для валидации будущей кластеризации (сравнить «пользовательская группа» vs «вычисленный кластер»), а не повод создавать синтетические хаб-заметки. Решение владельца 2026-09-18: хабы-заглушки не создавать — кластеризация заменяет их виртуальной группировкой без физического узла, а фальшивый узел исказил бы замеры MODEL-1.
6. **Типы.** Импорт ставит `asteroid` всем; у владельца типы несут семантику масштаба (аниме-серии — star, ресурсы по теме — moon, инструменты — satellite, курсы/книги «на потом» — planet). Предложение типа по домену/папке — часть нормализации.
7. **Переобогащение.** `PUT /notes/:id` сам ставит keywords+embedding+linkweight — ручные правки контента не ломают индекс. Смена `type` переобогащения не требует (embedding строится по title+content).
8. **Ручные связи.** Ставить только с объективным основанием: одна специализация→курсы, один курс→уроки, часть 1→часть 2, страницы одного сервиса, одно произведение (манга↔аниме). Связи «лежали в одной папке» НЕ ставить руками — это предрешает результат кластеризации.
