## Что готово — проверено

[`gamma_link_generator.go`](../../backend/internal/application/recommendation/gamma_link_generator.go):
класс, конструктор, `GenerateForNote` / `GenerateForNotes`, тесты. Обе зависимости реализованы
в инфраструктуре: `EmbeddingRepository.FindSimilarNotes` (pgvector, `1 - (e1 <=> e2)`, сортировка
по убыванию, `LIMIT`) и `BatchLinkRepository.FindBySourceIDs`. Домен знает тип связи:
`link.NewGammaLink` ставит `source_type = gamma`. Фронтенд его отличает:
[`LinkTooltip.svelte:83`](../../frontend/src/features/graph-ui/LinkTooltip.svelte) — `{#if sourceType === "gamma"}`.
Ничего из этого писать не надо.

Не готово ровно четыре вещи, и одна из них — не подключение, а дыра в замысле.

## 1. Порог близости — его нет, и без него подключать нельзя

`FindSimilarNotes` возвращает **top-N по близости без нижней границы**, генератор отбрасывает
только `score <= 0`. Значит **каждая** заметка с эмбеддингом получит две связи с двумя
«наименее чужими» заметками библиотеки — какими бы далёкими они ни были. Заметка про рецепт
в библиотеке про базы данных свяжется с двумя заметками про базы данных, с весом 0.3, и
это будет выглядеть как связь.

Нужен порог `GAMMA_LINK_MIN_SCORE` в конфигурации (та же тройка: env → `knowledge-graph.config.json`
→ умолчание в `config.go`), ниже которого связь не создаётся. Умолчание — **0.6** по косинусу;
это осторожная цифра для paraphrase-модели, **откалибровать на тест-сиде**: распределение
score для top-2 по всем заметкам сида, гистограмма в файл находок. После MODEL-1, если модель
сменится, порог пересматривается вместе с ней — у другой модели другое распределение.

## 2. Точка вызова и события

- Вызов `GenerateForNote(noteID)` — в воркере, **после успешного** `HandleComputeEmbedding`
  той же заметки, а не по расписанию и не при создании (эмбеддинга ещё нет).
- На каждую созданную связь — `PublishLinkCreated`: graph-service слушает `LinkCreated` и
  обновляет `note_links_closure` ([`pubsub.go:165`](../../services/graph-service/internal/subscriber/pubsub.go));
  без события представление не узнает о связи, и рекомендации её не увидят. Генератор сам
  не публикует — публикует вызывающий код.
- После генерации — `RefreshRecommendations` для источника **и для каждой цели**: у цели
  появился входящий сосед.

## 3. Пересчёт при смене модели

Автосвязи считаются по модели. После MODEL-1, если модель сменится, все связи с
`source_type = gamma` **устаревают**. Нужна команда `gamma-links-regenerate` (рядом с
`embed-recompute`): удалить все gamma-связи, для каждой заметки с эмбеддингом текущей модели
вызвать `GenerateForNotes` пачками, опубликовать события. `--dry-run` печатает, сколько
удалит и сколько создаст. Ручные связи не трогать — фильтр по `source_type`, и это
проверяется тестом.

## 4. Степень и представление

Исходящая степень — **2**, как написано в коде и в комментарии про взрыв `note_links_closure`.
Поднимать без замера времени `REFRESH MATERIALIZED VIEW CONCURRENTLY` на сиде — нельзя.
Замерить время обновления представления до и после генерации на всём сиде и приложить.

## Тесты

**Юнит:**
- порог: три кандидата со score 0.9 / 0.65 / 0.4 при пороге 0.6 → две связи, третьей нет;
- степень: пять кандидатов выше порога → ровно две связи;
- идемпотентность: повторный вызов на той же заметке не создаёт дублей;
- ручная связь на ту же цель уже есть → gamma-связь не создаётся (уже в тестах, оставить);
- `gamma-links-regenerate` удаляет только `source_type = gamma`.

**Интеграция:** заметка с эмбеддингом → `HandleComputeEmbedding` → в `links` появились
≤ 2 строки с `source_type = gamma`, в Redis опубликовано столько же `LinkCreated`.

**Adversarial:**
- заметка без эмбеддинга → ноль связей и ноль ошибок;
- две заметки с одинаковым эмбеддингом (дубликат) → score 1.0; связь создаётся — и это
  **сигнал дубликата** для NOTE-QUALITY-1, записать в файл находок;
- заметка, чьи два ближайших соседа — она сама (score 1.0) и её дубликат → степень
  не съедена самой заметкой (`s.NoteID == sourceID` уже отбрасывается — проверить тестом);
- удаление заметки-цели → gamma-связь ушла каскадом (`ON DELETE CASCADE`), closure обновилось.

**Мутации:**
1. Убрать проверку порога → тест «0.4 не проходит» краснеет.
2. Убрать `PublishLinkCreated` → интеграционный тест по Redis краснеет.
3. Убрать фильтр `source_type` в regenerate → тест «ручные не трогает» краснеет.

## Критерии приёмки

1. На тест-сиде после полного прогона у заметок есть gamma-связи, число — в файле находок,
   вместе с гистограммой score и выбранным порогом.
2. Три мутации краснеют, вывод приложен.
3. Время `REFRESH MATERIALIZED VIEW` до и после — приложено.
4. В графе на стенде gamma-связи отличимы визуально (существующая ветка в `LinkTooltip`).
5. `gamma-links-regenerate --dry-run` работает; полный прогон на сиде идемпотентен.
6. `check-all` зелёный; `docs/ARCHITECTURE_SUMMARY.md` описывает автосвязи и порог.

## Ограничения

- Personal-стек не трогать; там генерацию запускает владелец после MODEL-1.
- Степень 2 не поднимать без замера (п. 4).
- Порог — настройка, не константа в коде.
- Не подменять этим RECO-1: автосвязи кормят α-компонент, формулу они не чинят.
