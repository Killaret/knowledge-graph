# BOARD-2. Политика размера доски и архивирования в бэклог

Доска `docs/AI_HANDOFF.md` растёт: сейчас ~40 строк в трёх разделах и 90 постановок в `docs/tasks/`. Нужно решить, сколько задач может одновременно висеть на доске, при каком объёме и/или возрасте строки их убирать в бэклог, и как это встраивать в существующих сторожей.

## Вопросы для обсуждения

1. **Сколько задач на доске нормально?**
   - Абсолютное число строк? (например, не больше 30–40)
   - Число в каждом разделе (`На Devin`, `На Claude Code`, `На человеке`)?
   - Размер файла? Сейчас порог `check-board-size.mjs` — 120 КБ, но сама доска уже 39.8 КБ.

2. **Когда убирать в бэклог?**
   - Статус `ждёт` + не брались N дней?
   - Нет решения владельца/постановщика N дней?
   - Приоритет понижен и не перешёл в `в работе`?
   - Раздел `На человеке` уже собирает «обсуждается» без решения месяцами.

3. **Что такое бэклог в этом репозитории?**
   - `docs/BACKLOG.md` уже существует — он для планов или для «спящих» задач?
   - Новые файлы `docs/tasks/<id>-backlog.md`?
   - Или просто изменить статус на доске и дать ссылку на `BACKLOG.md`?

4. **Как сделать машинной проверкой?**
   - Дополнить `check-board-size.mjs`?
   - Новый сторож `check-board-rows.mjs`?
   - Проверять возраст `ждёт`-строк по дате в колонке?

5. **Что уже есть?**
   - `BOARD-1` ввёл ретенцию терминальных строк и реплик старше 3 дней.
   - `check-board-size.mjs` проверяет размер `AI_HANDOFF.md`.
   - Сторож не лимитирует количество активных (не терминальных) строк.

## Желаемый исход

- Ясное правило: «больше X строк в разделе Y → переносить в бэклог».
- Место для бэклог-задач и указатель из доски.
- Сторож, который не даёт доске разрастаться дальше.
