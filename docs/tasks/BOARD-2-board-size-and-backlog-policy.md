# BOARD-2. Лимиты доски: в работе, на ревью, бэклог

Постановка: Claude Code, 2026-09-21, по черновику Devin от 2026-09-15 (вопросы черновика и ответы
на них — в конце). Исполнитель сторожа: Devin. Перестройку доски под новые разделы Claude Code
делает сам, в этой же сессии, чтобы сторож принимался на настоящей доске, а не на выдуманной.

**Решение владельца (2026-09-21, BOARD-2):** «лимиты нужны для доски, это важно крайне» —
высший приоритет среди задач обвязки. Цифры — из его слов 2026-09-17: «пять задач в работе,
остальные должны быть в бэклоге», «на Devin — три».

## Почему доска без лимитов — не доска

Снимок 2026-09-21, до перестройки: в разделе «На Devin» 38 строк. Из них 22 терминальные
(ждут ретенции), одна `на ревью`, одна заблокирована, одна ждёт Devin — и **двенадцать**
в статусах «обсуждается», «ждёт решения владельца», «черновик», «новая», «бэклог», «решения
зафиксированы». Статуса `в работе` нет ни у одной строки, хотя Devin в этот момент работал:
строка появляется на доске уже как `на ревью`. То есть доска не отвечает на единственный
вопрос, ради которого существует — «что сейчас делается и чья очередь», — а владелец задаёт
его в чате (14.09: «Что сейчас в работе? На тебе? В каком статусе?»).

Порог размера (120 КБ, решение 36) ограничивает байты, не внимание. Лимит нужен на число
одновременно открытых дел, а всё, что не делается сейчас, должно лежать отдельно и не мешать.

## Устройство

### Разделы

| Раздел | Что в нём лежит | Лимит |
|---|---|---|
| `## На Devin` | только активное: `в работе`, `на ревью`, `отклонено` (= доработка), терминальные до ретенции | `в работе` + `отклонено` ≤ **3** |
| `## На Claude Code` | то же для Claude Code (постановки в работе, ревью в работе) | `в работе` + `отклонено` ≤ **3** |
| вся доска | очередь на ревью | `на ревью` ≤ **5** |
| `## На человеке` | только **блокирующие** решения: без них чья-то работа стоит. Каждая строка — вопрос, рекомендация агента, что заблокировано | мягкий: > 7 — предупреждение сторожа, не ошибка; владельцу приказывать нельзя, но видеть перегруз он должен |
| `## Бэклог` | всё остальное: постановки без приоритета, обсуждения, «ждёт X», черновики, отложенное. Одна строка на задачу, ≤ 500 байт, **порядок = приоритет**: верхняя строка — следующая, которую берут | по числу строк — нет; по байтам на строку — 500 |
| `## Обмен репликами`, `## Архив` | как сейчас | ретенция 3 дня (BOARD-1) |

### Словарь статусов

Закрытый список — первое жирное слово в колонке «Статус»:

`в работе` · `на ревью` · `отклонено` · `принято` · `отменено` · `бэклог` · `решает владелец`

Всё, что сегодня называется «обсуждается», «ждёт», «новая», «черновик», «думает владелец»,
«ждёт Devin», «решения зафиксированы» — либо `бэклог` с пояснением после тире («бэклог — ждёт
MODEL-1»), либо `решает владелец` в разделе «На человеке», либо `принято`, если делать больше
нечего. Сторож отказывает на слове вне словаря и называет строку.

### Правила движения

1. **Взял задачу — поставил `в работе`.** До первого коммита с кодом — коммит доски с одной
   изменённой строкой (статус, дата). Без этого лимит `в работе` — фикция: считать нечего.
2. **Очередь на ревью полна (5) — новое не берётся.** Исполнитель заканчивает начатое и ждёт;
   ревьюер по правилу `/kg-work` и так уходит в режим ревью первым делом. Лимит делает ревью
   ограничением, а не пожеланием — как «кто пишет — тот не проверяет».
3. **Из бэклога берут сверху.** Переставить строку выше — значит поднять приоритет; это делает
   владелец или Claude Code в постановке, не исполнитель.
4. **«На человеке» — только то, что блокирует.** Вопрос, который ничего не останавливает, идёт
   в бэклог со статусом `бэклог — ждёт владельца`. Строка старше 14 дней без решения тоже
   уходит в бэклог: вопрос остаётся в файле постановки, доска его не носит.
5. **Терминальные строки** живут три дня (BOARD-1) и уходят — в журнале и истории git след есть.

предупреждением: число — решение владельца, агент его не двигает. Фаза `check-all` (docs) и
CI-джоба docs, как у сторожа размера.

## Слияния и концы строк — два источника потерь, замеченных за месяц

- **Доска берётся из `ai-agents`.** `docs/AI_HANDOFF.md`, `docs/AI_LOG.md`, `docs/DECISIONS.md`,
  `docs/tasks/**` живут в `ai-agents`; при слиянии `main → ai-agents` конфликт в них решается
  в пользу `ai-agents` (`--ours`), при `ai-agents → main` — тоже в пользу `ai-agents`
  (`--theirs`). После любого слияния до пуша: `check-decisions`, `check-tasks-index`,
  `check-board-limits` зелёные. Записать в `docs/AI_AGENT_PROTOCOL.md`. Причина: 14.09 и 21.09
  строки доски терялись при слияниях и перезаписи файла редактором (`4897d17` — восстановление).
- **`.gitattributes`.** Сейчас в нём одна строка (`*.sh text eol=lf`); редакторы агентов
  переключают доску и журнал между LF и CRLF, и дифф по одной строке становится диффом на 600
  (`AI_LOG.md` 613 строк в `30f4ce3`, `CONFIGURATION_RU.md` 1747, `README.md` 650 в `dd4b896`).
  Добавить `*.md`, `*.json`, `*.yml`, `*.yaml`, `*.mjs`, `*.js`, `*.ts`, `*.go`, `*.py`, `*.svelte`
  — `text eol=lf`; `*.ps1 text eol=crlf`; отдельным коммитом `git add --renormalize .`, чтобы
  шум истории случился один раз и был подписан.

## Критерии приёмки

1. Доска после перестройки (её делает Claude Code до приёмки сторожа) проходит сторож: вывод
   «Board limits OK: Devin 1/3 в работе, на ревью 1/5, бэклог N строк» — цифры настоящие.
2. Шесть мутаций на фикстурах в `scripts/testing/fixtures/board-limits/` — по одной на правило:
   четвёртая строка `в работе`, шестая `на ревью`, `обсуждается` в разделе Devin, `бэклог` в разделе
   Devin, строка бэклога в 501 байт, восьмая строка «На человеке» (предупреждение, выход 0). Каждая
   красная с текстом, называющим строку. Тесты — `check-board-limits.test.mjs`, как у сторожа
   индекса задач.
3. Мутация на живой доске: перенести одну строку из «Бэклог» в «На Devin» без смены статуса →
   `check-all` красный на фазе docs.
4. `.gitattributes` расширен, `git add --renormalize .` — отдельный коммит; после него
   `git diff --stat` пустой на LF-файлах, а `git ls-files --eol` не показывает `w/crlf` у `*.md`.
5. Протокол (`docs/AI_AGENT_PROTOCOL.md`) и шапка доски («Правила доски») называют лимиты,
   словарь статусов и правило «взял — поставил `в работе`»; `.devin/skills/kg-work/SKILL.md` и
   `.claude/commands/kg-work.md` — то же в одном абзаце. Devin ставит `в работе` начиная со
   следующей взятой задачи — это проверяется первым ревью после приёмки.

## Вопросы черновика (Devin, 2026-09-15) — ответы

1. *Сколько задач на доске нормально?* — Не число строк, а число открытых дел: 3 в работе у
   исполнителя, 5 на ревью по доске. Размер файла остаётся вторым сторожем.
2. *Когда убирать в бэклог?* — Сразу: всё, что не `в работе`/`на ревью`/`отклонено` и не блокирующее
   решение, лежит в бэклоге с момента появления. Возраст важен только для «На человеке» (14 дней).
3. *Что такое бэклог здесь?* — Раздел `## Бэклог` на самой доске, одна строка на задачу.
   `docs/BACKLOG.md` — продуктовый бэклог (что планируется в продукте), его не трогаем; индекс
   `docs/tasks/README.md` берёт статус из любой секции доски, так что задача в бэклоге остаётся
   находимой по идентификатору.
4. *Как сделать машинной проверкой?* — Отдельный сторож, таблица выше.
5. *Что уже есть?* — Ретенция (BOARD-1) и размер (решение 36) остаются как есть.
