# LICENSE-1. Лицензия репозитория

Статус: **решает владелец — первоочередное; обсуждение после скорости GRAPH-LIGHT-1** (слово владельца

## Чего хочет владелец

Своими словами: людям можно пользоваться проектом для себя, но нельзя его продавать; сам владелец
собирается развернуть сервис в облаке; в проект вложено много труда.

## Что есть сейчас

- Репозиторий `Killaret/knowledge-graph` на GitHub **публичный** (`gh repo view`, 2026-09-29).
- В корне лежит `LICENSE` с текстом **MIT**. Файл добавлен коммитом `0f9c040` (2026-09-05, агент) при
  разборе внешнего аудита: README ссылался на `LICENSE` и объявлял MIT с коммита `17696cc`
  (2026-04-28), а самого файла не было.
- Решения владельца о выборе MIT в [`../DECISIONS.md`](../DECISIONS.md) нет.

Следствие, с которого начинается обсуждение: версии, опубликованные под MIT, остаются под MIT у всех,
кто их получил, — их можно использовать и продавать. Новая лицензия действует для версий после смены.

## Варианты на обсуждение

Отправная точка — ответ DeepSeek от 2026-09-29: он советует Business Source License 1.1, называет
также Functional Source License и Commons Clause. Перед обсуждением сверить по первоисточникам и
добавить:

- **BSL 1.1** — код открыт, «производственное» использование разрешено только тем, что перечислено в
  дополнительном разрешении (Additional Use Grant). Без такого разрешения человек не может
  пользоваться проектом для себя всерьёз: ежедневная работа со своими заметками — тоже
  производственное использование. Через срок не больше четырёх лет каждая версия переходит под
  выбранную открытую лицензию.
- **FSL 1.1** — разрешено всё, кроме конкурирующего использования; через два года версия переходит под
  MIT или Apache 2.0.
- **PolyForm Noncommercial** — только некоммерческое использование, без перехода в открытую.
- **Elastic License 2.0** — нельзя предлагать проект третьим лицам как облачный сервис.
- **AGPL 3.0** — открытая лицензия: продавать можно, но изменённый сервис обязан раскрыть свой код;
  вместе с двойным лицензированием оставляет владельцу коммерческую версию.

Ни одна из них, кроме AGPL, не открытая в смысле OSI: проект нельзя будет называть open source.

## Что решить

1. Какая лицензия и с какой версии.
2. Можно ли компаниям ставить проект у себя для внутренней работы.
3. Принимаются ли чужие правки. Если да — нужно соглашение контрибьютора, иначе владелец потеряет
   право сменить лицензию на чужой код.
4. Совместимость с лицензиями зависимостей и моделей. Прямые зависимости трёх сервисов уже сведены в
   [`../LICENSES.md`](../LICENSES.md), сторож `scripts/testing/check-licenses.mjs` (NLP-2) запрещает
   среди них копилефт; транзитивные зависимости и модели эмбеддингов — проверить.
5. Что писать в README, в поле `license` пакетов и в бейдже.

Это не юридическая консультация: выбор с серьёзными деньгами на кону стоит показать юристу.
