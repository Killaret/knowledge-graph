## Блокер: новая дата проходит через ссылку на файл

Проба — временный маркер в конце файла, после прогона — `git checkout`:

| Файл | Строк индекса ссылается | `(2026-10-01, ID)` — новая дата | `(2026-09-26, ID)` — тот же день |
|---|---|---|---|
| `SYNC-1-graph-loading-and-sync-review.md` | 2 — решения 69 и 71 | **Decisions OK** | Decisions OK |
| `NOTE-DELETE-1-soft-delete.md` | 1 — решение 72 | красный: `owner decision (2026-10-01) has no matching row` | Decisions OK |
| `JAVA-HANDOVER-1-chunking-and-text-know-how.md` | 1 — решение 73 | красный | Decisions OK |

Механизм (`scripts/testing/check-decisions.mjs`, `findMatchingRow`):

1. Шаг 1 больше не пропускает занятые строки. Маркеры с одним id и одной датой садятся на первую
   подходящую строку. В SYNC-1 два маркера — решения 69 и 71, оба `(2026-09-26, SYNC-1)`, строки 6 и
   130 файла — оба садятся на строку 69. Строка 71 остаётся свободной.
2. Шаг 2, «сильное совпадение» по ссылке на файл, даты не проверяет. Свободная строка 71 ссылается на
   файл SYNC-1 и достаётся маркеру с новой датой.

Итог: маркер новой даты проходит в любом файле, на который ссылается хотя бы одна свободная строка
индекса. В NOTE-DELETE-1 и JAVA-HANDOVER-1 единственную строку занимает маркер самого файла — там
проба красная.

Тест этого не видит: фикстура `tasks-probe/CHECK-DECISIONS-2-probe.md` — файл, на который не
ссылается ни одна строка индекса, и до шага 2 дело не доходит.

**Масштаб.** Проба по каждому файлу, на который ссылается индекс, на `3f79503`: в конец файла —
маркер `(2026-10-01, <ID файла>)`, прогон сторожа, `git checkout`. Файлов 62, маркер новой даты
**проходит в 22**, среди них SYNC-1, NOTE-QUALITY-1, URL-HEADING-1, UI-DESIGN-1, MODEL-1, DEPLOY-2,
BOARD-1, BOARD-2, BACKUP-2.

**Что нужно:**

- совпадение по ссылке на файл тоже требует даты — или хотя бы не принимает маркер, у которого есть
  общий id со строкой другой даты. Расхождение AUD-2 (маркер 09-07, строка 09-06) чинить в данных:
  выяснить верную дату по истории и поправить маркер или строку, а не ослаблять правило;
- тест на реальном пути: фикстура — файл, на который ссылаются две строки индекса, с их маркерами и
  третьим маркером новой даты. Тест обязан быть красным.

## Мелочь — ограничения, описать в стороже

- **Второе решение в тот же день по той же задаче** проходит без строки (последняя колонка
  таблицы): такой маркер неотличим от цитаты. Отличать можно по тексту маркера — отдельной задачей,
  если владелец сочтёт нужным. Пока достаточно строки в комментарии сторожа.
- **Маркер без даты** (`**Решение владельца (SYNC-1):**`) проходит: `dateCompatible` пропускает
  маркер без даты. Норма требует дату — сторож мог бы на такой маркер ругаться.
