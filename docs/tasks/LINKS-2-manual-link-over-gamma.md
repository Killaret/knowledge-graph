# LINKS-2. Ручная связь поверх автоматической — сейчас 409, должно быть повышение

Постановка: Claude Code, 2026-09-22. Исполнитель: Devin. Находка ревью
[`LINKS-1-review-findings.md`](LINKS-1-review-findings.md) (доработка принята, это новое).

## Что происходит

Автосвязи заняли пары `(источник, цель, related)`. Пользователь, который хочет связать две
заметки, уже связанные автоматически, получает отказ:

```
POST /api/v1/links  {"source_note_id":"5b139b46…","target_note_id":"e8a99f73…","link_type":"related","weight":0.9}
HTTP 409  {"code":"CONFLICT","reason":"already_exists",
           "expected":"unique combination of source, target and type"}
```

Проверено на тест-стенде 2026-09-22 (сид: 100 заметок, 60 ручных связей, 197 gamma).
Сеялка натыкается на это сама: один из 60 её случайных ручных линков упал с той же ошибкой —
около 1,7 % пар на сиде, а на реальной библиотеке с включёнными автосвязями доля будет выше:
каждая заметка имеет две исходящие gamma-связи к ближайшим по смыслу соседям, а человек
связывает руками как раз близкие по смыслу заметки.

Два следствия, и второе хуже первого:

1. **Намерение пользователя некуда записать.** «Я считаю, что эти заметки связаны» и «модель
   решила, что они похожи» — разные утверждения; сейчас первое отбрасывается, потому что
   второе уже есть.
2. **Связь остаётся стираемой.** `gamma-links-regenerate` удаляет **все** строки с
   `source_type='gamma'` и создаёт их заново по текущей модели. Пара, которую пользователь
   «связал» (а на деле получил 409), после смены модели может исчезнуть — хотя человек
   считает, что связь он сделал.

## Что сделать

1. **Повышение вместо отказа.** `POST /links` на паре, где существует связь того же типа с
   `source_type='gamma'`: перевести её в `source_type='user'`, записать вес и метаданные из
   запроса, вернуть **200** с этой связью (не 201 — новой строки не появилось). Ответ должен
   отличаться от «создано», чтобы фронтенд мог сказать «связь подтверждена».
2. **409 остаётся** там, где он осмыслен: ручная связь поверх ручной.
3. **Обратного понижения нет.** Удаление связи пользователем удаляет строку; следующий прогон
   автосвязей может создать её заново — это ожидаемо и не противоречит п. 1.
4. **Фронтенд.** В подсказке связи (`LinkTooltip`, ветка `sourceType === "gamma"`) — действие
   «подтвердить связь», которое делает тот же вызов. Кнопка нужна ровно там, где пользователь
   видит автоматическую связь.
5. **`gamma-links-regenerate`** уже фильтрует по `source_type` — после повышения строка
   становится `user` и переживает регенерацию; это надо закрепить тестом, а не считать
   следствием.

## Критерии приёмки

1. Живьём на тест-стенде: пара с gamma-связью → `POST /links` → **200**, в базе одна строка,
   `source_type='user'`, вес из запроса. Показать запрос и строку до/после.
2. `gamma-links-regenerate` после повышения: строка на месте, `source_type='user'` —
   интеграционный тест, а не наблюдение.
3. Мутация: вернуть 409 на gamma-паре → тест п. 1 красный. Мутация: `DeleteBySourceType`
   без фильтра → тест п. 2 красный (уже есть, проверить, что ловит и этот случай).
4. Ручная связь поверх ручной по-прежнему 409 — тест.
5. E2E или ручная проверка с экрана: у автоматической связи есть действие «подтвердить», после
   него бейдж «рекомендовано» сменился на обычную связь. Свидетельство — в
   `docs/agents/MANUAL_TEST_FEEDBACK.md`.

## Границы

- Не трогать порог и степень автосвязей — это LINKS-1 и W-1.
- Не вводить отдельный тип связи: `source_type` уже несёт это различие.
- Обратная (симметричная) связь — отдельный вопрос: на сиде 7 пар связаны в обе стороны
  автоматически, и это не дефект, а следствие направленности.
