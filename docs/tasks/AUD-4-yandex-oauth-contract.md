# AUD-4. Вход через Яндекс: свести маршрут, исключения и формат ответа

Постановка для Devin. Источник: [`../EXTERNAL_AUDIT_2026-09.md`](../EXTERNAL_AUDIT_2026-09.md), находка F-1. Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

Ставит Claude Code, реализует Devin, проверяет Claude Code на живом тест-стеке.

**Очерёдность:** можно брать сразу, ни с чем не пересекается. Задача подешевела: вторую половину поломки — метку PKCE — закрыл AUD-3.

## Проблема

Вход через Яндекс не работает и не работал. README рекламирует «OAuth2 (Yandex)» как готовую возможность.

Четыре источника расходятся по адресу инициации:

| Источник | Значение |
|---|---|
| `frontend/src/shared/api/auth.ts:82` | зовёт `v1/auth/yandex/login`, ждёт JSON `{url}` |
| `backend/cmd/server/router.go:117` | регистрирует `/api/v1/auth/yandex` |
| `backend/internal/interfaces/api/middleware/jwt.go:45` | вносит в исключения `/api/v1/auth/yandex/login` |
| `backend/openAPI.yaml:219` | документирует `/api/v1/auth/yandex`, ответ `302` |

Проверено на живом стеке в ходе аудита: **оба адреса отвечают `401`** анонимному пользователю. До `404` дело не доходит — глобальный `JWTAuth` обрывает запрос раньше, чем Gin отдаёт NoRoute.

## Что выяснено в коде

Читать перед началом.

**1. Расходится ровно инициация. Колбэк согласован.** `/api/v1/auth/yandex/callback` зарегистрирован (`router.go:118`), внесён в `SkipPaths` (`jwt.go:46`), возвращает JSON с токенами, фронтенд ждёт `AuthTokens` (`auth.ts:89-96`), OpenAPI документирует `200` с JSON. Здесь трогать нечего.

**2. Починка одного лишь пути на фронте не поможет.** Реальный маршрут `/api/v1/auth/yandex` в `SkipPaths` отсутствует, поэтому анонимный вызов получит `401` даже по верному адресу.

**3. Формат расходится третьим слоем.** `handler.go:639` отвечает `c.Redirect(http.StatusFound, redirectURL)`, а клиент читает тело как JSON `{url}`. Даже при совпадении путей `ky` пошёл бы по редиректу на `oauth.yandex.com` через `fetch` и упёрся в CORS.

**4. Тест фиксирует сломанный контракт.** `frontend/src/shared/api/auth.test.ts:153` утверждает, что клиент зовёт `v1/auth/yandex/login`, и он зелёный, потому что проверяет мок, а не систему. После правки он станет верным по случайности — это не делает его хорошим тестом.

## Решение: инициация отдаёт JSON по адресу `/api/v1/auth/yandex/login`

Из двух возможных контрактов — «302 с бэкенда» и «JSON с URL» — берём второй.

Обоснование: `SkipPaths` и фронтенд **уже** согласованы на `/login` и на JSON, поэтому это наименьший дифф; API остаётся JSON-only и проверяемым без следования редиректам; редирект из XHR всё равно нерабочий, а переход по ссылке фронтенд сделает сам.

## Что сделать

**Роутер** (`backend/cmd/server/router.go:117`)

Зарегистрировать инициацию как `/auth/yandex/login`. Старый путь `/auth/yandex` не оставлять: он никем не используется, а два адреса на одно действие — источник следующего расхождения.

**Хендлер** (`backend/internal/interfaces/api/handlers/auth/handler.go`, `YandexLogin`)

Вместо `c.Redirect(...)` вернуть `200` и JSON `{"url": "<authorization URL>"}`. Логику генерации `state`, его сохранения и PKCE не трогать — она приведена в порядок задачей AUD-3.

Поведение при невыставленном `YandexClientID` оставить как есть (`501` с телом ошибки).

**Middleware** (`backend/internal/interfaces/api/middleware/jwt.go:45`)

`SkipPaths` уже содержит `/api/v1/auth/yandex/login` — после переименования маршрута строка станет верной. Убедиться, что лишних записей про `yandex` не осталось.

**OpenAPI** (`backend/openAPI.yaml:219`)

Заменить описание: путь `/api/v1/auth/yandex/login`, ответ `200` с телом `{ url: string }`, плюс `501`, когда OAuth не настроен. Блок про `302` удалить.

**Фронтенд** (`frontend/src/shared/api/auth.ts`)

Клиент менять не требуется — он уже зовёт верный адрес и ждёт `{url}`. Убедиться, что вызывающая сторона после получения `url` делает переход (`window.location.href`), а не `fetch`.

**README**

Снять пометку о неработающем OAuth, которую поставил AUD-1 в разделах Features и Technology Stack.

## Ограничения

- Не трогать `/api/v1/auth/yandex/callback` — он согласован во всех четырёх источниках.
- Не менять генерацию и проверку `state` и PKCE: это сделано в AUD-3, повторная правка рискует регрессией.
- Не добавлять совместимость со старым путём. Это не публичный API, потребитель один.
- Не трогать `.claude/`, `docs/EXTERNAL_AUDIT_2026-09.md`, прочие `docs/tasks/AUD-*`.
- Personal-стек не поднимать.

## Критерии приёмки

1. `go test ./...` и `go vet ./...` зелёные; `npm run test:unit`, `npm run check`, `npm run lint` без новых замечаний.
2. **На живом тест-стеке анонимный `GET /api/v1/auth/yandex/login` возвращает `200` и JSON с полем `url`**, а не `401`. Это главный критерий: сейчас он не выполняется.
3. Значение `url` указывает на `https://oauth.yandex.com/authorize` и содержит `client_id`, `response_type=code`, `state` и — при включённом PKCE — `code_challenge` с `code_challenge_method=S256`.
4. Старый путь `/api/v1/auth/yandex` больше не зарегистрирован.
5. Тест, заменяющий `auth.test.ts:153`: проверяет **ответ хендлера**, а не факт вызова мока. Достаточно теста уровня хендлера на стороне Go, который разбирает возвращённый `url` и проверяет его параметры.
6. `grep -rn "auth/yandex" backend frontend/src backend/openAPI.yaml` даёт согласованный набор: `/login` и `/callback`, без остатков старого пути.

## Что приложить к результату

Вывод `curl -s http://127.0.0.1:18083/api/v1/auth/yandex/login` с тест-стека — до и после правки. До: `401`. После: `200` и JSON с `url`. Без этого критерий 2 не считается закрытым: именно живой ответ, а не юнит-тест, показывает, что маршрут и исключения сошлись.

### Про способ проверки

На тест-стенде эндпоинт отвечает `501 Yandex OAuth not configured`, потому что `YANDEX_CLIENT_ID` там не задан. Это **не дефект**: поведение предусмотрено постановкой и `handler.go:606-609`. Важно, что `501` приходит от хендлера, а не `401` от middleware, — значит маршрут зарегистрирован и внесён в исключения. Полный контракт проверен отдельным запуском сервера с заданным `YANDEX_CLIENT_ID` против базы тест-стека.

Старый путь `/api/v1/auth/yandex` отвечает `401`, а не `404`, — это известный артефакт: глобальный `JWTAuth` обрывает запрос раньше, чем Gin отдаёт NoRoute. Снятие маршрута подтверждено диффом.
