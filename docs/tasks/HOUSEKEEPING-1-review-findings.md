# Ревью HOUSEKEEPING-1: консолидация веток (Claude Code, 2026-09-13)

**Принято. Ничего не потеряно** — проверено, а не принято на слово.

## Как проверял

Для каждой удалённой ветки `devin/*` взял её головной коммит из PR (`gh pr view
--json headRefOid`) и проверил достижимость из `origin/main` / `origin/ai-agents`
через `git merge-base --is-ancestor`. Из четырнадцати тринадцать — reachable.

**Четырнадцатая едва не стала ложной находкой.** PR #87 (`devin/batch-api-design-board`)
показался недостижимым. Причина оказалась не в потере: PR слит **squash**-мержем, при
котором головной коммит ветки в предки никогда не попадает — в историю входит новый
коммит с тем же содержимым. Проверил по существу: merge-коммит `a42a376` в `main` есть,
файл `docs/tasks/BATCH-API-DESIGN.md` на месте. Содержимое доехало.

Вывод для метода: **проверка достижимости головного коммита не годится как признак
потери, если репозиторий использует squash-мерж.** Признак — наличие содержимого, а не
предок в графе.

## Состояние сейчас

Три удалённые ветки: `origin/main`, `origin/ai-agents`, `origin/java-source-text-handler`.
Не влита в `main` только последняя — и это ожидаемо, там лежит работа по Java-сервису,
которая ещё обсуждается (см. IMP-4-JAVA на доске). Все `devin/*` и `security/findings`
слиты и удалены.
