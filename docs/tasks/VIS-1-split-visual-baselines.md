# VIS-1. Разделить визуальные сценарии на анонимные и авторизованные

Постановка для Devin. Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

Ставит Claude Code, реализует Devin, проверяет Claude Code.

**Очерёдность:** после CI-3. Блокирует включение второго эталона в CI.

## Как это вскрылось

Задача «пересобрать baseline двумя снимками» выглядела конфигурационной: добавить проект `visual-real-auth` в джобу и перевести `ARGOS_REFERENCE_BRANCH` на `main`. Я так и сделал, а затем прогнал оба проекта локально против тест-стека, собранного **без** режима обхода.

```
7 failed   [visual]            — анонимный проект
0 failed   [visual-real-auth]  — авторизованный проект
19 passed
```

Причина на примере первого падения:

```
Error: page.evaluate: Element with selector "[data-testid="view-toggle-list"]" not found
```

Падают ровно те сценарии, которым нужна сессия: `Home page - list view`, `Home page - with star filter`, `2D Graph - full view with links`, `2D Graph - ghost node creation form`, `2D Graph - help modal`, `NoteCard - selected state`, `3D Graph - renders 3D view`.

**Вывод: визуальный набор писался в расчёте на авторизованного пользователя, а режим обхода молча эту сессию подставлял.** Пока `SKIP_AUTH=true`, разницы не видно; стоит его выключить — и «анонимный» проект разваливается, потому что анонимным он никогда не был.

Поэтому в CI я оставил `SKIP_AUTH: "true"` и не стал добавлять второй проект: иначе джоба покраснела бы, а второй эталон получился бы копией первого. Переведена только `ARGOS_REFERENCE_BRANCH` на `main` — она безопасна и от этого не зависит.

## Почему это важно, а не косметика

Решение владельца на доске: **визуальные эталоны на `SKIP_AUTH` не строятся.** В этом режиме `applyNoteScope` (`note_repo.go:40-44`) снимает фильтр по владельцу, а `isAuthenticated()` (`auth-session.svelte.ts:110-112`) всегда возвращает `true`. То есть нынешний эталон фиксирует состояние, которого в проде не существует, и называется при этом публичным.

## Что сделать

**1. Развести сценарии по проектам.**

`frontend/tests/visual/visual-regression.spec.ts`. Определить для каждого сценария, что он проверяет:

- **анонимные** — то, что видит незалогиненный посетитель: страницы входа и регистрации, публичный граф, пустые состояния;
- **авторизованные** — всё, что требует сессии: списки заметок, фильтры, создание призрачного узла, выбранная карточка, кокпит.

Разделение сделать тегами или отдельными файлами — на твой выбор, лишь бы проект `visual` брал только первые, а `visual-real-auth` только вторые.

**2. Выключить режим обхода в визуальной джобе.**

`.github/workflows/main.yml`, джоба `visual-regression`: `SKIP_AUTH: "false"` вместо `"true"`, комментарий-заглушку убрать. Обратить внимание: `docker-compose.test.yml` использует `${SKIP_AUTH:-true}`, поэтому переменную надо задать явно, а не удалить.

**3. Включить второй проект в прогон.**

`npx playwright test --project=visual --project=visual-real-auth`.

**4. Проверить фикстуру.**

CI сеет `NOTE_COUNT=20`, из них публичными становится около пятой части. Для анонимного эталона это четыре узла — возможно, слишком мало, чтобы снимок что-то проверял. Если так, увеличить долю публичных заметок в фикстуре визуального прогона, а не общее число.

## Ограничения

- Не возвращать `SKIP_AUTH=true` как способ «починить» анонимные сценарии: это ровно та подмена, из-за которой набор и разошёлся с реальностью.
- Не трогать `ARGOS_REFERENCE_BRANCH` — уже переведена на `main`.
- Эталоны не заливать локально: рендер на машине разработчика отличается от ubuntu-раннера шрифтами и сборкой headless Chromium, и локальный эталон сделает все последующие сравнения в CI красными. Baseline создаётся первым прогоном CI на референсной ветке.

## Критерии приёмки

1. `npx playwright test --project=visual --project=visual-real-auth` на стенде **без** режима обхода — оба проекта зелёные.
2. Ни один сценарий проекта `visual` не требует сессии: прогон под анонимным контекстом проходит без `storageState`.
3. Снимки авторизованного и анонимного проектов **различаются** — иначе второй эталон бессмыслен. Ориентир: на сидированных данных разница по пикселям была 28,8 %.
4. Джоба `visual-regression` зелёная на `ai-agents`.

## Что приложить к результату

Сводку прогона обоих проектов без режима обхода и попиксельное сравнение одного и того же экрана в двух проектах — доказательство, что эталоны действительно разные.
