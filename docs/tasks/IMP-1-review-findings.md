## Блокер: изменение ничем не охраняется

Постановка, п. 4: «дополнить или добавить тест, что `import/bookmarks` использует тот же набор»
и E2E на содержимое `<select>`. Ни того, ни другого нет. Тест `celestial-body.test.ts`
проверяет содержимое `UI_TYPES` — это про модель, не про страницу; страница может брать типы
откуда угодно, и тест этого не увидит.

Проверил мутацией. Вернул на страницу захардкоженный список:

```
const noteTypes = ["star", "planet", "technical", "reality_rift"];
```

и прогнал весь набор:

```
 Test Files  139 passed (139)
      Tests  1436 passed (1436)
MUTANT_UNIT_EXIT=0
```

**Ровно тот дефект, который задача чинила, вернулся — и 1436 тестов остались зелёными.**
Значит следующий, кто тронет этот файл — а его трогали четыре раза за сентябрь, — сломает
исправление, и никто не узнает. По норме проекта исправление без теста, который падает на его
откате, не считается законченным («Finishing Functionality»).

Что нужно: тест страницы, который рендерит селектор и утверждает, что `technical` и аномалий
в опциях нет, а все одиннадцать UI-типов есть. Мутация выше обязана его ронять. E2E из
постановки — по желанию, юнита на страницу достаточно.

## Открытое решение владельца: пункт 3

Домен после BATCH-DDD-1 **знает**, какие типы пользовательские — `isUserSelectable` стоит у
каждого. И не использует это знание: любой прямой `POST /import/bookmarks` или
`/import/bookmarklet` с `type: technical` создаст техническую заметку от имени пользователя.
UI-ограничение обходится одним `curl`.

Это не дефект реализации — постановка оставила пункт на решение владельца, решения не было.
Но полуреализация висит: поле есть, проверки нет. Варианты те же, что в постановке:
отклонять `technical` на пользовательских маршрутах (оставив для системных), либо приводить
к `asteroid`. Мой голос — отклонять: молчаливая подмена типа — это второй `is_public`, который
мы только что выкорчевали (PUB-FIELD-1).

## Мелочи

1. **Тест на `UI_TYPES` не упоминает `technical`.** Проверяет `unknown` и `reality_rift`, а
   тип, ради которого заводилась задача, — нет. Одна строка.
2. **`start-test.ps1` вернул 0 при неподнятом стеке.** Docker Desktop не был запущен; скрипт
   напечатал `ERROR: Test stack failed to start (exit 1)` — и обёртка вернула ноль. Тот же
   класс, что CHECK-ALL-1; не по этой задаче, отдельной строкой на доску.

## Принято без замечаний

- Сама замена: одна строка, правильный источник, никакого дублирования списка.
- i18n: все одиннадцать типов, оба языка — проверено по ключам, а не по вере.
- Пункт 2 постановки: у одиночного импорта `/import` селектора нет и не появилось — как и
  просила постановка.
