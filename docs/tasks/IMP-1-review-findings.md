## Блокер: изменение ничем не охраняется

Постановка, п. 4: «дополнить или добавить тест, что `import/bookmarks` использует тот же набор»
и E2E на содержимое `<select>`. Ни того, ни другого нет. Тест `celestial-body.test.ts`
проверяет содержимое `UI_TYPES` — это про модель, не про страницу; страница может брать типы
откуда угодно, и тест этого не увидит.

Проверил мутацией. Вернул на страницу захардкоженный список:

```
const noteTypes = ["star", "planet", "technical", "reality_rift"];
```

и прогнал весь набор:

```
 Test Files  139 passed (139)
      Tests  1436 passed (1436)
MUTANT_UNIT_EXIT=0
```

**Ровно тот дефект, который задача чинила, вернулся — и 1436 тестов остались зелёными.**
Значит следующий, кто тронет этот файл — а его трогали четыре раза за сентябрь, — сломает
исправление, и никто не узнает. По норме проекта исправление без теста, который падает на его
откате, не считается законченным («Finishing Functionality»).

Что нужно: тест страницы, который рендерит селектор и утверждает, что `technical` и аномалий
в опциях нет, а все одиннадцать UI-типов есть. Мутация выше обязана его ронять. E2E из
постановки — по желанию, юнита на страницу достаточно.

## Открытое решение владельца: пункт 3

Домен после BATCH-DDD-1 **знает**, какие типы пользовательские — `isUserSelectable` стоит у
каждого. И не использует это знание: любой прямой `POST /import/bookmarks` или
`/import/bookmarklet` с `type: technical` создаст техническую заметку от имени пользователя.
UI-ограничение обходится одним `curl` — воспроизведено на стенде, см. «Живой прогон». И контракт `openAPI.yaml` эти типы для импорта прямо разрешает.

Это не дефект реализации — постановка оставила пункт на решение владельца, решения не было.
Но полуреализация висит: поле есть, проверки нет. Варианты те же, что в постановке:
отклонять `technical` на пользовательских маршрутах (оставив для системных), либо приводить
к `asteroid`. Мой голос — отклонять: молчаливая подмена типа — это второй `is_public`, который
мы только что выкорчевали (PUB-FIELD-1).

## Живой прогон

Тест-стек с `ai-agents` `dd4b896`, `SKIP_AUTH=true`, после `seed-test-data.ps1` (100 заметок).

**Селектор — по дереву доступности страницы, не по глазам.** `/import/bookmarks` → адрес в
поле → Preview → в строке предпросмотра `combobox "Asteroids"` с ровно одиннадцатью опциями:

```
galaxy, nebula, blackhole, star, planet, moon, comet, satellite, asteroid (selected), dust, debris
```

Ни `technical`, ни `unknown`, ни одной аномалии. Порядок — по `scaleRank` таксономии, умолчание
`asteroid`. Критерии 1, 2 и 5 — выполнены. (Нативный выпадающий список в снимок экрана не
попадает; список опций из дерева доступности — свидетельство точнее снимка.)

**Обход через API — воспроизведён.** Три `POST /api/v1/import/bookmarks`, по одному элементу:

```
== technical ==      HTTP 202   task ad0694c3…
== reality_rift ==   HTTP 202   task e877e060…
== asteroid ==       HTTP 202   task 7a429115…

knowledge_test=# SELECT title, type FROM notes WHERE title LIKE 'IMP-1 probe%';
 IMP-1 probe asteroid     | asteroid
 IMP-1 probe reality_rift | reality_rift
 IMP-1 probe technical    | technical
```

Пользователь получил заметку типа `technical` и заметку-аномалию одним `curl`. Более того,
контракт это **обещает**: `backend/openAPI.yaml`, схема `ImportBookmarksItem.type`, перечисляет
все семнадцать типов включая `technical`, `unknown` и четыре аномалии. Интерфейс и контракт
теперь говорят разное, а контракт — это то, что читает внешний потребитель, в том числе
будущий Java-сервис.

**По дороге, не про IMP-1.** Первая проба упала на `notes_creator_id_fkey`: стенд был поднят
без сидера, и пользователя `SKIP_AUTH` в базе не было — ровно та зависимость от строки в базе,
которую владелец решил оставить как есть. Сидер отчитался об одной ошибке: NLP не успел
обработать 100 заметок за 600 с (98 эмбеддингов, 99 наборов ключевых слов) сразу после полной
пересборки образов — пригодится в ревью NLP-2, где скорость keybert и есть предмет замера.
