# PUB-1. Открыть анониму чтение публичной заметки и поиск по публичным

Постановка для Devin. Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

Ставит Claude Code, реализует Devin, проверяет Claude Code на живом тест-стеке.

**Очерёдность:** первая из тройки PUB. Блокирует VIS-1 раунд 3 — пока поиск закрыт, анонимный визуальный эталон снимает плашку ошибки.

**Это изменение публичного периметра.** Читать раздел «Что выяснено» до начала.

## Зачем

Решение владельца: публичный граф — витрина сообщества. Неавторизованный посетитель заходит, видит опубликованные заметки, читает их и ищет по ним; после входа переключается на своё.

Сегодня замысел выполнен наполовину. Граф рисуется, но **прочитать заметку нельзя**: узел несёт только `ID, Title, Type, Creator, Public` (`services/graph-service/internal/db/postgres_client.go:13-19`), содержимого в нём нет, а `GET /api/v1/notes/:id` требует токена. Поиск отвечает `401`:

```
GET /api/v1/notes/search?q=star   ->  401 Unauthorized
```

Получается витрина из подписанных точек, которые нельзя открыть.

## Что выяснено в коде

**1. Слой данных уже готов.** `applyNoteScope` (`backend/internal/infrastructure/db/postgres/note_repo.go:36-48`) при `userID == uuid.Nil` сам добавляет `WHERE is_public = true`. То есть анонимный запрос, дошедший до репозитория, вернёт только публичное — без единой правки.

**2. Мешает только middleware.** `JWTAuth` глобальный (`backend/cmd/server/router.go:83`) и отбивает запрос до хендлера. Список исключений — `DefaultJWTConfig`, `backend/internal/interfaces/api/middleware/jwt.go:39-52`, двенадцать записей; заметок и поиска среди них нет.

**3. Значит работа меньше, чем кажется:** пропустить запрос с пустым пользователем, а не писать новую логику доступа. Но именно поэтому нужна аккуратность — ошибка здесь открывает чужие приватные заметки.

**4. `Cache-Control` трогать нельзя.** После AUD-2 приватные ответы отдаются как `private` с `Vary: Authorization, Cookie`. Те же маршруты будут обслуживать обе аудитории, поэтому вернуть `public` **нельзя**: иначе приватный ответ владельца попадёт в общий кэш. Это прямая регрессия находки S-4 аудита.

## Что сделать

### 1. Пропустить два маршрута без токена

`GET /api/v1/notes/:id` и `GET /api/v1/notes/search` — в исключения `JWTAuth`.

Внимание на способ: `JWTAuth` сравнивает `c.FullPath()`, поэтому в списке должен стоять шаблон Gin (`/api/v1/notes/:id`), а не конкретный путь.

**Осторожно с коллизией маршрутов.** `/notes/:id` в Gin совпадёт и с `/notes/search`, если порядок регистрации неудачен, — проверь, что открытие `:id` не открыло заодно `/notes/batch`, `/notes/:id/links` и прочие соседние. Открыто должно быть ровно два маршрута, оба `GET`.

### 2. Убедиться, что анонимный запрос действительно ограничен публичным

Хендлер должен получить пустого пользователя и уйти в `applyNoteScope` по ветке `uuid.Nil`. Если где-то по пути есть выборка, минующая эту функцию, — найти и закрыть.

Отдельно проверь `Search`: он может иметь собственный запрос, не проходящий через `applyNoteScope`.

### 3. Приватная заметка анониму — `404`, а не `403`

Существование чужой приватной заметки не должно подтверждаться. Для анонимного запроса приватный `id` отвечает так же, как несуществующий.

### 4. Не трогать

- `Cache-Control` и `Vary` — остаются `private`.
- Запись: создание, правка, публикация, удаление остаются за токеном.
- `POST /notes/:id/publish` и `unpublish` — не трогать.
- Рекомендации, ключевые слова, достижения — вне задачи.

## Критерии приёмки

1. Анонимный `GET /api/v1/notes/<id публичной>` отдаёт `200` с содержимым.
2. Анонимный `GET /api/v1/notes/<id приватной>` отдаёт `404`.
3. Анонимный `GET /api/v1/notes/search?q=<слово из публичной>` отдаёт `200` и только публичные заметки.
4. Анонимный поиск по слову, которое встречается **только в приватной** заметке, не возвращает её.
5. Авторизованный владелец по-прежнему видит и приватные — в чтении и в поиске.
6. Запись анонимом по-прежнему `401`: `POST /notes`, `PUT /notes/:id`, `DELETE /notes/:id`.
7. Заголовки не изменились: `Cache-Control: private`, `Vary: Authorization, Cookie`.
8. **Проверено мутацией:** временно убрать ветку `userID == uuid.Nil` из `applyNoteScope` и убедиться, что тест на критерий 4 краснеет. Без этого утечка приватных заметок ничем не удерживается.

## Что приложить к результату

Вывод `curl -D -` по критериям 1–4 и 6, анонимно и под токеном, на одних и тех же идентификаторах. Плюс текст отказа из мутации по критерию 8.

Числа тест-стека для ориентира: сидер с `PUBLIC_PERCENT=50` даёт 20 заметок, из них 10 публичных.
