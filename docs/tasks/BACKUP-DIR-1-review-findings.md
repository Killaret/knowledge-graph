# BACKUP-DIR-1 — разбор ревью

Ревьюер: Claude Code. Дата: 2026-09-23. Реализация: Devin, `df18b67` (2026-09-22), по решению
владельца 52 («канонический каталог — `~/Desktop/my items`»).

**Вердикт: принято.** Жёстко вписанное имя пользователя ушло из compose, путь по умолчанию
раскрывается в синхронизируемую папку того, кто запускает стек, — проверено рендером. Одна
мелочь в документации достойна быстрой правки: документ разрешает форму, которую compose не
принимает.

## Проверено исполнением

Рендер `docker compose -f docker-compose.personal.yml config --format json` (с временным пустым
`.env`, как делает сторож монтирования), источник тома `/backups` у обоих сервисов:

| `KG_BACKUP_DIR` | `worker_personal` | `backup_scheduler` |
|---|---|---|
| не задан | `C:\Users\89209/Desktop/my items` | то же |
| `C:/Users/89209/Desktop/my items` | `C:/Users/89209/Desktop/my items` | то же |
| `Desktop/my items` (хвост от домашнего каталога) | **compose отказывается:** `service "backup_scheduler" refers to undefined volume Desktop/my items: invalid compose project` | — |

Умолчание раскрывается через `${USERPROFILE:-${HOME}}` — вложенная подстановка работает,
разделители смешанные (`\` и `/`), Docker Desktop их принимает.

Сторож разрушающих команд и проверка свежести на текущем коде читают ту же папку: обе видят
`backup-personal-auto-2026-09-21-214357.sql.gz` (32.5 ч на момент проверки) и обе отказывают по
порогу 24 ч. Расхождение «сторож смотрит в `<repo>\backups`», о котором Devin писал в реплике
22.09, было в старых локальных версиях скриптов клона `main`, а не в текущем коде.

`check-all` 2026-09-23 без `-Quick` — сводка в журнале; фаза `Worker backup mount` — PASS.

## Мелочи

1. **Документ разрешает то, что ломает запуск.** `docs/operations/BACKUP.md:15–19`:
   «`KG_BACKUP_DIR` … may be an absolute path or a tail relative to the user's home directory …
   Set `KG_BACKUP_DIR` in `.env` to override». Скрипты хвост понимают, compose — нет: по этой
   инструкции Personal-стек не стартует (см. третью строку таблицы). Падение громкое, данные не
   теряются, но инструкция неверна. Нужно одно предложение: в `.env` — только абсолютный путь;
   хвост понимают скрипты.
2. `docs/operations/BACKUP.md:326` в примере compose всё ещё показывает старое умолчание
   `${KG_BACKUP_DIR:-C:/Users/<your-username>/Desktop/my items}`, а не новое
   `${USERPROFILE:-${HOME}}/…`.
3. Свежего бэкапа Personal нет с 21.09 (32.5 ч на момент ревью) — не дефект задачи: стек не
   поднимался, событийный путь молчит, когда нет изменений. Сторож разрушающих команд это
   правильно блокирует; владельцу — к сведению.
