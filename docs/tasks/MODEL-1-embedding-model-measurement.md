# MODEL-1. Замер моделей эмбеддингов до любой смены модели

Постановка для Devin. Ставит Claude Code, замер делает Devin, **решение принимает владелец**
по приложенным выдачам. Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

**Решение владельца, 2026-09-17: замер провести до того, как менять модель.** Это следствие
решения 5 («модель первой: её замена обесценивает всё, что посчитано до неё»): пересчёт
ключевых слов в NLP-2 и автосвязи в RECO-1 зависят от модели, менять её после них — считать
дважды.

## Что известно о текущей модели — по её файлам, не по памяти

`paraphrase-multilingual-MiniLM-L12-v2`, снимок `e8f8c211`:

| Параметр | Значение | Откуда |
|---|---|---|
| окно, которое применяет библиотека | **128 токенов** | `sentence_bert_config.json: max_seq_length` |
| окно, которое сеть умеет физически | **512** | `config.json: max_position_embeddings` |
| размерность вектора | 384 | `config.json: hidden_size` |
| слоёв | 12 | `config.json` |
| лицензия | Apache-2.0 | карточка модели |

128 токенов — примерно 80–100 русских слов, один абзац. Всё, что дальше, модель не читает.
При этом окно 512 доступно **на той же модели одной настройкой** — но модель училась на
коротких парах, и качество на длинных входах не обещано никем. Это и надо мерить.

## Кандидаты

| Модель | Размерность | Окно | Лицензия | Что меняется в проекте |
|---|---|---|---|---|
| текущая, окно 128 | 384 | 128 | Apache-2.0 | ничего — базовая линия |
| текущая, окно 512 | 384 | 512 | Apache-2.0 | одна настройка; **пересчёт эмбеддингов**, потому что векторы изменятся |
| `intfloat/multilingual-e5-small` | **384** | 512 | MIT | **колонка pgvector не меняется**; нужны префиксы `query:` / `passage:`; пересчёт |
| `cointegrated/rubert-tiny2` | 312 | 2048 | MIT | миграция колонки; в разы быстрее; английский слабее |
| `intfloat/multilingual-e5-base` | 768 | 512 | MIT | миграция колонки; в 2–3 раза медленнее; пересчёт |

`bge-m3` (1024, окно 8192, MIT, 2 ГБ) в замер не включать: на CPU в 5–10 раз медленнее
текущей, для машины владельца это не вариант, а замер стоит часов.

Цифры окон и размерностей — из карточек моделей; **перед замером сверить по файлам**, как
сделано для текущей.

## Данные для замера

- **Реальные заметки владельца** — не выдуманные: 22 закладки из `bookmarks_11.09.2026.html`,
  которые уже использовал URL-HEADING-1. Это импортированные страницы, самый трудный случай.
- **Тест-сид** — 20 самых длинных и 20 типичных заметок.
- **Десять фиксированных запросов** для поиска — составить заранее, из того, что владелец
  реально искал бы: по-русски, по-английски и смешанных.

Personal-стек не трогать; заметки владельца — только те, что уже лежат в репозитории.

## Что мерить

Для каждой модели, на одних и тех же данных:

1. **Поиск.** Top-10 по каждому из десяти запросов — таблица «запрос × модель», в ячейке
   заголовки заметок. Владелец смотрит глазами, какая выдача похожа на правду.
2. **Близость пар.** Матрица косинусов для 20 заметок; список 15 самых близких пар по
   каждой модели. Это то, из чего будут строиться автосвязи и β-компонент.
3. **Ключевые слова.** Top-10 от keybert в гибридном режиме (шорт-лист по частоте → ранжирование
   моделью) для тех же заметок. Сравнить с текущим `yake` как базовой линией.
4. **Скорость.** p50 и p95 для эмбеддинга одной заметки и для одного вызова keybert,
   на CPU, в контейнере NLP-сервиса, а не на хосте.
5. **Память** контейнера с загруженной моделью.

Никаких сводных «баллов». Пять таблиц, рядом, в файле находок. Решение — владельца, по
тому, что он увидит.

## Как

- Скрипт в `nlp-service/scripts/` (или `scripts/testing/`), который принимает имя модели и
  окно, прогоняет пять замеров и пишет Markdown. Один скрипт — все модели, иначе цифры
  несравнимы.
- Модели качаются в HF-кэш; **офлайн-старт сервиса с текущей моделью не должен сломаться**
  от того, что в кэше лежат ещё три.
- Продуктивную модель в этой задаче **не менять** — ни в `.env`, ни в compose, ни в
  умолчаниях `config.go`.

## Критерии приёмки

1. Файл `MODEL-1-review-findings.md` с пятью таблицами для всех пяти вариантов на одних данных.
2. Параметры каждой модели сверены по файлам и приложены (окно, размерность, лицензия).
3. Скрипт лежит в репозитории и воспроизводит таблицы одной командой; команда в файле.
4. Продуктивная модель не изменилась: `git diff` по `.env*`, compose, `config.go` пуст.
5. Офлайн-старт с текущей моделью проходит.

## Что дальше

Владелец выбирает. Если выбор — не «текущая, 128», то это **новая постановка** с миграцией по
образцу P11-2, а пересчёт NLP-2 и подключение автосвязей RECO-1 ждут её.
