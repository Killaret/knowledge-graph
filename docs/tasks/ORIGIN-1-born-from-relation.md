# ORIGIN-1. Происхождение заметки: «рождена из»

Статус: **бэклог — Devin; в 1.0 или после — решает владелец.** Постановка — Claude Code, 2026-09-27,
по обсуждению с владельцем.

**Решение владельца (2026-09-27, ORIGIN-1):** происхождение заметки выносится из типов связей в
отдельную связь «рождена из». Она не зависит от типа связи, источников может быть несколько, и
ставится она сама, при создании заметки. Типы `parent` и `child` уходят.

## Зачем

Задумка `parent` и `child` — «эта заметка родилась из той»: из другой заметки, из обсуждения, из книги.
Пример владельца: прочитал книгу, захотел посмотреть экранизацию — записал заметку. Но тип связи
отвечает за смысл, а происхождение — за то, откуда заметка взялась. Это две независимые оси: они
могут дополнять друг друга, жить отдельно или существовать поодиночке.

Сейчас они в одном поле, и это мешает:

- дочерняя заметка не может быть одновременно «связано» или «зависимость» без второй линии между
  той же парой;
- `child` — та же связь, что `parent`, только в обратную сторону, и её ничто не создаёт;
- «Создать дочернюю заметку» (`frontend/src/features/home-page/home-page.svelte.ts:553`) — два
  отдельных запроса: если упадёт второй, заметка останется без происхождения.

## Модель

- Отдельная связь «рождена из»: заметка → заметка-источник, многие-ко-многим.
- Независима от типов связей: бывает вместе с любой связью, без неё или вообще не бывает.
- События графа — механизмом SYNC-1 A2 (outbox).
- Для кластеров (P11-1) происхождение — готовый сигнал близости.

## Как ставится — само, при создании

Вручную происхождение почти никто не заполнит. Слова владельца: «я этим заниматься не буду». Поэтому:

- «Создать из этой заметки» в контекстном меню — вместо нынешнего «создать дочернюю». Заметка и
  происхождение пишутся одной операцией;
- несколько узлов, выбранных с Ctrl → «создать из выбранных»;
- в списке — режим выбора → тот же сценарий.

## Перенос

- `parent` A→B → B рождена из A; `child` A→B → A рождена из B.
- API принимает создание связи `parent` или `child` и пишет происхождение — совместимость клиентов;
  в `openAPI.yaml` пометка «устарело».
- **Вопрос владельцу до начала:** остаётся ли после переноса между заметками обычная связь
  `related` или только происхождение.

## Показ

Когда и как показывать происхождение на графе, решается в конце, по живому интерфейсу (решение
владельца). В панели заметки: «Рождена из: …» и «Из неё рождены: …».

## Критерии приёмки

1. Создание из одной и из нескольких заметок — одна операция; тест: сбой записи происхождения
   откатывает создание.
2. Перенос на фикстуре: записей происхождения столько же, сколько было связей `parent` и `child`,
   направления верные — тест.
3. Создание связи `parent` или `child` через API пишет происхождение — тест.
4. Панель заметки показывает обе строки; живьём — свидетельство в
   `docs/agents/MANUAL_TEST_FEEDBACK.md`.
5. Документы: `LINK_TYPES.md`, `LINK_TYPES_RU.md`, `ARCHITECTURE_SUMMARY.md`, `openAPI.yaml`.
