# NOTE-TYPES-1. Типы заметок: пересечения и оси

Статус: **после 1.0 (решение 100); вопрос отложен 2026-09-27.** Разбор — Claude Code, 2026-09-27,
по вопросу владельца: «все ли типы действительно отличаются друг от друга, не пересекаются и логичны».

## Главное

`docs/product/CELESTIAL_BODY_SEMANTICS.md` прямо пишет, что тип заметки кодирует сразу три вещи:
масштаб, стадию жизни и центральность. Это та же ошибка, что с типами связей (LINK-TYPES-1,
ORIGIN-1): разные оси в одном поле. Если разложить 13 типов по тому, что они выражают:

| Что выражает | Типы |
|---|---|
| масштаб темы | galaxy → star → planet → moon |
| вид содержимого | comet — дело (решение 78); satellite — утилита: шаблон, чек-лист, конфиг; asteroid — фрагмент: цитата, закладка, мысль, TODO; nebula — набросок идеи; blackhole — проблема, открытый вопрос |
| стадия жизни | dust — не разобрана; debris — архив |
| системные | technical, unknown |

## Пересечения

1. **`dust`, `asteroid` и `nebula` — про одно: сырая мысль или закладка.** В документе: у `dust` «Late-night
   idea, Quick bookmark», у `asteroid` «quick thoughts, bookmarks», у `nebula` «Unsorted concepts».
2. **`asteroid` содержит TODO**, а с решения 78 дела — кометы.
3. **Чек-лист `satellite` против дела `comet`** — граница не проведена.
4. **`dust` против «сырой» из решения 77** — два признака «не обработано».
5. **`debris` затирает тип:** в архиве не видно, чем заметка была. Теперь есть и корзина (NOTE-DELETE-1),
   то есть два разных «ушло».
6. **`dust` без механизма.** По документу это «входящие, ждут разбора»; в коде — только особый вид
   карточки (`frontend/src/widgets/notes/NoteCard.svelte:81`, класс `dust`), разбора нет. Владелец
   помнит, что `dust` потом должен превращаться в другой тип.

## Предложение — на обсуждение

Тот же принцип, что для связей: тип — то, чем заметка является; стадия — отдельный признак.

- **Типы:** темы по масштабу (galaxy, star, planet, moon) и виды (comet, satellite, asteroid, nebula,
  blackhole).
- **Стадии:** «не разобрана» вместо `dust`, «сырая» (решение 77), «в архиве» вместо `debris` — тип
  сохраняется, «в корзине» (NOTE-DELETE-1).
- **Разбор «не разобранных»:** система предлагает тип, пользователь подтверждает одним кликом
  (есть дата — комета, одна ссылка — астероид).
- **Границы:** asteroid — законченный кусок (цитата, фраза, закладка), без TODO; nebula — идея, которая
  растёт; satellite — многоразовое (шаблон, конфиг); comet — разовое дело.

## Вопросы владельцу

1. `dust` — стадия «не разобрана», из которой заметка переходит в настоящий тип: так задумывалось?
2. `debris` — стадия «в архиве» с сохранением типа?
3. Нужны ли одновременно «не разобрана» и «сырая», или это одно?
4. Границы asteroid, nebula, satellite и comet — как выше?

Порядок разговора — по одному типу, как со связями: `dust` → `debris` → asteroid и nebula → satellite и
comet → типы масштаба.
