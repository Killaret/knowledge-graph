# VERIFY-ANCHORS-1. Якоря требований для доказательного тестирования — в реестре SPEC-AUDIT-1

Статус: **бэклог — после 1.0** (решение 118). Постановка — Claude Code, 2026-11-15, по разговору с владельцем.
Исполнитель — Devin, ревью — Claude Code. Связано: [VERIFY-SPEC-1](VERIFY-SPEC-1-evidence-testing-pilot.md),
[SPEC-AUDIT-1](SPEC-AUDIT-1-specs-vs-code.md), [PROMISES-1](PROMISES-1-user-promises.md),
[TEST-AUDIT-1](TEST-AUDIT-1-tests-that-matter.md).

## Зачем

Первый шаг методики `verify-by-spec` требует, чтобы у каждого инварианта были номер критерия и цитата из
спецификации. Каталога требований с такими якорями у нас нет. Без него инварианты пишет исполнитель, и они
подгоняются под его код. Против этого методика и сделана.

Сверка требований с кодом уже идёт — SPEC-AUDIT-1: вердикт с доказательством на каждое требование каждой
постановки. Отдельный каталог требований дал бы второй реестр того же, и реестры разошлись бы. Поэтому якоря
добавляются в реестр SPEC-AUDIT-1, а не в новый файл.

## Что сделать

1. **Строка реестра → якорь.** У каждой строки требования в `SPEC-AUDIT-1-register.md`:
   - номер требования (уже есть, вида `SYNC-A.4`);
   - цитата критерия из постановки — дословно, с путём и строкой;
   - действующий источник: постановка или решение из `DECISIONS.md`, которое требование изменило.
2. **Отменённое — отдельно.** Требование, которое отменило или заменило более позднее решение, получает пометку
   «отменено — решение N» и в инварианты не идёт. Иначе мы заякорим мёртвые требования.
3. **Верхний слой — обещания.** Каталог `docs/product/USER_PROMISES.md` (PROMISES-1) — то, что продукт обещает
   пользователю сейчас. Каждое обещание ссылается на якоря, которые его держат.
4. **Порядок областей.** Первым — этап D (безопасность, данные, эксплуатация): это полный уровень методики, где
   ложное «подтверждено» опаснее всего. Затем C, B, A.
5. **Сторож.** У строки «есть» без цитаты или без действующего источника `check-spec-audit-1-register.mjs`
   краснеет.

## Критерии приёмки

1. В области этапа D у каждой строки требования есть номер, цитата с `путь:строка` и действующий источник.
2. Выборка из 10 случайных якорей: цитата дословно совпадает с постановкой, источник — действующий. Один промах
   возвращает область.
3. Отменённые требования помечены номером решения. В выборке из 5 решение действительно отменяет требование.
4. Сторож с фикстурой «строка без цитаты» красный.

## Условие начала

После выпуска 1.0. До выпуска SPEC-AUDIT-1 идёт в прежнем виде: этапы B–E — в составе 1.0, без новых полей.
