# LINK-TYPES-1. Типы связей: пересмотр и отрисовка

Статус: **бэклог — Devin; в 1.0 или после — решает владелец.** Постановка — Claude Code, 2026-09-27,
по обсуждению с владельцем.

**Решение владельца (2026-09-27, LINK-TYPES-1):** тип по умолчанию везде — `related`; `reference` и
`custom` сливаются в `related`; `dependency` остаётся и показывается цепочкой; автосвязи рисуются
своим цветом, ручные — цветом типа, легенда в 2D и 3D; `parent` и `child` уходят в ORIGIN-1.

## Зачем

Владелец задумывал, что ручные связи и автосвязи различимы с первого взгляда, а у каждого типа свой
смысл. Сейчас, по проверке 2026-09-27:

- ручная связь по умолчанию `related` (`frontend/src/features/graph-forms/link-form.ts:35`), автосвязь
  модели — всегда `related` (`backend/internal/application/recommendation/gamma_link_generator.go:189`).
  Обе серые и различаются только толщиной (UI-GRAPH-1);
- в базе тип по умолчанию `reference` (`backend/internal/infrastructure/db/postgres/link_model.go:15`),
  в форме — `related`;
- `reference` («см. также») по смыслу совпадает с `related`, а его направление на графе не видно:
  стрелок нет;
- `custom` («смысл задаёшь сам») — поля для смысла нет ни у связи, ни в интерфейсе. Из легенды и
  фильтров тип скрыт (`isUi: false`), а при создании связи выбирается;
- ни рекомендации, ни раскладка графа от типа не зависят: тип — только подпись и цвет.

## Что сделать

1. **Тип по умолчанию — `related`** везде: default в базе (миграция), API, форма.
2. **`reference` и `custom` → `related`.** Миграция меняет тип и сохраняет вес. Если у пары заметок
   уже есть `related`, остаётся одна связь с большим весом, вторая удаляется мягко; число таких пар
   миграция печатает. API принимает старые значения и сохраняет `related` — совместимость клиентов,
   в том числе будущего Java-сервиса; в `openAPI.yaml` пометка «устарело». Из выбора в интерфейсе
   оба типа уходят.
3. **Автосвязи (`source_type = gamma`) — свой цвет**, которого нет ни у одного ручного типа; яркость —
   по силе сходства; тонкая линия из UI-GRAPH-1 остаётся. Ручные связи — цветом своего типа.
4. **Легенда в 2D и 3D:** ручные типы и строка «автосвязь (модель)». Это закрывает вопрос владельца о
   легенде 3D из разбора UI-GRAPH-1.
5. **`dependency` — дорога:**
   - смысл: цепочка связанных задач; направление — от того, что делается сначала, к тому, что потом;
   - наведение на заметку подсвечивает всю цепочку через неё — что до и что после — и гасит
     остальное. Это расширение готовой подсветки соседей (`renderer-orchestrator.ts`). Когда курсор
     переходит на другую заметку цепочки, подсветка пересчитывается от неё;
   - направление — бегущие точки от начала к концу, как огни на взлётной полосе;
   - яркость — по расстоянию от заметки под курсором;
   - глубина — не больше 10 шагов, число в конфиге (`frontend.graph.dependency_highlight_depth`)
     рядом с `label_hub_count`;
   - цикл — красным и предупреждение в панели заметки;
   - панель заметки: «Требует: …» и «Нужна для: …»;
   - в 3D — то же.
6. **Документы:** `LINKS_CHEATSHEET.md`, `LINK_TYPES.md`, `LINK_TYPES_RU.md`, `GRAPH3D.md`,
   `CONFIGURATION_EN.md`, `CONFIGURATION_RU.md`.

## Чего не делать

- `parent` и `child` не трогать — их переносит ORIGIN-1.
- Стрелки у связей в покое и остальную читаемость не решать: по решению владельца это решается в
  конце, по живому интерфейсу.

## Критерии приёмки

1. Миграция на фикстуре с парами-дубликатами: тип стал `related`, вес сохранён, у дубликата осталась
   одна связь с большим весом — тест.
2. API со старыми `reference` и `custom` сохраняет `related` — тест.
3. Цвет автосвязи не совпадает ни с одним ручным типом, яркость зависит от веса — тест отрисовки.
   Мутация «автосвязь цветом своего типа» — красная.
4. Цепочка `dependency` на фикстуре с ветвлением и циклом: подсвечены ровно узлы цепочки в пределах
   глубины, цикл помечен. Мутация «глубина без предела» — красная.
5. Живьём на стенде: снимки легенды в 2D и 3D и подсвеченной цепочки — в
   `docs/agents/MANUAL_TEST_FEEDBACK.md`.
