# P11-2. Мультиязычная модель эмбеддингов

Постановка для Devin. Источник — журнал проектирования [`P11-1-clustering-design-notes.md`](P11-1-clustering-design-notes.md). Порядок работы: [`../AI_AGENT_PROTOCOL.md`](../AI_AGENT_PROTOCOL.md).

Ставит Claude Code, реализует Devin, проверяет Claude Code на живом тест-стеке.

**Очерёдность:** брать после A-3 и A-1/A-2. Одна ветка — один агент.

## Зачем

Граф двуязычный: заметки пишутся и по-русски, и по-английски. Текущая модель `all-MiniLM-L6-v2` обучена на английском, поэтому семантическая близость русских заметок слабая, а близость между русской и английской заметкой об одном и том же не выражается вовсе.

Это фундамент под кластеризацию (P11-4): там семантика — основной источник рёбер. Делать замену модели после кластеризации нельзя: пришлось бы пересчитывать всё дважды.

Целевая модель — `paraphrase-multilingual-MiniLM-L12-v2`: те же 384 измерения, единое векторное пространство для 50+ языков. «Machine learning» и «машинное обучение» оказываются рядом — это требуемое поведение, а не побочный эффект.

## Что выяснено в коде

Читать до начала: здесь есть неочевидное.

**1. Смена `MODEL_NAME` в compose сама по себе ничего не даст и сломает стек.** Имя модели зашито в пяти местах, и два из них исполняемые:

- `nlp-service/Dockerfile:35` — предзагрузка модели в образ вызовом с литералом `all-MiniLM-L6-v2`;
- `nlp-service/entrypoint.sh:12,14` — проверка каталога `models--sentence-transformers--all-MiniLM-L6-v2` и дозагрузка тем же литералом.

Остальные три — значения по умолчанию: `nlp-service/app/nlp_utils.py:13`, `nlp-service/.env.example:1`, плюс переменные в трёх compose-файлах.

Если поменять только переменную окружения, в образе останется предзагруженной старая модель, а при `HF_HUB_OFFLINE=1` (dev и personal) взять новую будет неоткуда. `lifespan` в `nlp-service/app/main.py:31` при неудачной загрузке бросает `RuntimeError`, то есть контейнер не поднимется вообще.

**2. Регистр в переменных расходится.** `docker-compose.yml:64` и `docker-compose.personal.yml:56` задают `all-MiniLM-L6-V2` с заглавной `V`, `docker-compose.test.yml:65` — строчную, а `entrypoint.sh` сверяется с каталогом в нижнем регистре. Чинится заодно: имя пишется один раз и одинаково.

**3. Размерность сохраняется.** У обеих моделей 384. Миграцию `004_create_note_embeddings_table.up.sql`, тип `vector(384)` в `note_embedding_model.go:13` и тесты с `make([]float32, 384)` трогать не нужно.

**4. Различить векторы двух моделей сейчас нечем.** В `note_embeddings` есть только `note_id`, `embedding`, `updated_at`. При постепенном пересчёте в таблице окажутся векторы из двух несовместимых пространств одновременно, и косинус между ними будет числом без смысла — молча, без единой ошибки в логах. Это главный риск задачи.

**5. Эмбеддинги читают двое.** Монолит — `embedding_repo.go:40` (`FindSimilarNotes`, соединение `note_embeddings` с самой собой). Микросервис — `services/graph-service/internal/db/postgres_client.go:240` (`GetEmbeddings`). Оба должны читать векторы только текущей модели.

**6. Производные от эмбеддингов, которые обесцениваются при пересчёте:**

- `note_recommendations` — предрассчитанные рекомендации (`recommendation_model.go:19`);
- `links.weight` — `linkweight.Recalculator` (`backend/internal/application/linkweight/service.go:38`) записывает в вес любой связи семантическое сходство текстов, так что после смены модели веса связей останутся числами от старой;
- кэш рекомендаций в Redis, TTL 300 секунд.

**7. Образец массовой постановки задач уже есть** — `backend/cmd/cli/main.go`: обходит все заметки, ставит задачи с задержкой, умеет `-dry-run` и увеличенную паузу для партий свыше 1000 заметок. Тип задачи для эмбеддинга — `TypeComputeEmbedding = "compute:embedding"` (`queue/tasks.go:7`), обработчик — `worker.go:112`.

**8. `sentencepiece` в образ уже ставится** (`Dockerfile:26`) — токенизатору XLM-R он нужен, добавлять зависимость не потребуется. Проверить при первом запуске, что токенизатор поднимается офлайн.

**9. Индекс `ivfflat`** на `note_embeddings` строится по распределению данных. После полной замены содержимого его нужно перестроить, иначе поиск деградирует.

## Что сделать

**Миграция** (`backend/migrations/030_*`)

Добавить в `note_embeddings` колонку с именем модели, которой посчитан вектор. Существующим строкам проставить `all-MiniLM-L6-v2`. Колонка обязательная и без значения по умолчанию на будущее: писать её должен код явно.

**Запись и чтение**

- `EmbeddingRepository.Upsert` записывает имя текущей модели; оно приходит из конфигурации, не из литерала.
- `FindSimilarNotes` отбирает только пары, у которых обе стороны посчитаны текущей моделью.
- `GetEmbeddings` в graph-service — то же условие.
- Имя модели попадает в конфигурацию монолита и graph-service из окружения, единым ключом.

**Образ NLP-сервиса**

- `Dockerfile`: имя модели становится `ARG`/`ENV` со значением по умолчанию `paraphrase-multilingual-MiniLM-L12-v2`, предзагрузка идёт по нему.
- `entrypoint.sh`: и проверка каталога, и дозагрузка используют имя из окружения. Каталог кэша HuggingFace именуется как `models--sentence-transformers--<имя>`.
- Три compose-файла и `.env.example`: одно и то же имя, в одном регистре.

**Пересчёт**

Отдельная команда по образцу `backend/cmd/cli`: обходит заметки, у которых нет вектора текущей модели, и ставит `compute:embedding` партиями с той же логикой задержек. Обязателен `-dry-run`. Команда должна быть перезапускаемой: повторный запуск не должен заново обрабатывать уже пересчитанные заметки.

После пересчёта — перестроение индекса `ivfflat`, очистка `note_recommendations` с постановкой пересчёта, инвалидация кэша рекомендаций в Redis, пересчёт весов связей.

**Предзагрузка модели в host-cache**

`huggingface_cache/` монтируется в контейнер во всех трёх стеках. Новая модель должна оказаться там до старта dev- и personal-стека, где `HF_HUB_OFFLINE=1`. Тестовый стек работает с `HF_HUB_OFFLINE=0` и дотянет сам.

**Тесты**

- Юнит-тест на то, что вектор пишется с именем модели и что чтение отсекает чужую модель. Это главная защита от смешивания пространств: без неё задача не принимается.
- Проверить `nlp-service/tests/` на предмет привязки к старой модели.
- Прогнать канонический регрессионный цикл.

## Чего не делать

- Не менять размерность вектора и схему `vector(384)`.
- Не трогать извлечение ключевых слов и YAKE — это отдельная постановка P11-3.
- Не калибровать пороги рекомендаций (`recommendation.alpha/beta/gamma`, семантические отсечки). Числа под новую модель подбираются отдельно, после замеров на живых данных.
- Не удалять старые векторы до того, как новые посчитаны: колонка модели позволяет им сосуществовать, и откат должен оставаться возможным.

## Критерии приёмки

1. Стек поднимается при `HF_HUB_OFFLINE=1` без обращения в сеть; `/health` отвечает `model_loaded: true`.
2. `/embed` возвращает 384 числа и для русского, и для английского текста.
3. Кросс-языковая близость подтверждена численно: сходство пары «машинное обучение» / «machine learning» существенно выше, чем у пары несвязанных текстов на разных языках. Конкретные числа приводятся в отчёте, а не «работает».
4. В выдаче похожих заметок не участвует ни один вектор чужой модели — подтверждается тестом, а не осмотром.
5. Пересчёт отработал на всех заметках тестового стека; рекомендации после пересчёта не пустые.
6. Канонический регрессионный цикл зелёный по-честному, с учётом правок A-3.
