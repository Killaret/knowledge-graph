## Живая проверка конвейера (тест-стек, `SKIP_AUTH=false`)

`POST /import/bookmarks/preview` и `/import/bookmarks` реальным токеном:

| Проверка | Результат |
|---|---|
| `extract_content:true` тянет реальную страницу | title «Example Domain», text 127 байт — фетчер, декодирование, извлечение работают |
| 51 элемент в preview | **400** (`max 50`) |
| 50 элементов | **200** |
| создание через `/import/bookmarks` | **202** + `task_id` (асинхронно) |

Граница в 50 — ровно то, вокруг чего фронтенд бьёт список на пачки
(`MAX_IMPORT_BATCH_SIZE`). Раньше >50 молча падало «too many items»; теперь фронтенд
чанкует, а бэкенд честно отвечает 400 на переполнение одной пачки.

## Чего НЕ делал и почему

Точный сценарий из постановки — реимпорт 13 склеенных URL с animego.me и securitylab.ru,
ожидание `created 13, failed 0` — **не воспроизводил**. Ассертить «13 создано» против
живого стороннего контента недетерминированно: сайт может лечь, отдать иную кодировку,
сменить разметку — и тест станет флапать не по нашей вине. Детерминированные части этого
сценария (разделение склейки, декодирование windows-1251, рунное усечение заголовка
>200 байт) закрыты юнит-тестами и мутациями выше. Сам реимпорт своих закладок — ручная
проверка рабочего потока, её уместнее провести владельцу интерактивно; свидетельство —
в `MANUAL_TEST_FEEDBACK.md`.

## Мелочь

`extract_content` по умолчанию `false` — без него preview не ходит в сеть и `text`
пустой. Это разумный дефолт (быстрый preview), но в `docs/API_EN.md` стоит отметить: без
`options.extract_content:true` заметка создаётся с пустым телом. Не блокер.
