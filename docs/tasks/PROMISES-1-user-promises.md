# PROMISES-1. Обещания пользователю — каталог и сквозные тесты

Статус: **бэклог — Devin, в составе 1.0.** Постановка — Claude Code, 2026-09-26, по просьбе владельца.
Первая из двух привычек, которые владелец принял: каждое требование — с проверяемым критерием, а
ключевые обещания пользователю — сквозными тестами.

## Почему

- **Синхронизация графа (SYNC-1).** Каждая деталь проходила свои тесты, а целое не работало ни разу:
  удаления не доходили до клиента, импорт не давал событий. Теста на обещание «изменил — граф сошёлся»
  не было.
- **Постепенная загрузка (UI-LOAD-1).** Её потеряли при переписывании, и ни один тест этого не
  заметил.

## Что сделать

1. **Каталог `docs/product/USER_PROMISES.md`** — около десятка обещаний языком пользователя. У каждого
   обещания:
   - номер (`P-01` …);
   - условие, действие, ожидаемое;
   - срок («за N секунд»);
   - имя теста, который его держит.

   Предложение для начала, состав утверждает владелец:

   | № | Обещание |
   |---|---|
   | P-01 | заметка, созданная вручную, появляется в списке и на графе |
   | P-02 | импортированная закладка появляется на графе с названием страницы и её структурой |
   | P-03 | автосвязи к новой заметке появляются на открытом графе без перезагрузки (после SSE из SYNC-1) |
   | P-04 | переименование видно на графе без перезагрузки |
   | P-05 | удалённая заметка и удалённая связь исчезают с графа без перезагрузки |
   | P-06 | заметки доступны — список, поиск, открытие — до того, как загрузился граф |
   | P-07 | поиск находит заметку по слову из названия и из текста |
   | P-08 | ручная связь поверх автосвязи сохраняет происхождение |
   | P-09 | бэкап и восстановление возвращают все заметки и связи (на тест-стенде) |
   | P-10 | выключенная функция ничего не пишет (пример — `nlp.quality.enabled = false`) |

2. **Сквозной тест на каждое обещание:** Playwright и API против тест-стенда, метка `@promise`.
   Запускается в CI на PR; если прогон окажется слишком долгим — в регрессионном цикле, решает
   владелец.
3. **Сторож:** читает каталог и падает, если у обещания нет теста или тест пропущен.

## Критерии приёмки

1. Каталог есть, у каждого обещания — существующий тест.
2. На трёх обещаниях на выбор: поведение ломается — тест краснеет. Мутации записаны в сдаче.
3. Сторож с фикстурой «обещание без теста» — красный.
4. Тесты `@promise` идут в CI или в регрессионном цикле по решению владельца.
5. RELEASE-TEST-1 ссылается на каталог: автоматические обещания — основа ручного прогона выпуска.
