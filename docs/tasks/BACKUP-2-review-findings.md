# BACKUP-2 — разбор ревью

Ревьюер: Claude Code. Дата: 2026-09-21. Реализация: Devin, `b7070c8` (+ `9979b1f`, изоляция теста).
Постановка: [`BACKUP-2-backup-location-single-source.md`](BACKUP-2-backup-location-single-source.md).

**Вердикт: принято.** Три потребителя дают один вердикт на одних данных во всех состояниях,
`.sh` починен, хук в плохих состояниях отказывает. Одна мелочь и одно наблюдение для владельца.

## Матрица мутаций — временный каталог через `KG_BACKUP_DIR`, боевая папка не тронута

| Состояние | `check-personal-backup.ps1` | `.sh` | хук на `docker volume rm pgdata_personal` |
|---|---|---|---|
| каталог пуст | ERROR, каталог назван | то же | **deny** |
| свежий непустой файл | PASS, файл назван | то же | allow |
| свежий нулевой + старший непустой | PASS по непустому | то же | allow |
| только нулевой файл | ERROR «no non-empty backup» | то же | **deny** |
| файл старше 24 ч (mtime сдвинут) | ERROR, возраст назван | то же | **deny** |
| каталога нет | ERROR «No backup directory» | то же | **deny** |

Первый прогон матрицы показал у хука «0» во всех строках — потому что хук пишет решение в
JSON на stdout (`permissionDecision: deny`) и выходит с нулём всегда; мой замер читал код
выхода. Перемерено по stdout. Урок тот же, что и всегда: сначала узнай, как инструмент
сообщает результат.

Набор хука: `python scripts/devops/test_guard_personal_data.py` → 39 проверок зелёные
(это не pytest — `pytest -q` собирает ноль тестов, что можно принять за отсутствие тестов).

## Критерии приёмки

| # | Критерий | Вердикт | Чем проверен |
|---|---|---|---|
| 1 | Каталог задан в одном месте, ни у кого нет своей копии пути | проверен, с оговоркой | `KG_BACKUP_DIR=Desktop/my items` в `backup-policy.env`; `grep` по шести потребителям — единственная копия в `docker-compose.personal.yml:259` как умолчание `${KG_BACKUP_DIR:-C:/Users/89209/Desktop/my items}`. Постановка это допускала: compose не разворачивает `~` |
| 2 | Три проверки на одних данных — один вердикт | проверен | матрица выше, шесть состояний |
| 3 | Пять мутаций отработали, вывод приложен | проверен | шесть, вывод выше |
| 4 | `.sh` при полном каталоге не говорит «No backup directory» | проверен | на боевой папке: `Newest backup … is 120.2 h old; allowed: 24 h` — тот же вердикт, что у `ps1` |
| 5 | `check-all` зелёный, тесты хука проходят | тесты хука — да; `check-all` — в конце сессии | |

## Мелочь

Умолчание в compose (`C:/Users/89209/Desktop/my items`) и значение политики (`Desktop/my items`)
— одно место в двух записях. Разъедутся, если владелец переедет с `C:`. Это ограничение compose,
не дефект; заметка в `docs/operations/BACKUP.md` о том, что при смене каталога править два места, снимает риск.

## Наблюдение для владельца — не про задачу

На боевой папке свежайший бэкап `backup-personal-daily-2026-09-16-113454.sql.gz`, **120 часов**.
Ежедневный планировщик с 16-го не отработал ни разу — Personal-стек, судя по всему, не поднят.
Сторож делает своё: разрушающие команды заблокированы. Но самого бэкапа пять дней нет.

## Принято без замечаний

- Разбор `REPO_ROOT` в `.sh` починен — тот дефект с `(A || B) && C`, из-за которого скрипт не
  работал никогда.
- Тесты хука изолированы через временный `KG_BACKUP_DIR` (`9979b1f`) — набор не зависит от
  содержимого боевой папки.
- Сообщения всех трёх называют каталог, файл и возраст.
