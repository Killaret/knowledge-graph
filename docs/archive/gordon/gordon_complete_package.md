## 💡 Key Concepts Explained

### Why 180 seconds for NLP startup?
- Real startup time: ~100-120s (measured)
- Network buffer: +60s (for slow connections)
- Safe timeout: 180s (3 minutes, allows margin)
- Before: 600s (10 minutes) = excessive waiting

### Connection Pool Formula
- `(cpu_cores × 4) + 2`
- 8 cores → 34 connections → use 50 (safety)
- Why ×4? Each request may hold a connection
- Why +2? Burst traffic margin

### Kubernetes Probes
- **Startup:** 180s initial (full model load)
- **Liveness:** 30s after startup (is it still alive?)
- **Readiness:** 60s after startup (can we send traffic?)
