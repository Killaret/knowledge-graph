# Ревью процесса: верификация, визуальные тесты, работа агентов

Рабочий документ. Разбор того, как в проекте устроена проверка изменений, почему цикл правок по графу не сходится, и что с этим делать. Дополняет `AI_ECOSYSTEM_REVIEW.md`, который разбирает инструкции и обвязку агентов.

Дата: 2026-09-05. Ветка `feat/2d-adaptive-fog`, коммит `9ee17b1`.

## 1. Главное

Механизм визуальной регрессии на 3D-графе **не измеряет 3D-граф**. Скриншот снимается раньше, чем сцена успевает отрисоваться, поэтому изображение не меняется, что бы ни правили в коде. Наблюдение «снимки одинаковые, хотя должно быть разное» — не сбой Argos, а прямое следствие того, как написан тест.

Ниже — цепочка целиком, от теста до CI.

## 2. Находки по цепочке верификации

### P-1 (критично). Скриншот 3D снимается до рендера сцены

`frontend/tests/visual/visual-regression.spec.ts:141`

```ts
test("3D Graph - renders 3D view", async ({ page }) => {
  await page.goto("/graph/3d" + STABLE_RENDER);
  const viewer = page.locator('[data-testid="graph-3d-viewer"]');
  await expect(viewer).toBeVisible({ timeout: 15000 });
  await argosScreenshot(page, "3d-graph-view", { fullPage: true });
});
```

`data-testid="graph-3d-viewer"` висит на внешнем контейнере `Graph3DViewer.svelte:74`, который рендерится сразу при монтировании — до проверки WebGL, до динамического импорта `Graph3DScene.svelte`, до создания движка и до первого кадра. Тест дожидается появления обёртки и немедленно снимает кадр.

Сравните с 2D, где сделано правильно (`waitForGraph` в том же файле):

```ts
const canvas = page.locator('[data-testid="graph-canvas"][data-test-stable="true"]');
await canvas.waitFor({ timeout: 15000 });
```

Атрибут выставляется в `GraphCanvas.svelte:256` после сходимости симуляции. Для 3D аналога нет вообще — ни `data-test-stable`, ни ожидания коллбэка `onReady`, который в компоненте есть и тестами не используется.

**Следствие:** baseline в Argos для `3d-graph-view` — это снимок состояния загрузки. Правки материалов, тумана, камеры, масштаба узлов в него не попадают. Диффа нет, потому что нечему меняться.

### P-2 (критично). `stableRender` в 3D не поддержан, а признак теста определён неверно

`?stableRender=true` обрабатывается только в 2D (`GraphCanvas.svelte:176-180`). В 3D-ветке этого параметра нет: анимация, вращение камеры и переходы тумана продолжают идти во время съёмки.

Отключение анимации в 3D завязано на другое условие — `Graph3DScene.svelte:33`:

```ts
const isTest = typeof process !== "undefined" && process.env?.VITEST === "true";
```

Это признак Vitest, то есть unit-окружения. В браузере под Playwright `process` не определён, `isTest` всегда `false`, `disableAnimation` не включается, `simulateToStable()` не вызывается. Механизм детерминизма, заложенный в движке (`engine.ts:133`), в E2E не срабатывает ни разу.

### P-3. Визуальная регрессия не запускается на PR

Джоба `visual-regression` объявлена в `.github/workflows/main.yml`, триггер которого — `push` в `main`. На PR (`ci.yml`) выполняются core-checks, конфиг, compose и smoke, визуальных проверок нет. То есть визуальный контроль происходит уже **после** слияния.

### P-4. Документация описывает не тот сценарий, который реализован

`docs/ARGOS.md` в списке сценариев указывает для 3D:

> **3D Graph** — Frozen notice redirect to 2D graph

В коде теста ничего подобного нет — там `renders 3D view` со скриншотом `/graph/3d`. Агент, читающий `ARGOS.md`, чтобы понять покрытие, получит неверную картину.

### P-5. Тег `@3d` исключён из прогонов, но им не помечен ни один тест

`playwright.config.ts`, проект `chromium-skip-auth`: `grepInvert: /@3d|@visual|@auth-real|@manual|@canvas/`. При этом поиск по `frontend/tests` не находит ни одного теста с тегом `@3d`. Исключение написано, исключать нечего: сквозного покрытия 3D не существует, кроме нерабочего визуального теста из P-1.

### P-6. Пять осиротевших каталогов эталонов

В `frontend/tests` лежат снапшот-каталоги без соответствующих спеков:

| Каталог | Файлов | Спек |
|---|---|---|
| `graph-visual.spec.ts-snapshots` | 9 | удалён |
| `graph-visual-mock.spec.ts-snapshots` | 9 | удалён |
| `graph-visual-isolated-new.spec.ts-snapshots` | 9 | удалён |
| `graph-visual-isolated.spec.ts-snapshots` | 1 | удалён |
| `graph-simple.spec.ts-snapshots` | 1 | удалён |

29 файлов эталонов, которые ни с чем не сравниваются. Косвенно показывает, что визуальные тесты по графу переписывались минимум четыре раза.

### P-7. WebGL в headless-CI не гарантирован

`Graph3DViewer.svelte:43` при недоступности WebGL показывает оверлей ошибки вместо сцены. В `visual-regression` браузер ставится как `npx playwright install --with-deps chromium` на ubuntu-раннере без GPU-флагов. Если WebGL не поднимется, тест из P-1 всё равно пройдёт: обёртка видима, скриншот снят — просто на нём будет сообщение об ошибке. Отличить это от нормы по зелёному CI невозможно.

### P-8. Базовая ветка сравнения — `ai-agents`

`ARGOS_REFERENCE_BRANCH: ai-agents` в `main.yml`, при том что работа ведётся в `feat/*` от `main`. Стоит проверить, что baseline не устарел относительно текущего состояния UI.

Свидетельств до/после не остаётся, регрессия ловится только следующим ручным проходом.

## 4. Инструкции агентов

Подробности в `AI_ECOSYSTEM_REVIEW.md`. Здесь — то, что влияет на процесс:

- `.windsurfrules` — 460 строк, единственная точка входа, включает раздел «Current handler decoupling status» со списком конкретных файлов. Такой список устаревает быстрее остальных правил и тянет за собой весь документ.
- Нормативные факты продублированы: команды тестов в 16 файлах, версии стека в 8, правило сохранности томов в 10. Проверки согласованности нет.
- `docs/AGENTS.md` и `docs/AGENTS_EN.md` — разные по составу документы, а не перевод.
- Роль Claude Code не заведена; `CLAUDE.md` и `.claude/` отсутствуют.
- Кастомные скиллы (`ux-principles`, `analytics-product-analysis`) принадлежат другому проекту (`C:\avanpost\`), все ссылки в них ведут наружу, и они недоступны Devin, поскольку хранятся вне репозитория.

## 5. Что делать

Порядок по убыванию отдачи.

**Шаг 1. Починить сигнал готовности 3D.** Пробросить `stableRender` в 3D-ветку, заменить `isTest` на признак, работающий в браузере, выставлять `data-test-stable` на контейнере сцены после `simulateToStable()` и первого кадра, а тест переписать на ожидание этого признака и съёмку элемента сцены вместо `fullPage`. Без этого шага дальнейшие визуальные проверки бессмысленны.

**Шаг 2. Пересобрать baseline** после шага 1 — текущий эталон непригоден.

**Шаг 3. Перенести визуальную регрессию на PR** — отдельной джобой в `ci.yml` или через `workflow_call`, чтобы дифф был виден до слияния.

**Шаг 4. Диагностика WebGL в CI.** Явная проверка, что контекст создан, с падением теста при оверлее ошибки — иначе зелёный прогон ничего не гарантирует.

**Шаг 5. Покрытие 3D сквозными тестами** под тегом `@3d` и отдельным проектом Playwright, который их действительно запускает.

**Шаг 6. Гигиена.** Удалить 29 осиротевших эталонов, привести `ARGOS.md` в соответствие с реальными сценариями.

**Шаг 7. Фиксация свидетельств.** В `MANUAL_TEST_FEEDBACK.md` поле «Screenshot / Logs» должно заполняться — единственный способ отличить «починили» от «показалось».

**Шаг 8. Обвязка агентов** — протокол взаимодействия, `CLAUDE.md`, `.claude/`, сведение таблиц ролей, проектные скиллы. По приоритету ниже, чем цепочка верификации: она сейчас стоит дороже.
