# Руководство по тестированию

Этот документ описывает инфраструктуру тестирования и процедуры для Knowledge Graph.

## Обзор

Knowledge Graph использует три Docker-стека:
- **Dev-стек** (docker-compose.yml) - Среда разработки (порты 3000/8080)
- **Personal-стек** (docker-compose.personal.yml) - Персональная среда (порты 3001/8082)
- **Test-стек** (docker-compose.test.yml) - Изолированная среда тестирования (порты 3002/8083)

## Тестовый стек

Тестовый стек полностью изолирован от dev и personal стеков:
- Отдельная база данных PostgreSQL (knowledge_test)
- Отдельный экземпляр Redis
- Отдельный экземпляр MongoDB
- Отдельный NLP-сервис
- Отдельные контейнеры backend и frontend
- Отдельные тома (test_postgres_data, test_mongodb_data)

### Сервисы

| Сервис | Имя контейнера | Порт | Назначение |
|--------|---------------|------|-----------|
| postgres-test | kg-test-postgres | 5434 | Тестовая база данных |
| redis-test | kg-test-redis | 6381 | Тестовый кэш/очередь |
| mongo-test | kg-test-mongo | 27018 | Тестовые черновики |
| nlp-test | kg-test-nlp | 15002 | Тестовый NLP-сервис |
| backend-test | kg-test-backend | 8083 | Тестовый backend API |
| frontend-test | kg-test-frontend | 3002 | Тестовый frontend |

### Конфигурация

- **SKIP_AUTH: true** - Аутентификация отключена для тестирования
- **REDIS_FLUSH_ON_STARTUP: true** - Redis очищается при запуске
- **База данных: knowledge_test** - Отдельная тестовая база данных

### URL тестового стека

- **Frontend:** http://localhost:3002
- **Backend API:** http://localhost:8083

## Скрипты автоматизированного тестирования

### check-stacks-health
Проверяет здоровье dev и personal стеков.

**Windows:**
```powershell
.\scripts\check-stacks-health.ps1
```

**Linux/Mac:**
```bash
./scripts/check-stacks-health.sh
```

**Проверки:**
- Dev-контейнеры запущены
- Health-эндпоинт dev (http://localhost:8080/health)
- Dev API (http://localhost:8080/api/v1/notes?limit=1)
- Personal-контейнеры запущены
- Health-эндпоинт personal (http://localhost:8082/health)
- Personal API (http://localhost:8082/api/v1/notes?limit=1)

### start-test
Запускает изолированный тестовый стек.

**Windows:**
```powershell
.\scripts\start-test.ps1
```

**Linux/Mac:**
```bash
./scripts/start-test.sh
```

**Действия:**
- Останавливает и удаляет предыдущий тестовый стек (с томами)
- Собирает и запускает тестовый стек
- Ожидает, пока все контейнеры станут здоровыми
- Отображает URL тестового стека

### stop-test
Останавливает и уничтожает тестовый стек.

**Windows:**
```powershell
.\scripts\stop-test.ps1
```

**Linux/Mac:**
```bash
./scripts/stop-test.sh
```

**Действия:**
- Останавливает тестовый стек
- Удаляет тома (полная очистка)

### seed-test-data
Загружает тестовые данные в тестовую базу данных.

**Windows:**
```powershell
.\scripts\seed-test-data.ps1
```

**Linux/Mac:**
```bash
./scripts/seed-test-data.sh
```

**Создаёт:**
- Тестового пользователя (логин: testuser, пароль: TestPassword123!)
- 5 тестовых заметок (star, planet, comet, galaxy, asteroid)
- 2 тестовые связи между заметками

### check-stacks-identity
Проверяет идентичность dev, personal и test стеков.

**Windows:**
```powershell
.\scripts\check-stacks-identity.ps1
```

**Linux/Mac:**
```bash
./scripts/check-stacks-identity.sh
```

**Проверки:**
- Версии сервисов (Go, Node, Python)
- Docker-compose файлы
- Конфигурационные файлы
- Nginx конфигурации
- Health эндпоинты

### run-full-test-cycle
Оркестрирует полный цикл тестирования.

**Windows:**
```powershell
.\scripts\run-full-test-cycle.ps1
```

**Linux/Mac:**
```bash
./scripts/run-full-test-cycle.sh
```

**Шаги:**
1. Проверка здоровья dev и personal стеков
2. Проверка идентичности стеков
3. Запуск тестового стека
4. Загрузка тестовых данных
5. Отображение инструкций для ручного тестирования
6. Ожидание ручного тестирования (нажмите Enter)
7. Остановка тестового стека
8. Повторная проверка здоровья dev и personal стеков
9. Отображение сводки

## Ручное тестирование

### Тестовое окружение

После запуска тестового стека получите доступ к тестовому окружению по адресу:
- **Frontend:** http://localhost:3002
- **Backend API:** http://localhost:8083

### Учётные данные тестового пользователя

- **Логин:** testuser
- **Пароль:** TestPassword123!

### Чек-лист ручного тестирования

Следуйте чек-листу ручного тестирования в `docs/MANUAL_TEST_CHECKLISTS_RU.md` для детальных процедур тестирования.

### Покрытие ручного тестирования

Чек-лист ручного тестирования покрывает:
- **Предварительная настройка** - Проверки здоровья стеков, запуск тестового стека, загрузка данных
- **Smoke-тесты** - Публичный доступ, аутентификация, профиль, граф, создание заметки, выход
- **Проверка публичного графа** - Создание публичных заметок/связей, доступ к API без аутентификации, публичный доступ во фронтенде
- **Функции Canvas** - Призрачный узел, чёрная дыра, связи перетаскиванием, горячие клавиши, tooltips, индикаторы новых
- **Карточки заметок** - Визуальный стиль, пакетные операции, отмена, сортировка, стиль dust, tooltips карточек
- **Общий UX** - Galactic Lexicon, консоль браузера, переключение языка
- **Очистка после тестирования** - Уничтожение тестового стека, проверка здоровья стеков, сообщение о дефектах

## Проверка идентичности стеков

Скрипт `check-stacks-identity` проверяет, что dev, personal и test стеки консистентны:

- Версии сервисов (Go, Node, Python)
- Docker-compose конфигурации
- Конфигурационные файлы
- Nginx конфигурации
- Health эндпоинты

Запуск вручную:
```bash
./scripts/check-stacks-identity.sh  # Linux/Mac
./scripts/check-stacks-identity.ps1  # Windows
```

Эта проверка автоматически выполняется во время полного цикла тестирования.

## Изоляция тестовых данных

Тестовый стек обеспечивает полную изоляцию:
- Отдельная база данных (knowledge_test vs knowledge_base/knowledge_personal)
- Отдельные тома (test_postgres_data vs postgres_data)
- Отдельные имена контейнеров (kg-test-* vs kg-*)
- Отдельные порты (3002/8083 vs 3000/8080 и 3001/8082)

## Очистка

После тестирования всегда запускайте скрипт очистки для обеспечения полной изоляции:

```powershell
.\scripts\stop-test.ps1
```

или

```bash
./scripts/stop-test.sh
```

Это обеспечивает:
- Тестовые контейнеры остановлены
- Тестовые тома удалены
- Нет утечки данных в dev/personal стеки

## Устранение неполадок

### Ошибка 502 dev-стека (ИСПРАВЛЕНО)

**Проблема:** Dev nginx возвращает 502 Bad Gateway для API-запросов

**Корневая причина:** Некорректные имена контейнеров в nginx.conf

**Исправление:** Обновлён nginx.conf с правильными именами контейнеров (kg-backend, kg-frontend, kg-graph-service)

**Проверка:**
```bash
curl http://localhost:8080/health
curl http://localhost:8080/api/v1/notes?limit=1
```

**Статус:** ✅ Решено - Dev API теперь доступен

### Тестовый стек не запускается

**Проверьте Docker:**
```bash
docker ps
docker compose -f docker-compose.test.yml ps
```

**Проверьте логи:**
```bash
docker compose -f docker-compose.test.yml logs
```

**Общие проблемы:**
- Конфликты портов (3002, 8083, 5434, 6381, 27018, 15002)
- Docker Desktop не запущен
- Недостаточно ресурсов

### Неудачная загрузка тестовых данных

**Проверьте здоровье backend:**
```bash
curl http://localhost:8083/health
```

**Проверьте API:**
```bash
curl http://localhost:8083/api/v1/notes
```

**Общие проблемы:**
- Backend не готов
- Проблемы с сетью
- Некорректные тестовые данные

### Dev/personal стеки затронуты

**Проверьте изоляцию:**
```bash
docker ps --filter "name=kg-"
```

**Проверьте наличие тестовых контейнеров:**
```bash
docker ps --filter "name=kg-test"
```

**Если тестовые контейнеры существуют:**
```bash
docker compose -f docker-compose.test.yml down -v
```

## Лучшие практики

1. **Всегда проверяйте здоровье стеков перед тестированием** - Обеспечивает стабильность dev/personal стеков
2. **Используйте скрипт полного цикла тестирования** - Автоматизирует весь процесс
3. **Очищайте после тестирования** - Предотвращает утечку данных
4. **Проверяйте изоляцию** - Убедитесь, что тестовый стек не влияет на dev/personal
5. **Документируйте проблемы** - Используйте секцию сообщения о дефектах в ручном чек-листе

## Интеграция CI/CD

Тестовый стек может быть интегрирован в пайплайны CI/CD:

```yaml
- name: Запуск тестового стека
  run: ./scripts/start-test.sh

- name: Загрузка тестовых данных
  run: ./scripts/seed-test-data.sh

- name: Запуск тестов
  run: npm run test

- name: Остановка тестового стека
  run: ./scripts/stop-test.sh
```
