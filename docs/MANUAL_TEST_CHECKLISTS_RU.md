# Чек-листы ручного тестирования

Этот документ содержит чек-листы для ручной проверки функциональности Knowledge Graph.

## Предварительная настройка

### Проверка здоровья стеков
- [ ] Запустите `scripts/check-stacks-health.ps1` (Windows) или `scripts/check-stacks-health.sh` (Linux/Mac) → Скрипт проверки здоровья выполняется и сообщает статус
- [ ] Проверьте, что dev-стек здоров (http://localhost:8080/health) → Dev-стек возвращает статус "healthy"
- [ ] Проверьте, что personal-стек здоров (http://localhost:8082/health) → Personal-стек возвращает статус "healthy"
- [ ] Проверьте доступность dev API (http://localhost:8080/api/v1/notes?limit=1) → Dev API возвращает корректный ответ
- [ ] Проверьте доступность personal API (http://localhost:8082/api/v1/notes?limit=1) → Personal API возвращает корректный ответ
- [ ] Если какая-либо проверка не прошла, запустите соответствующий стек перед продолжением → Затронутый стек становится здоровым

### Запуск тестового стека
- [ ] Запустите `scripts/start-test.ps1` (Windows) или `scripts/start-test.sh` (Linux/Mac) → Контейнеры тестового стека запускаются и становятся здоровыми
- [ ] Подождите, пока все контейнеры станут здоровыми → Все контейнеры показывают статус "healthy"
- [ ] Проверьте готовность тестового стека (http://localhost:3002) → Frontend загружается успешно
- [ ] Проверьте доступность тестового backend API (http://localhost:8083) → API возвращает корректные ответы

### Загрузка тестовых данных
- [ ] Запустите `scripts/seed-test-data.ps1` (Windows) или `scripts/seed-test-data.sh` (Linux/Mac) → Скрипт создания тестовых данных выполняется успешно
- [ ] Проверьте регистрацию тестового пользователя (логин: testuser, пароль: TestPassword123!) → Пользователь может войти с этими учётными данными
- [ ] Проверьте создание 5 тестовых заметок (star, planet, comet, galaxy, asteroid) → Заметки появляются в системе с правильными типами
- [ ] Проверьте создание 2 тестовых связей между заметками → Связи видны на графе, соединяющие заметки

### Быстрый старт (полный цикл)
- [ ] Запустите `scripts/run-full-test-cycle.ps1` (Windows) или `scripts/run-full-test-cycle.sh` (Linux/Mac) → Скрипт автоматически выполняет полный цикл тестирования
- [ ] Это автоматически: проверит здоровье стеков, запустит тестовый стек, загрузит данные, дождётся ручного тестирования, уничтожит тестовый стек, снова проверит здоровье стеков → Все шаги завершаются без ошибок

## Smoke-тесты

- [ ] Нажмите кнопку "Login" → Появляется форма входа с полями username/password

- [ ] Проверьте работу базовых взаимодействий с графом → Масштабирование, панорамирование и выбор узлов работают корректно

### Создание заметки

### Выход из системы

## Проверка связей на публичном графе

### Создание публичных заметок (без аутентификации)
- [ ] Откройте http://localhost:3002 в браузере → Canvas загружается без аутентификации
- [ ] Используйте API для создания публичной заметки: `POST http://localhost:8083/api/v1/notes` с `{"title": "Public Test", "content": "Test content", "is_public": true}` → Заметка создана успешно (201)
- [ ] Проверьте появление заметки на публичном графе → Новый узел виден на canvas без входа в систему

### Создание публичных связей (без аутентификации)
- [ ] Создайте две публичные заметки через API → Обе заметки созданы успешно
- [ ] Создайте связь между ними: `POST http://localhost:8083/api/v1/links` с `{"source_id": "...", "target_id": "...", "type": "related"}` → Связь создана успешно (201)
- [ ] Проверьте появление связи на публичном графе → Ребро видно между узлами на canvas

### Проверка доступа к API без аутентификации
- [ ] Вызовите `GET http://localhost:8083/api/v1/graph` без заголовка Authorization → Возвращает данные публичного графа (200)
- [ ] Вызовите `GET http://localhost:8083/api/v1/notes?is_public=true` без аутентификации → Возвращает только публичные заметки (200)
- [ ] Проверьте недоступность приватных заметок → Приватные заметки исключены из ответа

### Проверка публичного доступа во фронтенде
- [ ] Загрузите http://localhost:3002 в режиме инкогнито/приватного окна → Canvas загружается с публичным графом
- [ ] Проверьте видимость только публичных узлов/рёбер → Приватный контент не отображается
- [ ] Попробуйте получить доступ к защищённым маршрутам (например, профиль) → Перенаправление на вход или ошибка 401

## Функции Canvas

### Создание призрачного узла
- [ ] Кликните на пустую область canvas / используйте горячую клавишу `N` для активации создания призрачного узла → Появляется форма призрачного узла с размытием фона и градиентным стилем
- [ ] Заполните заголовок и подтвердите → Новый узел star/planet появляется на canvas
- [ ] Обновите страницу → Новая заметка сохраняется и продолжает существовать
- [ ] Проверьте наличие бирюзового индикатора/свечения "New" → Бирюзовая обводка/свечение с меткой "New" видна на узле

### Удаление в чёрную дыру (с отменой)
- [ ] Выберите существующий узел заметки → Узел становится выделенным/выбранным
- [ ] Перетащите выбранный узел на аномалию чёрной дыры → Узел исчезает с canvas
- [ ] Проверьте появление toast с действием "Undo" → Toast показывает "Done", затем кнопку "Restore" через 1.5с
- [ ] Нажмите "Undo" и проверьте появление узла → Узел возвращается на предыдущую позицию на canvas
- [ ] Перетащите снова и отклоните toast; проверьте удаление заметки после обновления → Заметка удалена окончательно после отклонения toast
- [ ] Откройте боковую панель заметки и проверьте наличие кнопки "Delete all links" → Кнопка видна в секции управления связями
- [ ] Нажмите "Delete all links" и подтвердите через модальное окно → Появляется модальное окно подтверждения
- [ ] Подтвердите удаление → Все связи удаляются из заметки

### Создание связей перетаскиванием
- [ ] Наведите курсор на исходный узел для отображения возможности создания связи → Маркер связи становится видимым на узле
- [ ] Перетащите маркер связи к целевому узлу → Визуальный предпросмотр связи появляется при перетаскивании
- [ ] Отпустите на целевом узле → Появляется форма связи с улучшенным стилем
- [ ] Заполните тип связи и вес → Форма принимает ввод и валидирует
- [ ] Подтвердите создание связи → Новая связь/ребро рисуется между узлами
- [ ] Попробуйте создать ту же связь снова → Появляется предупреждение/toast "Duplicate link"
- [ ] Обновите страницу → Связь сохраняется и остаётся видимой

### Горячие клавиши
- [ ] Нажмите `N` → Активируется создание призрачного узла
- [ ] Нажмите `F` → Появляется поле поиска/фокуса
- [ ] Нажмите `?` → Открывается модальное окно справки с горячими клавишами
- [ ] Нажмите `Esc` → Любое открытое модальное окно/tooltip закрывается
- [ ] Нажмите `Ctrl+Z` → Отмена последнего действия (если реализовано)
- [ ] Нажмите `Delete`/`Backspace` → Удаление выбранного узла (если реализовано)

### Knowledge Core (техническая заметка)
- [ ] Проверьте, что центральный узел "Knowledge Core" всегда виден → Центральный узел остаётся видимым в любое время
- [ ] Кликните на узел Knowledge Core → Узел становится выбранным
- [ ] Попробуйте перетащить его в чёрную дыру → Узел не может быть удалён через чёрную дыру
- [ ] Наведите курсор на узел → Tooltip показывает системную информацию

### Tooltips
- [ ] Наведите курсор на любой узел → Появляется tooltip с заголовком, типом и кнопками действий
- [ ] Наведите курсор на любую связь → Появляется tooltip с типом связи и весом

### Индикатор "New"
- [ ] Создайте новую заметку → Узел имеет бирюзовую обводку/свечение с меткой "New"
- [ ] Подождите/выполните другое действие → Индикатор исчезает после того, как заметка перестаёт быть "новой"

## Карточки заметок (списочный вид)

### Визуальный стиль
- [ ] Переключитесь на списочный вид → Списочный вид отображается с карточками заметок
- [ ] Проверьте наличие цветной полоски на каждой карточке, соответствующей типу → Цветная полоска соответствует типу заметки (star, planet, comet, galaxy, asteroid)
- [ ] Проверьте отображение иконки типа → Эмодзи/иконка типа появляется в левом верхнем углу
- [ ] Проверьте наличие тонкого свечения/эффекта при наведении → Карточка поднимается и светится при наведении

### Стиль Dust
- [ ] Создайте заметку с типом `dust` → Карточка использует специальный визуальный стиль "dust" (выцветшие частицы/фон пыли)

### Tooltip карточки
- [ ] Наведите курсор на карточку → Tooltip показывает ключевые слова, количество связанных ссылок и кнопки быстрых действий

### Пакетные операции
- [ ] Включите режим выбора → Режим выбора активируется с видимыми чекбоксами
- [ ] Выберите несколько заметок с помощью чекбоксов → Выбранные заметки выделяются
- [ ] Нажмите "Delete selected" → Удаляются только выбранные заметки и появляется toast Undo
- [ ] Проверьте, что toast показывает "Done" сначала, затем "Restore" через 1.5с → Toast переходит от "Done" к кнопке "Restore"
- [ ] Нажмите "Restore" в течение 5с → Заметки снова появляются в списке

### Отмена удаления
- [ ] Удалите заметку из списочного вида → Toast показывает "Done" (Galactic Lexicon) с кнопкой "Restore"
- [ ] Нажмите "Restore" → Заметка снова появляется в списке

### Сортировка
- [ ] Откройте выпадающий список сортировки → Отображаются опции сортировки
- [ ] Сортируйте по дате создания по возрастанию → Заметки упорядочены от старых к новым
- [ ] Сортируйте по дате создания по убыванию → Заметки упорядочены от новых к старым
- [ ] Сортируйте по заголовку А-Я → Заметки упорядочены по алфавиту
- [ ] Сортируйте по заголовку Я-А → Заметки упорядочены в обратном алфавитном порядке
- [ ] Сортируйте по дате обновления → Заметки упорядочены по последним обновлённым
- [ ] Проверьте корректность обновления порядка → Список переупорядочивается немедленно после выбора

### Анимация каскадного появления
- [ ] Загрузите страницу с множеством заметок → Карточки появляются с каскадной анимацией появления, не все сразу

### Пустое состояние
- [ ] Очистите все заметки (или отфильтруйте по несоответствующему запросу) → Отображается дружелюбная иллюстрация/сообщение пустого состояния

## Очистка после тестирования

### Остановка тестового стека
- [ ] Запустите `scripts/stop-test.ps1` (Windows) или `scripts/stop-test.sh` (Linux/Mac) → Тестовый стек уничтожен (контейнеры остановлены и тома удалены)
- [ ] Проверьте отсутствие запущенных тестовых контейнеров (`docker ps --filter "name=kg-test"`) → В списке не появляются тестовые контейнеры

### Проверка здоровья стеков
- [ ] Запустите `scripts/check-stacks-health.ps1` (Windows) или `scripts/check-stacks-health.sh` (Linux/Mac) → Выполняются проверки здоровья dev и personal стеков
- [ ] Проверьте, что dev-стек всё ещё здоров после тестирования → Dev-стек возвращает здоровый статус
- [ ] Проверьте, что personal-стек всё ещё здоров после тестирования → Personal-стек возвращает здоровый статус
- [ ] Проверьте отсутствие утечки данных из тестового стека в dev/personal стеки → Тестовые данные не появляются в dev/personal стеках

### Очистка тестовых данных (если необходимо)
- [ ] Если тестовые данные были созданы в dev/personal стеках, вручную удалите тестовые заметки → Тестовые заметки удаляются из dev/personal стеков
- [ ] Удалите тестового пользователя, если он был создан в dev/personal стеках → Тестовый пользователь удаляется из dev/personal стеков
- [ ] Проверьте отсутствие тестовых артефактов в production стеках → В production стеках не остаются тестовые данные или пользователи

## Сообщение о дефектах

Для каждого неудачного пункта:
- [ ] Зафиксируйте окружение (браузер, стек) → Документируйте версию браузера, ОС и какой стек тестировался
- [ ] Прикрепите скриншот или короткую запись экрана → Захватите визуальное доказательство проблемы
- [ ] Скопируйте соответствующие логи консоли/backend → Сохраните сообщения об ошибках и стеки вызовов
- [ ] Создайте issue со ссылкой на пункт чек-листа → Создайте GitHub issue ссылаясь на конкретный пункт чек-листа, который не прошёл

### Шаблон issue

При создании issue включите:
- **Пункт чек-листа:** Ссылка на конкретную секцию и пункт (например, "Canvas → Создание призрачного узла → Пункт 3")
- **Окружение:** Браузер, ОС, стек (dev/personal/test)
- **Шаги воспроизведения:** Точные выполненные действия
- **Ожидаемый результат:** Что должно было произойти
- **Фактический результат:** Что произошло на самом деле
- **Скриншоты/Логи:** Прикрепите визуальные доказательства и логи ошибок
