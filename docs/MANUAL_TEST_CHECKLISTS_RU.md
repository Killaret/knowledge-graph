# Актуальный чек-лист ручного тестирования

> **Дополнение:** для ветки `ai-agents` / 3D-рефакторинга см. [MANUAL_TEST_CHECKLIST_AI_AGENTS_3D_REFACTOR.md](MANUAL_TEST_CHECKLIST_AI_AGENTS_3D_REFACTOR.md).

**Последнее обновление:** test stack с исправлениями real-auth, auth init race, canvas, hover-delay и ghost-node; добавлен раздел режима real-auth.

**Окружение**

- Frontend: `http://127.0.0.1:3002` (или `FRONTEND_PORT`, если 3002 занят Hyper-V excluded range); на Windows используйте `127.0.0.1` вместо `localhost`, чтобы избежать проблем с `::1`.
- Backend: `http://127.0.0.1:18083`
- Тестовый пользователь: `testuser` / `TestPassword123!`
- Тестовые данные: 100 notes + 60 links (по умолчанию); можно переопределить параметрами `seed-test-data.ps1`
- `hover_delay_ms` в `knowledge-graph.config.json` → `frontend.graph.2d.hover_delay_ms` = 150
- В режиме real-auth фронтенд обращается к бэкенду через same-origin прокси `/api` и `/graph-service/api`; серверный прокси (`frontend/src/hooks.server.ts`) пробрасывает заголовки `Authorization` и `Cookie`, включая HttpOnly auth cookies.
- **Для real-auth тестов стек запускается с `SKIP_AUTH=false`**, и `seed-test-data.ps1` выполняется в том же режиме; иначе заметки создадутся под анонимным владельцем и граф в real-auth режиме окажется пустым.

**Перед стартом**

- [ ] `docker ps` показывает все `kg-test-*` контейнеры healthy.
- [ ] `curl http://127.0.0.1:18083/health` → `{"status":"ok"}`.
- [ ] `curl http://127.0.0.1:3002` → HTTP 200.
- [ ] Открыть DevTools → Network и Console, держать их открытыми во время тестов.

## 3. Canvas Features

**Для создания связей используйте страницу `/graph`**, т.к. на главной (`/`) GraphCanvas не передаёт `onLinkCreate`.

### Hover / затемнение
- [ ] Быстро провести курсором над любой нодой — граф не затемняется.
- [ ] Задержать курсор на ноде ~150 ms — остальные ноды и связи становятся полупрозрачными, появляется подсветка hovered node.
- [ ] Быстро провести курсором над связью — tooltip связи не появляется.
- [ ] Задержать курсор на связи ~150 ms — появляется `LinkTooltip` с типом связи и весом.

### Drag-and-drop создание связи
- [ ] На странице `/graph` нажать на исходную ноду и, не отпуская, повести курсор к целевой ноде.
- [ ] Исходная нода остаётся на месте; появляется preview-линия к курсору или к целевой ноде.
- [ ] Отпустить курсор над целевой нодой — открывается форма создания связи.
- [ ] Заполнить тип и вес, подтвердить — новая связь появляется на графе.
- [ ] Попробовать создать ту же связь снова — появляется предупреждение "Duplicate link".

### Ghost-нода
- [ ] Нажать `N` на `/graph` — открывается форма создания заметки.
- [ ] Заполнить title/content, выбрать тип, создать.
- [ ] Новая нода появляется на графе; в списке `/notes` она тоже появляется.
- [ ] Новая заметка имеет бирюзовое свечение/обводку "New".

### Выбор и удаление нод
- [ ] Кликнуть на ноду — открывается `NoteSidePanel` с деталями.
- [ ] Кликнуть на Knowledge Core — открывается Help/подсказка.
- [ ] Выбрать обычную ноду, нажать `Delete`/`Backspace` — нода удаляется, граф перезагружается.
- [ ] Knowledge Core нельзя удалить.

### Hotkeys
- [ ] `N` — форма создания ghost-ноды.
- [ ] `F` — появляется поисковая панель.
- [ ] `?` — модальное окно справки с hotkeys.
- [ ] `Esc` — закрывает модалки/поиск.
- [ ] `Delete`/`Backspace` — удаление выбранной ноды.
- [ ] `Ctrl+Z` — пока placeholder (должно логировать в консоль).

### Навигация
- [ ] Pan: перетаскивать пустое место canvas.
- [ ] Zoom: колесо мыши.
- [ ] Double-click по пустому месту — zoom in.
- [ ] Поиск: `F`, ввести часть title, `Enter` — камера фокусируется на совпадениях.

### Чёрная дыра (actual behavior)
- [ ] Навести/перетащить ноду на чёрную дыру — она glow'ится.
- [ ] **Известное ограничение:** удаление ноды перетаскиванием в чёрную дыру в текущей сборке не реализовано.

## 4. Карточки заметок (списочный вид)

### Визуал
- [ ] Переключиться на списочный вид на `/`.
- [ ] Карточки отображают title, content, emoji типа, дату.
- [ ] Цветная полоска слева соответствует типу.
- [ ] Новые заметки (< 24h) — бирюзовое свечение/индикатор.
- [ ] Недавно обновлённые (< 1h) — бирюзовый индикатор.
- [ ] Hover на карточке — tooltip с ключевыми словами, количеством связей и быстрыми действиями.
- [ ] При hover карточка приподнимается/светится.
- [ ] Карточки появляются каскадной анимацией.

### Сортировка и фильтрация
- [ ] Сортировка по created (newest/oldest) — порядок меняется.
- [ ] Сортировка по updated — последние обновлённые сверху.
- [ ] Сортировка по типу — группировка по типу.
- [ ] Поиск по title/content фильтрует карточки.
- [ ] Фильтр по типу — остаются только заметки выбранного типа.
- [ ] Пустое состояние (поиск без результатов) — friendly illustration/message.

### CRUD
- [ ] Создать заметку через кнопку/модалку — появляется в списке.
- [ ] Открыть карточку — `NoteSidePanel` с деталями.
- [ ] Редактировать заметку — изменения сохраняются.
- [ ] Удалить карточку — появляется "Done" → "Restore" undo toast (1.5s → 5s).
- [ ] Нажать "Restore" в течение 5s — заметка восстанавливается.

### Пакетные операции
- [ ] Нажать "Select" — чекбоксы на карточках активны.
- [ ] Выбрать несколько заметок.
- [ ] "Select all" — выбираются все видимые.
- [ ] "Delete selected" — confirm dialog, удаляются выбранные.
- [ ] Batch delete не имеет undo toast (это ожидаемо).

### NoteSidePanel / Links
- [ ] Открыть заметку в списке или на графе.
- [ ] Видны связанные заметки.
- [ ] "Delete all links" — confirm modal, все связи заметки удаляются.

## 5. Валидация и пользовательские сообщения об ошибках

### Валидация длины заголовка заметки
- [ ] Открыть форму создания заметки (верхний бар или `N` на `/graph`).
- [ ] Ввести заголовок длиннее 200 символов.
- [ ] **Ожидаемый результат:** фронтенд блокирует отправку формы, показывает ошибку валидации.
- [ ] **Проверка:** индикатор длины показывает `200+/200` и становится красным.
- [ ] **Проверка:** кнопка "Создать" отключена при превышении лимита.
- [ ] **Проверка:** текстовое сообщение об ошибке понятно объясняет лимит (на русском/английском).
- [ ] Проверить в DevTools Network: нет запроса к API при превышении лимита (валидация на фронтенде).

### QuickCaptureWidget (пылинки)
- [ ] Нажать кнопку ✨ или `Ctrl+Shift+N`.
- [ ] Ввести очень длинный текст (>200 символов).
- [ ] **Ожидаемый результат:** заголовок автоматически обрезается до допустимой длины.
- [ ] **Проверка:** пылинка создаётся успешно без ошибки валидации.
- [ ] **Проверка:** заголовок имеет форму "первые 197 символов...".

### Сообщения об ошибках API
- [ ] Попробовать создать заметку с пустым заголовком.
- [ ] **Ожидаемый результат:** фронтенд показывает понятное сообщение об ошибке.
- [ ] **Проверка:** сообщение локализовано (русский/английский в зависимости от настроек).
- [ ] **Проверка:** в DevTools Network есть запрос к API с ошибкой 400/422.
- [ ] **Проверка:** ответ API содержит `VALIDATION_ERROR` и понятное описание поля.
- [ ] **Проверка:** компонент `ApiErrorDisplay` показывает ошибку в удобном виде.

### Ответы API при ошибках валидации
- [ ] Создать заметку с некорректными данными (пустой заголовок).
- [ ] **Проверка:** API возвращает JSON с полями:
  - `code: "VALIDATION_ERROR"`
  - `message: "Invalid input data"`
  - `details: [{ field: "title", reason: "invalid_value", message: "..." }]`
- [ ] **Проверка:** HTTP статус код 422 Unprocessable Entity.
- [ ] **Проверка:** CORS заголовки присутствуют в ответе об ошибке.

### Валидация на бэкенде (fallback)
- [ ] Отключить фронтенд-валидацию (через DevTools или модификацию JS).
- [ ] Попробовать отправить заголовок длиннее 200 символов напрямую через API.
- [ ] **Ожидаемый результат:** бэкенд возвращает ошибку валидации.
- [ ] **Проверка:** ответ API содержит ошибку с полем `title` и ограничением `max`.
- [ ] **Проверка:** сообщение об ошибке понятно описывает лимит (200 символов).

### Пользовательский опыт при ошибках
- [ ] При ошибке валидации форма не закрывается, данные сохраняются.
- [ ] Пользователь может исправить ошибку и повторить отправку.
- [ ] Кнопка закрытия ошибки (`×`) скрывает сообщение.
- [ ] После исправления ошибки сообщение исчезает автоматически.

## 6. Режим real-auth (дополнительно)

> Для проверки JWT-аутентификации запустите test stack с `SKIP_AUTH=false` и выполните `seed-test-data.ps1`.

### Подготовка
- [ ] `docker compose -f docker-compose.test.yml down -v` (убедиться, что старый skip-auth стек удалён).
- [ ] `$env:SKIP_AUTH="false"; .\scripts\testing\start-test.ps1` (Windows) или `SKIP_AUTH=false ./scripts/testing/start-test.sh` (Linux/Mac).
- [ ] `scripts/testing/seed-test-data.ps1` — создаёт `testuser` / `TestPassword123!` и 100 заметок.
- [ ] `curl http://127.0.0.1:18083/health` → `{"status":"ok"}`.
- [ ] `curl http://127.0.0.1:19091/health` → `{"status":"ok","service":"graph-service"}`.

### Проверки real-auth
- [ ] Открыть `http://127.0.0.1:3002` в инкогнито — публичный граф загружается без 401-циклов.
  - До входа одиночный `POST /api/v1/auth/refresh` с кодом `400` является ожидаемым (нет refresh cookie).
- [ ] `GET http://127.0.0.1:19091/api/v1/graph/full` без `Authorization` → `401`.
- [ ] Войти как `testuser` / `TestPassword123!`.
- [ ] После входа на главной (`/`) загружаются заметки `testuser`.
- [ ] В Network запросы к `/api/v1/...` содержат `Authorization: Bearer <token>` или корректный `Cookie` (пробрасывается через SvelteKit proxy).
- [ ] Запросы к `/graph-service/api/v1/graph/full` содержат `Authorization: Bearer <token>` (graph-service в текущей сборке читает только header; cookie пробрасывается, но не используется для авторизации).
- [ ] Переключиться в списочный вид — фильтр по типу оставляет только заметки выбранного типа.
- [ ] Открыть `/graph` — 2D-граф отрисовывает пользовательские ноды.
- [ ] Создать заметку с графа (`N`) — она появляется в списке и на графе.
- [ ] Logout — возврат на публичный вид, приватные заметки не отображаются.
- [ ] Повторный hard refresh (`Ctrl+F5`) после логина не вызывает 401 (cookie с access_token пробрасываются через SvelteKit proxy).

## Известные ограничения в текущей сборке

- **Чёрная дыра:** glow на hover есть, но удаление ноды перетаскиванием в чёрную дыру не реализовано.
- **Перемещение нод:** drag используется для создания связей; свободное перемещение нод по canvas не поддерживается.
- **Ctrl+Z:** placeholder — undo в canvas не реализован.
- **Создание связей на главной (`/`):** GraphCanvas на `/` не получает `onLinkCreate`, поэтому форма связи откроется, но callback не сработает. Для создания связей используйте `/graph`.
- **Real-auth smoke:** до входа в Network может быть один `400` на `/api/v1/auth/refresh` (нет refresh cookie) — ожидаемо. После входа граф может запросить `/api/v1/notes/00000000-0000-0000-0000-000000000001` и получить `404` (default Knowledge Core-нода отсутствует в notes) — не блокирует тестирование.
- **Переход login → `/`:** в момент анимации страницы в DOM может ненадолго появиться два `data-testid="graph-stats"` (фоновый граф `AuthCard` + главный граф); Playwright-тесты используют `.first()`.
