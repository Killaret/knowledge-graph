## Критические проблемы

### 1. Страница /graph показывает только один узел вместо полного графа

**Симптомы:**
- При переходе на `http://127.0.0.1:50070/graph` отображается только один узел
- Запрос к graph-service: `/graph-service/api/v1/graph/note/7e97f6e3-5fd1-4ecc-b798-5e95585fa17f?depth=3&layout=2d` (запрос конкретной ноды)
- Ожидается полный граф через `/graph-service/api/v1/graph/full?limit=100`

**Технические детали:**
- Запрос: `GET http://127.0.0.1:50070/graph-service/api/v1/graph/note/7e97f6e3-5fd1-4ecc-b798-5e95585fa17f?depth=3&layout=2d`
- Статус: 200 OK
- Проблема: страница `/graph` использует endpoint для конкретной ноды вместо полного графа

**Приоритет:** 🔴 Критический  
**Компонент:** `/graph` страница, graph routing

---

### 2. Моргание графа при дельта-обновлениях

### 1. Моргание графа при дельта-обновлениях

**Симптомы:**
- После входа граф пустой 10 секунд, затем появляется
- Периодически пропадает и появляется снова
- В Network видны повторяющиеся запросы к `/graph-service/api/v1/graph/delta?last_hash=...`

**Технические детали:**
- Запрос: `GET http://127.0.0.1:50070/graph-service/api/v1/graph/delta?last_hash=7b226e6f646573223a5b7b226964223a`
- Метод: GET
- Статус: 200 OK
- Проблема: дельта-обновления вызывают полный перерендеринг графа

**Возможные причины:**
- Race condition в PreloadService при применении дельта-обновлений
- Отсутствие debouncing для дельта-запросов
- Некорректная обработка `last_hash` и инкрементальных обновлений в GraphCanvas

**Приоритет:** 🔴 Критический  
**Компонент:** PreloadService, GraphCanvas, graph-service

### 13. Изменение email в профиле не сохраняется

**Симптомы:**
- Изменил email в профиле, метод отработал (API возвращает успех)
- При обновлении страницы возвращается старый email
- Изменения не сохраняются в БД или не подтягиваются из БД

**Анализ кода:**
- Backend handler `UpdateMe` корректно вызывает `u.SetEmail(req.Email)` и `h.repo.Update(ctx, u)`
- Backend repo `Update` сохраняет email: `model.Email = u.Email()` и `r.db.Save(&model)`
- Frontend `ProfileEditor` после сохранения вызывает `updateUserInfo()` который делает `usersApi.getMe()`
- `updateUserInfo()` обновляет `authState.currentUser` из API ответа

**Возможные причины:**
- Проблема с транзакцией в PostgreSQL (commit не выполняется)
- Race condition между `Update` и `getMe()`
- Кэширование где-то в middleware или proxy
- Проблема с test database контейнером

**Приоритет:** 🔴 Критический  
**Компонент:** ProfileEditor, auth store, backend user handler, PostgreSQL

## Известные ограничения (не блокирующие)

- Чёрная дыра: glow на hover есть, но удаление ноды перетаскиванием в чёрную дыру не реализовано
- Перемещение нод: drag используется для создания связей; свободное перемещение нод по canvas не поддерживается

- Переход login → `/`: в момент анимации страницы в DOM может ненадолго появиться два `data-testid="graph-stats"` (фоновый граф `AuthCard` + главный граф)
