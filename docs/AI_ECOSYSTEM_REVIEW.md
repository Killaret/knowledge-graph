Рабочий документ. Инвентаризация и аудит всего, что в репозитории относится к работе AI-агентов: правила, скиллы, промпты, роли, разрешения. Не является нормативным источником — норма остаётся в `.windsurfrules`.

Дата ревью: 2026-09-05. Ветка: `feat/2d-adaptive-fog`.

## 2. Находки

### Критично

**F-1. Разрешения Devin противоречат non-negotiable правилу сохранности данных.**
`.devin/config.local.json` содержит в allowlist `Exec(rm)`, `Exec(rmdir)`, `Exec(del)` без каких-либо ограничений по путям. При этом `.windsurfrules` объявляет удаление томов `pgdata_personal` / `redisdata_personal` / `mongodbdata_personal` недопустимым без явного разрешения и бэкапа. Единственный работающий механизм защиты сегодня — текст в документации, то есть добросовестность модели.

Косвенный признак, что риск не теоретический: `.windsurf/PROTECT.md` с содержимым «Do not delete» — заплатка, которую обычно ставят после инцидента.

### Существенно

**F-2. Claude Code не заведён как агент.**
Нет `CLAUDE.md`, нет `.claude/`. В `.windsurfrules` §AI Tool Usage Policy Claude отсутствует в таблице ролей; в `PROJECT_REVIEW §16` упомянут только как получатель промптов «для обсуждений». Практическое следствие: сессия стартует без проектных правил, каждый раз требуется ручная вставка мастер-промпта, а разрешения на запуск тестов запрашиваются заново.

**F-3. Одна система Cognition описана как два независимых агента.**
`AGENTS_EN.md` содержит отдельные разделы «Windsurf SWE 1.7 Max» (primary implementation agent) и «Devin» (CLI repository agent) с разными зонами ответственности. Windsurf SWE и Devin — продукты одного вендора и по факту одна система с двумя поверхностями. Агент, читающий документ, делает вывод о четырёх участниках вместо трёх и не понимает, кому адресована задача.

**F-4. `AGENTS.md` и `AGENTS_EN.md` — не перевод друг друга, а два разных документа.**
Только в EN: Task Routing, Verification, Language Policy, Inactive Tooling. Только в RU: Instruction Files, Required Workflow. Пересечение частичное, объём отличается в полтора раза. Правка одного файла не отражается во втором и не детектируется ничем.

**F-5. Нормативные факты размножены копированием.**
`go test ./...` встречается в 16 markdown-файлах, версии стека («Go 1.25») — в 8, правило про personal-тома — в 10. Внутри AI-обвязки стек продублирован четырежды: `.windsurfrules`, `SKILL.md`, `MASTER_PROMPT.md`, `MASTER_PROMPT_RU.md`. Механизма проверки консистентности нет ни в CI, ни в хуках. Первый же апгрейд Go или Redis разведёт копии.

### Заметки

**F-6. `.kilo/` противоречит заявленной политике.** Политика прямо перечисляет Continue/Koda среди неиспользуемых инструментов, при этом на диске лежит рабочий конфиг Kilo Code с метаданными о четырёх worktree, созданных в июне 2026 от `main` и `fix/integration-tests`. Сами worktree удалены (`git worktree list` чист), в git ничего не попадает благодаря вложенному `.gitignore`. Расхождение декларации и факта.

**F-7. `.devin/test_permissions.txt` закоммичен** и не несёт нагрузки.

**F-8. `ANALYSIS_PROMPT.md` дублирует семь constraints из `.windsurfrules`,** одновременно требуя его прочитать первым пунктом.

**F-9. Нейтральная норма живёт под вендорским именем.** `.windsurfrules` обязателен для всех агентов, но называется по одному инструменту. Переименование сломает автозагрузку в Windsurf, поэтому менять не предлагается — но каждому новому агенту приходится отдельно объяснять, почему «правила Windsurf» распространяются на него.

## 3. Чего нет вовсе

Роли описаны, протокол — нет. В репозитории отсутствуют:

- описание того, кто ставит задачу, кто исполняет, кто верифицирует и через какой канал агенты обмениваются состоянием;
- правило разграничения одновременной работы двух имплементирующих агентов (ветки, блокировки);
- явный статус `PROJECT_REVIEW_AI_AGENTS.md` как шины состояния — фактически он ею работает, но нигде не сказано, что каждый агент обязан дописать туда результат сессии и прочитать перед началом;
- разграничение по доступу к окружению: какие задачи в принципе неисполнимы для облачного агента (personal-стек, offline HF-кэш, локальные порты, ручные UI-чек-листы);
- технические барьеры под критичными правилами — вся защита текстовая.

## 4. Рекомендации

Порядок отражает приоритет.

1. **Протокол взаимодействия.** Один документ, описывающий петлю «постановка → реализация → верификация → фиксация состояния», разграничение по доступу к окружению и правило веток. Роли переносятся туда из четырёх мест, остальные файлы получают ссылку.
2. **Барьер под F-1.** Ограничить деструктивные команды в разрешениях агентов; для Claude Code — deny-list на `docker volume rm` и `down -v` для personal-стека.
3. **Конфигурация Claude Code.** `CLAUDE.md` как тонкий указатель на `.windsurfrules` без дублирования правил, `.claude/settings.json` с allowlist на тесты, слэш-команды поверх существующих PowerShell-скриптов.
4. **Свести F-3 и F-4.** Объединить строки Cognition в одну, добавить Claude Code, привести RU и EN к одинаковой структуре.
5. **Ограничить дублирование.** Самодостаточными остаются только промпты для агентов без файлового доступа (браузерные чаты); конфиги агентов с доступом к репозиторию ссылаются на норму.
6. **Гигиена.** Удалить `.devin/test_permissions.txt`; определиться со статусом `.kilo/` — либо привести политику в соответствие с фактом, либо убрать каталог.
