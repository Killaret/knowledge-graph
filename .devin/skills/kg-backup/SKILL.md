# Сохранность данных Personal-стека

Использовать перед любой операцией, способной уничтожить данные, и при разборе отказа «команда заблокирована, нет свежего бэкапа».

Выведено из: `scripts/devops/backup-personal.ps1`, `scripts/devops/guard-personal-data.py`, `.claude/settings.json`, `docs/BACKUP.md`. При их изменении скилл проверить.

## Что защищается

Три именованных тома с живыми данными владельца:

```
pgdata_personal
redisdata_personal
mongodbdata_personal
```

Решение владельца: удалять их **можно**, полного запрета нет. Условие одно — существует свежий непустой бэкап.

## Как сделать бэкап

```powershell
.\scripts\devops\backup-personal.ps1            # режим daily по умолчанию
.\scripts\devops\backup-personal.ps1 -Mode weekly
```

Результат — `backups/backup-personal-<режим>-<метка времени>.sql.gz`. После прогона **убедиться, что файл создан и не пустой**: в каталоге уже лежат нулевые файлы от прошлых неудачных попыток, и они не считаются бэкапом.

Linux и Mac: `scripts/devops/backup-personal.sh`.

## Почему команда может быть заблокирована

У Claude Code стоит хук `PreToolUse`, вызывающий `scripts/devops/guard-personal-data.py`. Он разбирает команду перед выполнением и отказывает, если она способна уничтожить данные Personal-стека, а свежего бэкапа нет.

Что считается деструктивным:

- `docker volume rm`, `docker volume prune`, `docker system prune`;
- `down -v` и `down --volumes` для personal-стека;
- `rm -r` по путям, где встречается `personal`.

Свежесть по умолчанию — **24 часа**, порог меняется переменной `KG_BACKUP_MAX_AGE_HOURS`. Годными считаются файлы по маскам `backup-personal-*` и `personal-volumes-raw-*`, непустые.

Изолированный тест-стек под ограничение не попадает: `docker compose -f docker-compose.test.yml down -v` проходит свободно. Обёртки не спасают — `bash -c "docker volume prune"` разворачивается и проверяется.

## Что делать при отказе

Отказ приходит с текстом, где названы имя последнего бэкапа и его возраст. Порядок:

1. Сделать бэкап и проверить, что файл непустой.
2. Повторить команду.
3. Если бэкап заведомо не нужен — поднять порог переменной окружения на один вызов, но это осознанное решение, а не способ обойти проверку.

Не обходить хук через переименование команды и не отключать его в настройках. Это единственный технический барьер под правилом, всё остальное держится на дисциплине.

## Проверка самого барьера

```powershell
python scripts/devops/test_guard_personal_data.py
```

36 проверок: деструктивные случаи, ложные срабатывания (упоминание команды в тексте коммита), обёртки, и ветки решения по бэкапу — нет, пустой, устаревший, свежий.
