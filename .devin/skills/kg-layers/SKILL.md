# Границы слоёв

Использовать при добавлении импорта, переносе файла между каталогами, создании нового модуля и при ревью чужих изменений в `backend/internal/` или `frontend/src/`.

Выведено из: `.windsurfrules` (раздел Architecture Rules), `frontend/scripts/check-circular.mjs`, `backend/internal/`. Норма — в `.windsurfrules`; здесь процедура проверки.

## Бэкенд: Clean Architecture

Порядок слоёв изнутри наружу:

```
domain/ → application/ → infrastructure/ → interfaces/api/
```

- `domain/` — чистый Go. Ни `*gorm.DB`, ни `gin.Context`, ни Redis, ни любых типов фреймворков.
- `application/` — оркестрация доменных объектов через интерфейсы, объявленные внутри.
- `infrastructure/` — реализации интерфейсов, объявленных внутренними слоями.
- `interfaces/api/` — хендлеры Gin, DTO, middleware.

Запрещено безусловно: глобальные переменные вместо внедрения зависимостей (`var db *gorm.DB`), `panic` в бизнес-логике, обращение хендлера напрямую к клиенту базы вместо порта.

Быстрая проверка чистоты домена:

```bash
grep -rn --include="*.go" -E "gorm|gin\.|go-redis" backend/internal/domain/ | grep -v "_test.go"
```

Ограничение по `*.go` обязательно: без него в выдачу попадает `domain/README.md`, где эти слова упоминаются законно. На момент написания скилла совпадений ноль. Любое новое — нарушение либо осознанное исключение, которое объясняется в ревью.

## Фронтенд: FSD

Кому что можно импортировать:

| Слой | Может импортировать |
|---|---|
| `shared/` | ничего из вышестоящих слоёв |
| `components/atoms/` | только `shared/` |
| `components/molecules/` | `atoms/`, `shared/` |
| `components/organisms/` | `atoms/`, `molecules/`, `shared/` |
| `entities/` | только `shared/` |
| `features/` | `entities/`, `components/`, `shared/` |
| `widgets/` | `entities/`, `features/`, `components/`, `shared/` |
| `routes/` | любой слой |

Псевдонимы: `$shared/*`, `$components/*`, `$features/*`, `$entities/*`, `$widgets/*`. Наследие `$lib` удалено — встретили, значит файл давно не трогали.

Проверка нарушения снизу вверх:

```bash
grep -rnE 'from "\$(entities|features|widgets|components)/' frontend/src/shared/
grep -rnE 'from "\$(features|widgets)/' frontend/src/entities/
```

**Кавычки здесь одинарные, и это не стиль.** В двойных кавычках bash раскроет `$(entities|features|...)` как подстановку команды: grep получит пустой шаблон, напечатает «command not found» в stderr и вернёт ноль совпадений. Проверка будет выглядеть пройденной, ничего не проверив. Ошибка допущена при первом написании этого скилла и поймана прогоном.

Пусто — граница цела. На момент написания обе проверки дают ноль.

## Циклические зависимости

```powershell
cd frontend; npm run check:circular
```

Скрипт `frontend/scripts/check-circular.mjs`. Гоняется в CI как отдельный шаг, поэтому цикл, добавленный локально, всё равно всплывёт — дешевле поймать сразу.

## Типичные способы сломать границу незаметно

- Утащить тип из `features/` в `shared/`, потому что «он общий»: правильный ход — перенести сам тип в `shared/`, а не импортировать наверх.
- Положить в `entities/` компонент, который дёргает виджет.
- Вынести хелпер в `shared/`, оставив в нём импорт стора из `features/`.
- На бэкенде — принять `*gorm.DB` параметром доменного конструктора «временно».

Все четыре проходят компиляцию и ловятся только чтением импортов. При ревью изменений в этих каталогах проверка границ обязательна.
