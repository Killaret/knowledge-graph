# /kg-work — единственная проектная команда

Режим не выбирается человеком. Его определяешь ты по состоянию доски.

## 0. Проверить чистоту дерева

Перед началом сессии рабочее дерево обязано быть чистым. Запустить:

```
node scripts/testing/check-agent-session-tree.mjs .
```

Если вывод не `Working tree is clean; agent session may start.` — сессию не начинать, сказать человеку, чьи незакоммиченные изменения лежат в дереве. Это второй сигнал AUTHOR-1: пока в индексе остаётся чужая работа, `git commit` может захватить её под чужим авторством, и сторож трейлеров её не поймает.

## 1. Прочитать

- `.windsurfrules` — норма.
- `.devin/skills/knowledge-graph/SKILL.md` — базовый workflow.
- `docs/AI_HANDOFF.md` — доска.
- `docs/AI_AGENT_PROTOCOL.md` — порядок работы.
- `git status` и `git log --oneline -5`. Файлы, которые правит Claude Code, не твои.

Обнови свою строку вычитывания в шапке доски: имя, дата, текущий хеш HEAD. Хеш обязателен — он говорит, какое состояние ты видел.

## 2. Выбрать режим

**Есть строки в статусе `на ревью`, автор которых — Claude Code** → режим **ревью**. Только он, свою очередь в этой сессии не берёшь.

**Таких строк нет** → режим **работы**: выполняешь раздел «На Devin» сверху вниз.

Оба режима в одной сессии не совмещаются никогда. Причина в протоколе: «кто пишет — тот не проверяет». Рецензировать чужое, держа в голове план собственной работы, значит рецензировать мягче.

**Свои строки в статусе `на ревью` пропускай.** Самопроверка запрещена, даже когда очередь пуста.

## 3. Режим ревью

- Проверяй исполнением, а не по описанию: прогоняй тесты, поднимай что можно, читай дифф.
- Перед статусом `принято` прогони `scripts/testing/check-all.ps1` (без `-Quick`) локально и приложи сводку к записи на доске или в журнале. Правило владельца: о красном CI узнаём прогоном, а не наблюдением за GitHub.
- Принято → статус `принято`, строка в `docs/AI_LOG.md`.
- Не принято → статус `отклонено`, замечания отдельным файлом `docs/tasks/<id>-review-findings.md` с воспроизведением. Вердикт без доказательства не вердикт.
- Ревью, оставшееся в чате, не считается переданным.

## 4. Режим работы

- Пункты, условие которых не наступило, пропускай, назвав чего ждёшь.
- Постановки лежат в `docs/tasks/`.
- **Критерии приёмки исполнитель не правит.** Если машинная проверка находит постановку, ADR или запись в журнале — это записывается как исключение с пометкой и датой, а не устраняется удалением текста (урок PUB-3: подогнанный критерий проверяет исполнителя его же линейкой, а документ теряет «что именно меняли»).
- Сделанное → статус `на ревью`, строка в журнале.
- Новое для другой стороны → в разделы «На Claude Code» или «На человеке».

## 5. Закрыть сессию

- Перед коммитом прогнать сторож авторства на незапушенном диапазоне: `node scripts/testing/check-commit-authorship.mjs . origin/ai-agents..HEAD`. Признанные нарушения истории перечислены в `scripts/testing/authorship-corrections.txt` — новый хеш добавляется туда только вместе с записью в `AI_LOG.md`. Коммитить только канонической подписью из `docs/AI_AGENT_PROTOCOL.md`.
- Свою работу закоммить под своим авторством. Чужую не трогать. Merge и push — за человеком, если он не попросил иначе.
- Строки на доске не удалять: менять статус и ставить дату. Терминальные строки и реплики в разделе «Обмен репликами» старше трёх дней удалить — след остаётся в журнале и в истории git.
- Реплика — указатель, не пересказ: 3–4 предложения (вердикт, одно, что другой стороне надо знать, ссылка на `docs/tasks/<id>-review-findings.md`). **Статус строки доски — тоже указатель, не пересказ:** вердикт, одно, что другой стороне надо знать, ссылка на `docs/tasks/<id>-review-findings.md`. Разбор и мутации — в review-findings.
- Дописать реплику, если есть что сказать другому агенту.
- Если делать нечего — сказать это и перечислить, чего ждём и от кого.

## Чего не делать

- Не поднимать Personal-стек без явной просьбы.
- Не удалять данные Personal-стека без свежего бэкапа.
- Не брать задачи из разделов «На Claude Code» и «На человеке».
- Не менять ограничения Claude Code без поручения человека.
